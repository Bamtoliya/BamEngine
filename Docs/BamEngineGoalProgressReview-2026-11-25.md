## 1. 평가 목적 및 범위

BamEngine을 단순한 게임 엔진이 아니라 기존 개발 계획에 명시된 종합 제작·실행 플랫폼으로 평가한다. 기능 수나 소스 규모만으로 완료를 판정하지 않고, 기능의 구현 범위, 공통 기반과의 통합, 실행 검증 및 최종 결과물의 완성 여부를 구분한다.

기준 문서는 2026-10-24 작성 후 갱신된 `EngineDevelopmentPlan.md`이다. 최초 작성본의 Git 이력 자체를 복원한 것은 아니므로, 이 문서에서 말하는 원래 목표는 **현재 저장소에 유지된 원래 목표의 범위**를 뜻한다.

### 1.1 최종 목표

1. 2D·3D 게임 제작 및 실행 엔진
2. AI 강화학습 시뮬레이터
3. 2D·3D VTuber 실행·추적·방송
4. 3D 모델링·리깅 및 2D 아바타 제작 도구

리플렉션, 직렬화, ECS, 렌더링, 리소스 관리, 에디터 및 배포는 여러 결과물이 공유하는 기반으로 평가한다. 조건부 장기 렌더링 연구 목표는 실용 게임 엔진의 필수 완료 조건으로 간주하지 않는다.

### 1.2 평가 방법

- 코드 존재와 실제 동작을 구분한다. 코드 또는 호출 경로만 확인한 항목은 구현 근거로 사용하되, 실행 성공이나 성능 검증을 단정하지 않는다.
- 기존 개발 문서의 날짜가 명시된 검증 결과는 해당 시점의 기록으로만 취급한다.
- 명시적인 미구현 경로, 후속 과제 및 실패·검증 대기 기록을 반영한다.
- 점수는 정성적 추정값이다. 전체 요구사항을 원자 단위로 분해해 전수 검증한 공식 체크리스트 달성률이 아니다.
- 0%는 전용 구현이 확인되지 않았다는 의미이며, 전체 코드베이스에서 기능 부재가 증명되었다는 뜻은 아니다.

참고 척도: 0%는 전용 구현 미확인, 25% 전후는 기반 또는 초기 구현, 50% 전후는 핵심 경로의 부분 구현, 75% 전후는 주요 경로 구현 및 일부 검증, 90% 이상은 핵심 요구가 상당 부분 충족된 상태로 본다. 100%는 해당 평가 범위의 완료 기준 충족 및 검증이 필요하다. 이 척도는 점수를 해석하기 위한 지침이지 기계적 채점표가 아니다.

## 2. 종합 달성률

**종합 추정 달성률: 59.25% (약 59%)**

| 평가 영역 | 추정 달성률 | 기본 가중치 | 전체 기여도 |
|---|---:|---:|---:|
| 공통 엔진 기반 | 85% | 30% | 25.50%p |
| 2D·3D 게임 제작 | 80% | 30% | 24.00%p |
| 강화학습 | 45% | 15% | 6.75%p |
| VTuber 실행·방송 | 10% | 15% | 1.50%p |
| 모델링·리깅 제작 도구 | 15% | 10% | 1.50%p |
| **합계** | | **100%** | **59.25%p** |

계산식: `전체 달성률 = Σ(영역별 달성률 × 가중치) / Σ(가중치)`

계획 문서에는 목표별 가중치가 명시되어 있지 않다. 위 기본값은 공통 기반 및 게임 제작을 60%, 나머지 확장 목표를 40%로 설정한 평가자의 가정이다. 공통 기반과 제품별 기능은 중복 산입하지 않는 방향으로 분류했으나, 세부 점수 간 완전한 독립성은 검증하지 않았다.

| 평가 범위 | 달성률 또는 추정치 | 해석 |
|---|---:|---|
| 공통 기반과 게임 제작만 동일 비중 | 82.5% | 약 83% |
| 기본 가중치 적용 | 59.25% | 종합 플랫폼 전체 |
| 다섯 영역 동일 비중 | 47.0% | 영역별 중요도가 동일할 때 |
| 최소 기능 게임 엔진 | 약 95% | 별도의 정성적 범위 평가 |
| 고급 그래픽스 및 제작 엔진 | 약 75~80% | 별도의 정성적 범위 평가 |
| 장기 연구 목표까지 포함 | 약 45~50% | 가중치 미확정 참고 추정치 |

게임 엔진 자체의 구현 수준은 높지만, 강화학습의 실제 학습·추론 경로와 아바타 제작·방송 제품이 아직 완성되지 않았으므로 종합 목표 달성률은 상대적으로 낮다.

### 4.4 기존 검증 기록과 정정 사항

- 렌더링 계획 문서에는 과거 GPU Timestamp 계측, VRAM 및 Descriptor 통계, 실시간 MetricsPanel 동작 검증 기록이 있다. GPU Profiler는 미구현 신규 기능으로 분류하지 않는다.
- 문서에 기록된 인스턴싱 배칭 비교(드로우콜 56→57회), Tiled Lighting 비용 비교(1.10ms→0.25ms)는 당시의 측정 사례이며 현재 커밋의 독립 재측정 결과가 아니다.
- `DevelopmentPriorities.md`에는 Probe GI 빛샘, 얇은 벽 가시성 및 일부 렌더링 수동 검증이 후속 과제로 기록되어 있다.

## 5. AI 강화학습 시뮬레이터

종합 추정 달성률: **45%**.

| 세부 영역 | 추정 달성률 | 근거 또는 보완 |
|---|---:|---|
| 환경 API 및 과제 정의 | 90% | `IRLEnvironment`, 관측·행동·보상 계약 |
| Headless 실행 및 Reset/Step | 85% | CartPole, 독립 RL 서버 및 시간 제어 기반 |
| Python/Gymnasium 연동 | 75% | Python 어댑터와 과거 실행 기록 |
| 병렬·벡터화 환경 | 65% | VectorizedRLEnvironment, VEC 프로토콜 |
| 센서 및 관측 확장 | 30% | 영상 센서·다중 에이전트 확장 검증 필요 |
| 실험 및 평가 | 30% | Curriculum·SaveGame 등 일부 구현; 실험 재현성 보완 |
| 정책 추론 모듈 | 15% | Client 추론·정책 재생 통합 검증 필요 |
| 모션·리깅 최적화 | 0% | 전용 구현 미확인 |

위 세부 점수의 단순 평균은 48.75%이지만, 학습부터 배포·추론까지의 종단 간 검증 부족과 `RLSimulationCheck` 실패 기록을 고려하여 영역 전체를 45%로 보수적으로 평가했다. 실패 원인은 이번 검토에서 확인하지 않았다.

첫 완료 예제는 벡터 관측 환경 → Gymnasium 외부 학습 → 헤드리스 실행 → 독립/벡터 환경 격리 검증 → 학습된 정책의 Client 재생이다. 이후 실제 필요에 따라 영상 센서, 다중 에이전트, 도메인 랜덤화 및 모션·리깅 최적화로 확장한다.

공통 기반을 재사용할 수 있다는 점과 아바타 전용 기능의 실제 구현을 구분한다. VTuber 실행·방송의 영역 점수는 10%, 모델링·리깅 제작 도구는 15%로 추정한다. 하위 항목의 단순 평균이 아니다.

첫 완료 예제는 다음과 같다.

- 3D: 단순 리그·표정 → VRM 지원 범위 검증 → 외부 추적 → 눈·얼굴·립싱크 → OBS 캡처.
- 2D: 자체 파츠·변형 메시·파라미터 모델 → 추적 매핑 → Client 재생·방송 캡처. Cubism 호환은 별도 경로로 검증한다.
- 제작 도구: 간단한 메시·뼈·웨이트·모프 또는 2D 파츠·디포머 편집 → 저장 → 실행용 변환 → Client 재생. 외부 DCC와의 입출력을 유지한다.

|---|---:|---|
| 게임 엔진 기초 구축 | 100% | 기초 기능 존재 범위의 추정이며 무결점 의미 아님 |
| 게임 엔진 기능 확장 | 90% | 주요 기반 다수 구현 |
| 에디터 및 제작 환경 구축 | 85% | 데이터 보호 및 UX 검증 잔여 |
| 실제 게임 제작 및 배포 | 75% | 배포 경로 확보, 완성 게임 검증 잔여 |
| 강화학습 플랫폼 확장 | 45% | 학습·추론 종단 간 검증 잔여 |
| VTuber 플랫폼 확장 | 10% | 전용 기능의 첫 결과물 필요 |
| 모델링·리깅 도구 확장 | 15% | 전용 저작 경로의 첫 결과물 필요 |

2026-11-25 `DevelopmentPriorities.md`의 검증 기록에는 독립 Shipping Client 빌드·구동, 원본 Assets 없이 `.bampak` 로드, HDR 환경맵 캡처 성공이 명시되어 있다. 이는 기존 평가의 배포 및 IBL 상태를 업데이트하는 근거이다. 현재 커밋에서 직접 재현한 결과는 아니다.

앞으로의 달성률 갱신 시 다음의 제품별 증거를 우선 반영한다.

| 결과물 | 최소 검증 기준 |
|---|---|
| 2D 게임 | 입력, 타일맵/충돌, UI, 저장, 독립 Client 배포 및 플레이 |
| 3D 게임 | 캐릭터·카메라·충돌, 애니메이션, 씬 전환, UI, 저장, 독립 Client 배포 및 플레이 |
| 강화학습 | Reset/Step 및 seed, 병렬 환경 격리, 외부 학습·고정 평가, 정책 Client 재생, steps/s |
| 3D VTuber | 표정 및 리그, 추적 재연결, 립싱크, 방송 캡처 및 지연 측정 |
| 2D VTuber | 변형·파라미터·마스크, 추적 매핑, Client 재생 및 방송 캡처 |
| 제작 도구 | 편집→저장→변환→재생에서 데이터 보존 및 Undo/Redo 검증 |

## 8. 결론

BamEngine은 실용적인 개인 게임 엔진을 구축하는 목표에 대해서는 약 83%, 원래 계획의 종합 제작 플랫폼 전체에 대해서는 기본 가중치 기준 약 59%에 도달한 것으로 평가한다.

공통 엔진 기반을 구축하는 단계의 막바지에 있으며, 이를 실제 게임·학습 환경·아바타 제품으로 전환하는 단계에 진입했다. 이후에는 각 결과물의 최소 종단 간 경로를 독립적으로 완성하고, 구현 여부와 실행·성능·배포 검증을 분리하여 평가를 갱신하는 것이 적절하다.
