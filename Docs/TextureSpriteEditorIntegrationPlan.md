- 범위: 텍스처 정보·변환과 스프라이트 저작의 에디터 작업 흐름. 씬 엔티티용 `InspectorPanel`은 제외한다.

## 현재 방향 변경 및 진행 상태

- 이미지 원본 더블클릭으로 별도 텍스처 편집기를 열고, 그 창의 버튼에서 현재 텍스처를 스프라이트 편집기로 연다. `.bamsprite`는 스프라이트 편집기로 직접 연다. 버튼 자체는 자동 변환이나 저장을 수행하지 않는다.
- 텍스처 편집기에 변환 상태·미리보기를 옮기고, 스프라이트 편집기는 이력과 미저장 교체 보호를 유지한다. 진행 중 변환 출력의 열기·저장·경로 이동과 스프라이트 편집 중인 출력의 변환을 제한한다.
- 텍스처 화면은 실제 텍스처 우선의 크기 조절 미리보기와 잘린 경로 툴팁을 제공한다. 실제 텍스처를 표시할 수 없으면 썸네일을 사용한다. 슬라이스 수의 로캘 서식도 수정했다. 전체 UI와 로캘의 회귀 검증은 남았다.
- 스프라이트 오른쪽 패널의 속성과 목록은 공통 `EditorUI` 테이블을 사용한다. 피벗 프리셋은 좁은 폭에서 줄바꿈되는 아이콘 버튼이며, 9-Slice 보더는 좌·우와 상·하 행으로 분리한다. 기존 편집 이력과 목록 검색·선택을 유지하고 잘린 이름의 툴팁과 검색 결과 없음 안내를 제공한다. 변경 후 전체 UI 회귀 검증은 남았다.
- 스프라이트 편집기의 캔버스·스플리터·사이드바 폭 계산에 두 간격을 모두 반영하고 좁은 창에서 표시 폭을 제한한다. 실제 가로 밀림의 원인과 수정 효과는 실환경 검증 전이다.
- 변환 후 재로드 중단 시 사용자가 `Texture.AlreadyUploaded`를 확인했다. 기존 GPU 텍스처에 다른 참조가 있으면 `Safe_Release`가 포인터를 비우지 않아 같은 객체의 `ReadArchive`가 실패한다. 현재 코드는 별도 `Texture`에 읽고 성공 시 자원을 교체한다.
- 21:45 로그에서 실제 GPU BC7 압축과 워커 완료가 기록됐지만 재로드가 실패했다. 수정 후 22:21 재시도는 `cached GPU BC7`이며 `.bamtex` 재로드 성공이 두 번 기록됐다. 사용자는 실패 브레이크가 더 이상 발생하지 않는다고 보고했다. 이 재시도는 수정 후 실제 GPU 압축 실행을 입증하지 않는다.
- `Texture::Reload()`의 마지막 `IsFailure(result)`는 여전히 Debug 실패 경로에서 브레이크를 유발할 수 있다. GPU 업로드 내부 실패 경로도 확인해야 한다. 두 번의 재로드는 변환 완료 갱신과 핫리로드에 해당하며 비용과 중복 제거의 안전성은 미측정이다.
- 기준 커밋의 `ContentBrowserPanel.cpp`에는 별도 작업에서 수정 중인 문법 오류가 있다. 해당 수정은 이 작업 범위에 포함하지 않았으므로 이 변경만으로 독립 빌드 가능하다고 판단하지 않는다.

## 1. 목적과 통합 전 상태

같은 이미지를 확인하고 변환한 뒤 스프라이트로 편집하는 진입 흐름을 연결한다. 텍스처 변환과 스프라이트 저작은 별도 패널과 저장 문서로 유지한다.

| 구성 | 현재 확인한 역할 |
|---|---|
| `TextureEditor` | 이미지 및 `.bamtex` 등의 미리보기·정보·변환을 제공하고 스프라이트 편집기를 연다. |
| `SpriteEditor` | 텍스처 또는 스프라이트를 열어 슬라이스·피벗·보더를 편집하고 별도 스프라이트 파일을 저장한다. 문서 이력과 애니메이션 생성 기능이 있다. |
| `TextureInspector` | 텍스처 변환 설정과 자동 스프라이트 생성 UI가 있으나 생성·등록·호출 경로가 확인되지 않았다. 현재 접근 가능한 UI라고 가정하지 않는다. |

통합 전 `ImGuiManager::FindResourceEditor()`는 처음 지원하는 편집기를 선택했고, 확장자가 겹치는 일반 열기는 텍스처 편집기를 선택했다. 콘텐츠 브라우저의 우클릭 메뉴에는 스프라이트 편집기를 직접 여는 별도 경로가 있었다.

`TextureEditor`는 로드된 텍스처를 우선 표시하고 표시할 수 없으면 `AssetCache` 썸네일을 사용한다. 썸네일을 원본과 같은 해상도로 가정하지 않는다.

## 2. 제안하는 구조

정보·변환과 스프라이트 편집을 각각의 리소스 편집 창에 제공한다. 텍스처 편집기의 버튼은 현재 표시 중인 텍스처를 스프라이트 편집기로 전달한다.

- 이미지 또는 `.bamtex`를 일반적으로 열면 텍스처 편집기를 표시하고, `.bamsprite`를 열면 스프라이트 편집기로 진입한다. 기존 스프라이트 우클릭 메뉴도 유지한다.
- 정보·변환은 대상 텍스처의 경로와 미리보기를 표시하고, **지원하는 원본**에서 출력 형식과 압축 방식을 선택해 변환한다. 변환 가능한 입력은 실제 변환기의 지원 범위를 기준으로 표시한다.
- 스프라이트 화면은 기존 캔버스, 슬라이싱, 속성, 저장, 이력 및 애니메이션 생성 기능을 유지한다. 스프라이트를 열었을 때 참조 텍스처를 확인할 수 없는 경우에는 오류를 알리고 없는 원본 경로를 추정하지 않는다.
- `TextureInspector`의 유용한 변환 기능은 지원 여부와 수명·오류 처리를 확인해 이관한다. 기존 코드를 그대로 호출하지 않으며, 이관과 참조 확인이 끝나기 전에는 클래스를 삭제하지 않는다.

이전 단일 창 방식과 달리 두 창을 동시에 볼 수 있다. 패널별 문서 수명과 변환 중 충돌을 별도로 보호해야 한다.

## 3. 상태·저장 및 변환 안전성

- 텍스처 변환은 산출물 생성 작업이고, 슬라이스 저장은 텍스처를 참조하는 별도 스프라이트 문서를 저장하는 작업이다. 저장·변환 버튼과 결과의 대상을 명확히 표시한다. 스프라이트 Undo/Redo와 미저장 상태를 변환 설정 변경과 혼동하지 않는다.
- 같은 텍스처를 다시 열면 미저장 슬라이스와 이력을 유지한다. 다른 대상 열기·드롭·닫기·종료는 기존 `ResourceEditorInterface`의 문서 교체·닫기 보호를 따르며, 저장 실패나 취소 시 편집 상태를 유지한다.
- 변환 중에는 중복 요청을 막고, 대상 전환이나 창 닫기 후 완료된 작업이 다른 대상에 결과를 적용하지 않도록 요청 대상과 수명을 관리한다. 변환 산출물과 열린 스프라이트가 충돌하거나 갱신이 필요한 경우를 확인하고, 미저장 편집을 조용히 덮어쓰지 않는다.
- 기존 출력 덮어쓰기 확인, 실패 시 기존 파일 보존, 취소 및 오류 알림을 처리한다. `Engine://` 읽기 전용 정책을 준수하며 쓰기 가능 여부를 대상과 출력 경로 모두에서 확인한다.
- 변환 결과가 표시·사용되는 경로에서 썸네일 및 리소스 캐시의 갱신 필요성을 확인한다. 갱신이나 핸들 교체가 진행 중 편집에 미치는 영향을 함께 검증한다.
- 기존 CPU 표준·CPU 빠른 BC7·GPU BC7 선택을 연결한다. GPU 경로와 지원 형식의 실제 제한 및 CPU 폴백을 표시 또는 로그로 구분한다. 미지원 플래그를 동작하는 옵션처럼 노출하지 않는다.
- 원본 파일과 생성된 `.bamtex`의 역방향 연결이나 저장된 임포트 옵션 복원은 현재 보장되지 않는다. 새 원본 추적·설정 영속화는 [에셋 임포트 설정 계획](ImGuiDevelopmentPlan.md)에서 별도 범위로 다룬다.

## 4. 진행 순서

1. **진입점과 문서 경계**: 이미지·`.bamtex`와 `.bamsprite`를 각각의 편집기에 연결하고 스프라이트 우클릭 진입을 유지한다.
2. **패널과 변환 분리**: 텍스처 정보·변환과 작업 상태를 텍스처 창으로 옮기고 버튼에서 스프라이트 창을 연다.
3. **검증**: 출력 충돌·비동기 수명·작업공간 복원·미저장 문서 보호 및 실제 UI를 사용자가 검증한다.

표시 문구는 기존 키를 우선 사용하고 필요한 변경은 에디터 로캘 CSV 원본에 반영한다. 단축키는 `EditorActionRegistry`/`ShortcutManager`, 속성 행과 모달은 공통 UI 지침을 따른다.

### 4.1 이전 단일 창 구현 기록

- 기존 `SpriteEditor` 창을 통합 창으로 사용하고, 별도 `TextureEditor` 등록은 중단했다. 이미지·텍스처는 정보 모드, 스프라이트는 편집 모드로 연다. 기존 우클릭은 편집 모드로 전환한다. 기존 스프라이트 패널의 내부 ID와 단축키 문맥은 유지한다.
- 모드 전환에서는 슬라이스와 이력을 보존한다. 스프라이트 파일의 텍스처 참조가 없으면 동명 파일을 추정하지 않고 로드 실패를 알린다. 이미지에서 기존 슬라이스를 찾을 때는 텍스처 참조가 같은 파일인지 확인한다.
- 기존 스프라이트의 PPU와 직접 연 파일의 저장 형식을 유지한다. 자동 슬라이싱은 참조 텍스처의 이미지 디코딩을 사용하며, `.bamtex` 등 디코딩할 수 없는 경우나 영역이 없으면 기존 슬라이스를 유지하고 알린다. 격자 슬라이싱의 결과가 비어 있어도 기존 슬라이스를 유지한다.
- 스프라이트 저장은 기존 Archive의 파일별 임시 파일·교체 경로를 사용한다. 다수 슬라이스 저장 전체가 하나의 트랜잭션은 아니므로 중간 실패 시 이미 저장된 앞쪽 파일은 유지되며 미저장 편집 이력은 유지된다.
- 정보의 해상도는 리소스의 실제 RHI 텍스처에서만 표시한다. 이전 구현은 썸네일만 사용했으며 현재 미리보기 변경은 위 진행 상태를 따른다. 읽기 전용 대상의 슬라이스 저장·편집은 제한한다.
- 기존 인스펙터를 직접 호출하지 않고 지원하는 포맷·압축 방식과 밉맵·병렬·sRGB 설정을 정보 화면에 연결했다. PNG·JPEG·BMP·TGA를 대상으로 하며 TGA는 WIC 코덱에 의존한다. 변환 전 두 출력 경로의 덮어쓰기를 확인하고 비동기 완료 시 썸네일 무효화와 로드된 텍스처 갱신을 시도한다.
- 자동 스프라이트 생성은 선택 사항이며, 같은 이름의 `.bamsprite`가 있으면 변환을 시작하지 않는다. 변환 후 새 파일은 staging을 거쳐 기존 파일을 덮어쓰지 않고 생성한다. 텍스처 변환 후 스프라이트 생성이 실패할 수 있으며, 이 경우 텍스처 출력은 유지하고 실패를 알린다.
- 변환 중 중복 요청과 해당 출력의 편집기 열기·경로 이동을 제한한다. 완료 콜백은 편집기 객체를 캡처하지 않는다. 기존 `Texture Editor`와 `Sprite Editor`의 열림 상태는 통합 창에 반영하고 작업공간 저장 시 기존 텍스처 창의 상태 키를 제거한다. 기존 텍스처 창의 도킹 위치는 자동 이관하지 않는다.
- 위 항목은 이전 단일 창 구현 기록이다. 현재 패널 분리의 검증 상태는 문서 상단을 따른다. 다른 임포트 경로 또는 외부 프로그램의 동시 출력 변경은 편집기 요청 보호 범위 밖이다.

## 5. 완료 및 검증 기준

- 이미지, `.bamtex`, `.bamsprite`와 기존 우클릭·드롭 진입이 의도한 화면을 연다. 기존 파일 열기·스프라이트 슬라이싱·저장·애니메이션 생성이 유지된다.
- 슬라이스 편집 후 같은 텍스처 재열기와 다른 파일 열기·닫기·종료의 저장/버리기/취소, 저장 실패와 Undo/Redo를 확인한다. 텍스처 변환이 슬라이스의 미저장 상태를 해제하지 않는다.
- CPU 표준·빠른 BC7·GPU BC7에서 실제 사용 backend와 GPU 실패 시 CPU 폴백을 구분한다. 캐시 적중과 최초 압축은 별도로 측정한다. 변환 중 전환·닫기, 출력 충돌, 실패·취소, 캐시 갱신과 `Engine://` 보호를 확인한다.
- 공유 참조가 유지되는 `.bamtex` 재로드와 손상된 아카이브·업로드 실패 시 기존 리소스 보존을 검증한다. 원본 이미지·DDS 경로와 변환 완료 및 파일 감시의 중복 재로드도 확인한다.
- [에디터 UX 검증 기준](EditorUXTestGuidelines.md)에 따라 정적·헤드리스 자동 검사와 실제 에디터 검증을 구분한다. 한·영 전환, 좁은 도킹 폭, UI 배율 및 단축키 문맥도 확인한다.
- 기존 워커·스프라이트·로캘 관련 검사와 변경 범위에 맞는 회귀 검사를 사용자가 실행한다. 기존 워커 테스트 통과만으로 통합 UI, 실제 GPU 사용 또는 속도·화질이 검증됐다고 판단하지 않는다.
