# 리소스 편집기 비동기 열기 계획

- 작성일 2026-11-19
- 상태 · 설계 초안. 현재 호출 경로를 정적으로 확인했다. 구현과 성능 측정은 이후 단계에서 진행한다.
- 2026-11-20: 공용 진입점의 `SetTargetResource()` 호출 시간과 모델 편집기의 리소스 로드·프리뷰 생성·전체 시간을 로그로 추가했다. 공용 로그는 성공 여부를 뜻하지 않으며 패널 내부의 직접 열기는 측정하지 않는다. 모델 로그에는 실패한 열기가 포함되지 않고, 로드 시간에는 의존 에셋과 GPU 작업이 함께 포함된다. 이는 기준 측정의 일부일 뿐이며 창 우선 표시, 비동기 로딩과 진행 UI는 아직 구현하지 않았다. 실제 측정은 사용자 실행이 필요하다.

## 1. 목표와 적용 범위

콘텐츠 브라우저나 리소스 피커에서 에셋을 열면 기존 도킹 위치에 편집기 창을 먼저 표시한다. 준비가 길어지면 모델 임포트 프리뷰처럼 창 본문에 로딩 상태를 표시한다. 그동안 메인 에디터는 입력과 화면 갱신을 계속 처리한다. 여러 편집기를 열어도 파일 읽기, 준비 결과의 메모리 점유, GPU 업로드와 프리뷰 생성 비용이 한꺼번에 몰리지 않도록 제한한다.

첫 적용 대상은 이미 임포트한 `.bammodel`과 `.bammodel.json`의 모델 편집기 열기다. 모델로 공통 흐름을 검증한 뒤 Texture·Sprite·Material 등은 실제 열기 비용을 측정해 적용 순서를 정한다. 원본 모델 임포트는 기존 임포트 경로를 사용한다. 독립 Prefab Editor와 콘텐츠 브라우저의 Prefab Mode는 진입점과 씬 수명이 다르므로 별도 흐름으로 검증한다. 런타임 비동기 로딩은 [엔진 개발 계획 G절](EngineDevelopmentPlan.md#g-런타임-비동기-로딩에셋-식별)의 범위다.

## 2. 현재 경로와 재사용할 부분

- `ImGuiManager::RequestOpenResourceEditor()`는 경로를 예약한다. `Draw()` 후반의 `OpenPendingResourceEditor()`가 예약을 꺼내고 `SetTargetResource()`를 동기로 호출한다. 예약을 위한 단일 경로 슬롯은 프레임 안에서 여러 요청을 수집하면 앞선 요청을 덮어쓸 수 있다. 같은 문서나 이미 보유한 탭을 포커스하는 경로와 미저장 확인은 기존 구현을 활용한다. [ImGuiManager.cpp](../Editor/Source/ImGui/Private/ImGuiManager.cpp)
- 모델 편집기의 `SetTargetResource()`는 `ResourceManager::LoadFile()` 후 `SetupPreviewModel()`에서 프리뷰 씬에 모델을 배치한다. 모델 파일을 읽는 동안 리소스 핸들 역직렬화가 의존 에셋의 `LoadFile()`까지 호출할 수 있고, 메시 로드는 RHI 버퍼 생성에 이른다. `LoadFile()`이나 `SetTargetResource()` 전체를 작업 스레드에 넘기려면 이 호출들과 수명을 함께 다뤄야 한다. [ModelEditor.cpp](../Editor/Source/ImGui/ResourceEditor/Private/ModelEditor.cpp) · [ResourceHandleArchiveAdapter.h](../Engine/Source/Resource/Public/ResourceHandleArchiveAdapter.h) · [Mesh.cpp](../Engine/Source/Render/Mesh/Private/Mesh.cpp)
- 모델 임포트 프리뷰에서 백그라운드 준비, 완료 확인, 메시·머티리얼 단위의 메인 스레드 작업, 로딩바 배치를 참고한다. `AssetManager`는 준비가 완료된 작업만 수거하고, `AssetCache`는 썸네일 업로드 수를 프레임당 제한한다. `BamAssetWorker`의 모델 변환은 원본 임포트용이다. 패널 열기는 저장된 에셋의 디코딩 비용과 격리 필요성을 측정한 뒤 워커 프로세스 재사용 여부를 판단한다. 단, 임포트 모달은 준비 스레드를 `detach`하고 취소 표시로 결과만 버리므로 진행 중인 파싱을 중단하거나 종료 전에 회수하지 못한다. 이 수명 방식은 따르지 않고 4절의 서비스 소유·종료 순서 규칙을 적용한다. ## 3. 창 표시와 문서 전환

1. **요청 수락.** 공용 열기 경로에서 대상 편집기를 찾고 창을 열어 포커스를 요청한다. 현재 문서나 보유 탭이 대상이면 포커스만 이동한다. 다른 문서에 미저장 변경이 있으면 기존 `RunWithDiscardConfirmation()`의 저장·버리기·취소를 먼저 처리한다. 저장 실패나 취소 시 새 작업을 등록하지 않는다. 경로 확인에 이미 해석한 경로나 에셋 목록을 재사용할 수 있는지 측정하고, 느린 파일 존재 확인이 창 표시를 막으면 로딩 단계로 옮긴다.
2. **준비 중.** 제목과 `###` 도킹 ID는 기존 창에서 유지하고 본문에 대상 파일명과 진행 상태를 표시한다. 처음 열 때는 가벼운 로딩 본문을 그리고, 교체 중에는 기존 문서와 이력을 보유한 채 문서 편집 액션을 잠근다. 다른 패널과 씬 뷰는 계속 조작할 수 있다. 짧은 캐시 적중에는 로딩바가 깜빡이지 않도록 표시 유예를 두되, 로드나 완료 처리를 지연시키지 않는다.
3. **도중 상태.** 전체 작업량을 계산할 수 없는 파일 준비나 의존성 탐색은 퍼센트 없이 표시한다. 생성해야 할 작업 수가 확정된 단계에서는 단계명과 실제 완료량을 표시할 수 있다. 문서가 준비되면 편집 기능을 열고, 프리뷰에만 남은 작업은 프리뷰 영역에서 표시한다. 접히거나 가려진 패널의 프리뷰 준비·제출은 뒤로 미룬다.
4. **완료와 실패.** 현재 요청의 유효성을 확인한 뒤 성공한 문서의 경로·핸들·이력을 함께 교체한다. 로드 실패 시 기존 문서로 돌아가고 원인을 표시한다. 최초 열기 실패라면 열린 창에 실패 상태와 다시 시도할 방법을 제공한다. 문서는 열렸지만 프리뷰만 실패했다면 문서 편집은 가능해야 한다.

상태 UI는 `ResourceEditorInterface`와 기존 `EditorUI` 스타일을 사용한다. `불러오는 중`, `프리뷰 준비 중`, 실패 안내에 해당하는 한·영 키를 `Editor.ResourceEditor.csv`에서 관리한다. 편집기별 문구도 도킹 ID에 영향을 주지 않아야 한다. 저장·Undo·Redo의 실행 가능 여부는 메뉴와 `ShortcutManager`에서 동일하게 평가한다. 닫기와 취소는 기존 입력·액션 경로에 연결한다. ## 4. 처리 경계와 프레임 예산

### 백그라운드 준비

- 제한된 작업 큐에서 파일 읽기, 형식 디코딩, 의존 경로 수집과 CPU 데이터 준비를 처리한다. 독립적으로 준비할 수 있는 데이터만 옮기고, 작업은 경로·옵션과 자신이 소유한 결과를 다룬다. 패널 포인터와 ImGui·Scene·RHI 객체는 작업에 넘기지 않는다. 기존 Archive의 파일 형식과 필드 호환 정책을 재사용한다. 리소스 핸들의 즉시 로드가 섞인 경로는 의존 키를 먼저 수집하고 핸들을 연결하는 단계로 나눌 수 있는지 모델 경로에서 검증한다. [Reflection·Archive 지침](ReflectionArchiveGuidelines.md)
- 작업자 수와 대기 중인 준비 데이터의 바이트를 제한한다. 결과를 소비하지 못하면 신규 준비 작업 등록을 늦춘다. 단일 대형 리소스가 한도를 넘기면 가능한 범위에서 스트리밍·분할하고, 지원할 수 없는 크기라면 한도 오류를 전달한다. 초기 한도는 대표 에셋의 크기와 임포트·썸네일이 함께 도는 상황의 메모리 사용량을 측정해 정한다.
- `ResourceManager`의 기존 캐시·핸들 조회를 우선한다. 같은 프로젝트 안에서 같은 파일과 동일한 옵션·유효 버전으로 들어온 요청만 준비 작업을 공유한다. 패널의 편집 상태와 프리뷰는 패널별로 유지한다. 첫 구현의 준비 데이터 재사용 범위는 진행 중인 요청으로 잡고, 추가 캐시는 재열기 비용과 무효화 방식이 확인된 경우에 검토한다.

### 메인 스레드 반영

- 프레임마다 결과가 준비됐는지 즉시 확인하고 반환한다. 진행 중인 작업의 `get()`·`join()`이나 동기 GPU 완료 대기로 프레임을 막지 않는다. `std::async`를 사용할 경우 마지막 future의 소멸이 프레임 경로에서 대기를 유발하는지도 확인한다. `Draw()`는 상태를 읽어 표시하고, 결과 소비·등록은 `Update()` 또는 기존 렌더 제출 단계의 적절한 지점에서 수행한다.
- 기존 리소스 등록·핸들 정책을 사용해 의존성 연결, GPU 업로드, 프리뷰 씬 구성을 반영한다. 등록 직전에 다른 요청이 같은 파일을 이미 로드했는지 재확인해 살아 있는 핸들을 재사용한다. 모델 씬 배치가 큰 작업으로 측정되면 노드·메시 단위로 나눌 수 있는지 검토한다. 중간 결과를 문서나 렌더러에 노출하기 전에 준비 완료와 요청 유효성을 확인한다. 취소된 임시 GPU 자원은 기존 RHI 수명 규칙에 따라 안전한 시점에 회수한다. [소스 조직 지침](SourceOrganizationGuidelines.md) · [SceneModel.cpp](../Engine/Source/World/Scene/Private/SceneModel.cpp)
- **패널 전체가 하나의 프레임 예산을 공유한다.** 첫 측정에서 패널 로드 작업의 메인 스레드 합산 예산 `2ms/프레임`을 시작값으로 사용한다. 먼저 입력·렌더링 여유를 확보하고, 여유가 적은 프레임에는 프리뷰 작업량을 줄인다. 최근에 요청된 가시 패널의 문서 열기를 우선하되, 동일 우선순위 작업을 번갈아 진행하고 기다린 가시 요청이 계속 밀리지 않게 한다. 썸네일 업로드·임포트 반영과 동시에 병목이 재현되면 함께 계측하고 해당 예산을 조정한다.
- 시간 제한은 다음 작업을 시작할지 결정하는 기준이다. 이미 시작한 버퍼 생성이나 씬 배치를 중단할 수 없으므로, 단계별 최장 호출 시간과 업로드 바이트도 기록한다. 한 단계가 예산을 반복해서 넘기면 가장 긴 작업부터 더 작게 나눈다. GPU 복사·완료 확인을 분리해야 한다면 해당 RHI에서 가능한 경로를 확인하고 별도 변경으로 검증한다. 기존 임포트 프리뷰의 `4ms`는 참고값이며 여러 패널에 그대로 적용할 예산으로 간주하지 않는다.

### 요청과 자원의 수명

- 패널마다 현재 요청을 식별한다. 같은 패널의 A 다음에 B를 열면 B를 현재 요청으로 바꾸고, 다른 패널의 요청은 큐에 유지한다. 준비 작업을 공유하더라도 참조하는 요청이 모두 사라졌을 때만 취소한다. 완료 순서와 무관하게 현재 요청만 문서를 바꿀 수 있다.
- 닫기, 파일 수정·재임포트·이동·삭제, 프로젝트 전환과 종료에서 요청을 무효화하는 규칙을 정한다. 기존 에셋 이동·이름 변경 검사에 진행 중인 대상과 필요한 의존 경로를 포함하거나, 변경을 감지해 결과를 폐기한다. 적용 직전에 프로젝트와 요청 세대·파일 변경 여부를 확인한다. 검증에 필요한 파일 접근 비용도 측정한다.
- 취소한 요청은 UI에서 즉시 해제하고, 중단할 수 없는 작업의 결과는 도착 시 폐기한다. 프로젝트나 에디터 종료 시 서비스가 작업 수명을 관리하고 `ResourceManager`와 RHI보다 먼저 정리한다. 플러그인 편집기는 DLL 재로드와 결과 소유권을 검증한 뒤 편입한다. [에디터 플러그인 수명과 교체](EditorPluginArchitecturePlan.md#5-수명과-교체)

## 5. 구현 순서와 단계별 완료 기준

1. **기준 측정.** `RequestOpenResourceEditor()`의 경로 해석·검사부터 파일/Archive 처리, 의존 로드, GPU 생성, `SetupPreviewModel()`, 첫 화면 표시까지 시간 구간을 나눈다. 작은 모델과 큰 모델의 최초·재열기에서 가장 긴 메인 스레드 호출과 총 로드 시간을 기록한다. 이미 열린 모델 및 썸네일이 많은 폴더와의 차이도 확인한다.
2. **모델 편집기의 문서 열기.** `ImGuiManager`의 공용 진입점과 `ResourceEditorInterface`의 창 상태를 연결한다. 모델 파일과 의존 준비를 백그라운드 작업으로 분리하고 현재 요청이 맞을 때 문서를 반영한다. 하나의 큰 모델에서 창이 먼저 표시되고 기존 문서 보존, 실패, A→B 재요청, 닫기 중 완료가 올바르게 동작하면 다음 단계로 진행한다.
3. **프리뷰와 여러 요청의 작업량 제한.** 계측 결과에 따라 병목인 RHI 호출 또는 씬 배치 작업부터 나누고, 공유 예산과 대기 데이터 제한을 모델 경로에 붙인다. 같은 유형의 여러 요청과 다른 에셋 작업이 겹치는 상황에서 입력·화면 갱신, 진행 우선순위와 메모리 상한을 확인한다.
4. **두 번째 편집기 적용 후 확장.** 측정에서 효과가 큰 유형 하나를 골라 공용 UI·예약·반영 흐름을 재사용한다. 두 편집기를 함께 열어도 서로의 요청을 덮어쓰지 않아야 한다. 각 편집기의 파일 메뉴, 드롭, 브라우저, 피커가 쓰는 진입점을 확인하고 지원 경로를 일치시킨다. 가벼운 편집기는 측정 근거가 생길 때 편입한다.

## 6. 검증과 성능 판정

### 비교 조건과 기록 항목

- 동일 PC·RHI·Release 설정·씬에서 변경 전과 후를 반복 측정한다. 유휴, 비캐시 첫 열기, 이미 로드된 리소스 재열기, 대형 모델, 서로 다른 패널 동시 열기, 썸네일·임포트 동시 동작을 각각 기록한다. 엔진의 리소스 캐시가 비어 있는 첫 열기와 운영체제 파일 캐시 상태를 측정 기록에서 구분한다.
- 요청에서 창의 첫 표시, 문서 편집 가능, 프리뷰 첫 표시까지 걸린 시간을 각각 기록한다. 로딩 구간의 프레임 시간 `p95`, `p99`, 최댓값과 `50ms` 초과 횟수, 최장 메인 스레드 단계, CPU·GPU 대기 시간, 준비 큐와 메모리 최고점, 총 로드 시간을 비교한다. `Editor UI` 측정만으로 렌더 제출 비용을 추정하지 않고 해당 구간을 따로 기록한다.
- 초기 목표는 정상적으로 60 FPS에 가까운 참조 장면에서 **다음 프레임에 창 제출, 요청 후 첫 표시 `p95 ≤ 50ms`, 로드 작업 때문에 `50ms`를 넘는 프레임 `0회`**다. 패널 로드 작업의 합산 메인 스레드 시간은 `2ms` 시작값을 기준으로 기록하고 초과 원인을 남긴다. 유휴·캐시 적중과 총 로드 시간은 변경 전 반복 측정의 변동 범위를 기준으로 악화를 확인한다. 기존 장면 자체가 느리면 로드 없는 동일 조작 구간과 비교해 추가 지연을 구분한다. 수치는 설계 시작값이며 실측과 조정 근거를 구현 기록에 남긴다.

### 완료 체크리스트

- [ ] **정적 검사.** 메인 스레드 대기 경로, 예산 밖 GPU·씬 작업, 로캘 키·파일형식 호환, 요청 소유권과 무효화 지점을 확인한다.
- [ ] **헤드리스 검사.** 작업 완료 순서와 예산을 제어할 수 있는 가짜 준비 작업으로 A→B 역순 완료, 패널별 요청 유지, 중복 요청 공유와 수명, 취소·실패, 프레임 예산 소진 다음 프레임의 재개, 미저장 문서 보존을 확인한다. 기존 문서 이력 회귀는 `EditorHistoryCheck`에서 확인한다.
- [ ] **실환경 사용성.** 로딩 중 씬 카메라 이동, 계층 선택, 도킹 탭 전환과 창 닫기가 동작한다. 좁은 도킹 폭·UI 배율 확대·한영 전환에서 표시가 잘리지 않고 탭이 유지된다. 캐시 적중, 파일 누락·손상, 작업 중 파일 교체, 창 닫고 재열기, 저장 실패, 에디터 종료를 확인한다.
- [ ] **실환경 성능.** 비교 조건별 측정값, 가시 패널 입력 반응, GPU 업로드와 메모리·큐 최고점을 기록한다. 단일 장시간 호출과 다른 작업의 동시 실행으로 초과한 프레임을 구분한다. [에디터 UX 테스트 지침](EditorUXTestGuidelines.md) · [기존 에셋·렌더링 성능 기록](AssetPipelineAndRenderingOptimizationPlan.md)

구현 후 저장소 루트에서 사용자가 실행할 기존 회귀 검사다. 새 상태 검사는 구현 단계에서 적절한 CTest 타깃에 연결한다. UI와 프레임 시간은 Release 에디터에서 별도로 확인한다.

```powershell
cmake --preset x64-debug -DBUILD_TESTING=ON
cmake --build --preset x64-debug --config Debug --target Editor AuditLocalization EditorHistoryCheck ShortcutManagerCheck
ctest --preset x64-debug --output-on-failure -R "LocalizationAuditUtility|EditorHistoryCheck|ShortcutManagerCheck"
cmake --preset x64-release
cmake --build --preset x64-release --config Release --target Editor
```
