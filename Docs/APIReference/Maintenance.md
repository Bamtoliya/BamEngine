# API Reference 유지보수

[목차](README.md) · [감사](APIAudit.md)

## 변경 원칙
- 공개 API 변경 시 동일 PR/커밋에서 해당 레퍼런스와 호출 예제, UserGuide를 갱신한다.
- 구현 상태/안정성/검증 수준을 별도로 기록한다. Stable은 명시적 호환성 정책과 테스트를 갖춘 뒤 부여한다.
- 함수 이름뿐 아니라 실제 전체 signature, 반환/오류, 호출 시점, owner thread, lifetime, 참조 무효화, 좌표계/단위를 작성한다.
- 헤더만 보고 실패 처리/성능/스레드 안전성을 추측하지 않는다. 구현 근거와 검사 경로를 기록한다.
- 엔진 내부 호출용 public API와 게임용 API를 구분한다.
- 새 예제는 프로젝트 모듈로 컴파일하고 PIE/Client를 필요한 범위에서 확인한다.
- 감사 문서에는 확인된 결함 경로와 재현 가설을 구별하며, 해결 시 테스트/커밋을 연결한다.
- 코드 변경을 추적할 수 있는 기준 커밋 및 링크를 갱신한다.

## 후속 자동화 제안 (미구현)
Reflection Generator와 Doxygen/Clang AST 등을 사용해 시그니처/메타데이터를 자동 카탈로그로 추출한다. 이 레퍼런스의 예제와 사용 계약은 수동 관리한다. CI에서 Markdown 링크, 공개 심볼 변경, 코드 조각의 별도 테스트 target을 검사한다.

## 문서 완료 기준
1. 소스와 문서 시그니처 대조.
2. 호출 전제·실패·소유권 명시.
3. 예제의 실제 빌드/실행 결과를 기록.
4. 해당 시스템의 테스트 및 API 감사 갱신.
5. 한국어/영어 문서가 둘 다 있으면 변경 동기화.
