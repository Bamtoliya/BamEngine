## 1. 목표

화면 크기, 프레임 제한과 렌더링 관련 설정을 `GraphicsSettingPanel`에서 쉽게 확인·변경·저장한다.
에디터를 다시 실행하면 저장한 설정을 복원하고, 패널을 닫았다 다시 열어도 실제 적용 상태를 정확히 보여준다.
프리팹 제작·편집·배치 패널을 추가하고, 다른 엔진의 제작 도구를 참고해 현재 빠져 있거나 연결이 부족한 기능을 단계적으로 보완한다.
콘텐츠 브라우저의 내부·외부 에디터 열기와 타입별 미리보기를 연결하고, 컴포넌트의 리소스 핸들을 검색·썸네일로 선택한다.
파티클·스플라인 제작 기능과 바이너리 에셋의 타입별 표시도 후속 목표에 포함하며, 검색·미리보기의 CPU·GPU·메모리 비용을 제한한다.

이 문서는 다음 구현 목표를 기록한다. 패널 생성이나 설정 적용·복원 검증이 완료됐다는 뜻은 아니다.
이번 문서 작성에서는 C++ 코드와 기존 설정 파일을 변경하지 않는다.

## 2. 현재 코드에서 확인한 상태

- 확인일: 2026-11-03.
- 통합 설정 패널(`UnifiedSettingsPanel`)이 전면 구현되어 환경설정 7대 카테고리가 일원화되었으며, ImGui 커스텀 스타일 영속화(`EditorStyle.json`) 및 Unscaled SSOT 아키텍처가 구축되었다.
- 화면 설정은 독립 GraphicSettingPanel에서 편집한다.
  파일 메뉴와 창 메뉴가 같은 패널에 연결되어 있다 (후속으로 3절의 카테고리 기반 `UnifiedSettingsPanel` 통합 예정).
- EditorPreferences는 언어·UI 배율·목표 FPS·VSync를 사용자 설정 경로에 저장한다.
- EditorWorkspace는 창 상태·패널 열림·도킹·콘텐츠 브라우저·뷰포트 상태를 프로젝트별로 저장한다.
- EditorSettingsService가 시작 시 로드·검증과 실행 중 적용 요청·저장 결과를 조정한다.
- 기본 Scene/Game View의 해상도는 대상별 초안으로 편집한다.
  기존 뷰포트 Update에서 리사이즈하고 결과 확인 후 저장한다.
- Scene View의 편집 카메라와 렌더 패스 활성화 상태는 ViewportWorkspace로 캡처·복원한다.
- VSync는 시작 시 복원과 프레임 경계의 변경 요청에 연결되어 있다.
- 손상되거나 지원하지 않는 설정 파일은 기본값으로 대체하고 원본 덮어쓰기를 차단한다.
  시작 알림과 설정 패널에서 저장 차단 상태를 안내한다.
- 씬 문서 보호(`SceneDocument`, `EditorDocumentManager`, `EditorDocumentController`)와 `HistoryPanel`(Undo/Redo 이력 및 저장 기준점 표시)이 구현되어 New/Load/Save/Close 및 종료 흐름에 연결되었다 (11절 A).
- 프리팹 파이프라인(생성·배치, 뷰포트 격리 편집 모드 `PrefabModeManager`, 단일 원천 루트 `PrefabInstanceComponent` 및 Apply/Revert/Unpack, 저장 기준점 Undo 연동)과 엔티티 다중 복사·붙여넣기(`EntityClipboard`)가 구현 완료되었다 (10절, 17절).
- 인스펙터 리소스 피커(`ResourcePicker.h`)의 템플릿 인자 `T`별 호환 확장자 필터링 및 팝업 진입 시 1회 스캔 캐싱과, 콘텐츠 브라우저(`ContentBrowserGridItem`/`ContentBrowserPanel`)의 공통 열기(`OpenAssetOrFolder`), 외부 프로그램 실행(`ShellExecuteW`), 검색 범위 토글(`현재 폴더` vs `전체 리소스 폴더`)이 구현되었다 (14절 A, B, E).
- 전용 리소스/그래프 에디터로 2D `SpriteAnimationEditor`(필름스트립 타임라인·피벗 프리뷰, `ResourceHandle` 참조)와 3D `AnimatorGraphPanel`(상태 머신 캔버스·파라미터 독·트랜지션 인스펙터·활성 상태 하이라이트, 11절 H)이 구현되었으며, `GraphPanel` 상단 도구 모음이 윈도우 메뉴바(`File`, `Edit`, `View`, `Mode`, `Debug/Build`) + 1줄 퀵 액세스 툴바로 리팩터링되었다 (18절).
- EditorSettingsCheck의 파일 입출력·데이터 검사는 통과했다.
  이는 실제 UI·GPU·재실행 복원 검증 완료를 의미하지 않는다.

8절의 실행 검증 항목은 실제 확인 결과에 따라 완료 처리한다.

### 패널 초기화와 등록

- 새 패널은 에디터 UI 스레드에서 힙에 생성한 뒤 `IImGui::Initialize()`를 호출한다. 공통 초기화는 패널별 `OnInitialize()`가 성공한 경우에만 `ImGuiManager`의 추가 대기열에 넣는다. 파생 패널에서 부모 초기화가 필요하면 부모의 `OnInitialize()`를 호출한다.
- 최초 초기화가 성공하면 관리자가 생성 참조를 넘겨받고, 실패하면 생성한 호출자가 해제한다. 등록된 패널의 재초기화는 `AlreadyInitialized`로 거부한다. 목록 반영과 해제는 관리자의 기존 프레임 경계를 따른다.
- 시작 시 생성한 기본 패널은 워크스페이스 복원 대상이다. 실행 중에 만드는 새 뷰포트와 렌더 타깃 뷰어도 같은 초기화 경로를 사용한다. `창 > 패널`의 하위 메뉴는 각 인스턴스의 `GetPanelMenuCategory()`를 읽으며, 가져오기 팝업은 메뉴에서 숨긴다.
- 수동 확인 항목은 시작 후 기본 패널 복원, 새 뷰포트와 렌더 타깃 뷰어의 등록 및 메뉴 토글, 여러 뷰포트가 열린 상태에서의 정상 종료다.

## 3. 통합 설정 패널(Unified Settings Panel)의 구성과 카테고리 분류

여러 설정이 개별 독립 패널(`GraphicSettingPanel`, `ShortcutSettingsPanel` 등)로 파편화되거나 한 화면에 무질서하게 나열되는 문제를 해결하기 위해,
언리얼의 `Editor Preferences / Project Settings` 및 Visual Studio의 `Options` 구조를 벤치마크하여 **좌측 카테고리 네비게이션 + 우측 상세 속성 뷰**의 2열 구조를 갖춘 **통합 설정 패널(`UnifiedSettingsPanel` 또는 `EditorSettingsPanel`)** 로 일원화한다.

`ImGuiManager`의 기본 패널 목록과 상단 메뉴(`File > Settings` 및 `Window > Settings`)에서 단일 진입점으로 제공하며, 기존의 개별 설정 UI를 카테고리별 하위 뷰로 통합한다.

### 3.1 레이아웃 구조

```
+---------------------------------------------------------------------------------+
| Settings                                                                      x |
+---------------------------------------------------------------------------------+
| [Q Search settings...                                                        ] |
+-----------------------+---------------------------------------------------------+
| Category              | General Settings                                        |
| --------------------- | ------------------------------------------------------- |
| > General             | [v] Language                                            |
|   Graphic             |     Language: [ Korean               v ]                |
|   Editor              |                                                         |
|   Workspace           | [v] Auto Save                                           |
|   Shortcuts           |     Enable Auto Save: [x]                               |
|   Project Settings    |     Interval (Minutes): [ 5 ]                           |
|                       |                                                         |
|                       | [v] Startup                                             |
|                       |     Restore Last Scene: [x]                             |
+-----------------------+---------------------------------------------------------+
| Status: Modified      |                 [ Reset Defaults ]  [ Revert ]  [ Apply ] |
+-----------------------+---------------------------------------------------------+
```

1. **상단 검색창 (Search Filter):**
   - `ImGuiTextFilter` 기반의 실시간 키워드 검색.
   - 검색어 입력 시 매칭되는 속성을 포함하는 카테고리에 검색 결과 개수 배지(Badge)를 표시하고, 검색 결과 목록에서 선택 시 해당 카테고리 및 속성 섹션으로 자동 스크롤 점프.
2. **좌측 카테고리 사이드바 (Navigation Sidebar):**
   - 너비 조절 가능한 좌측 차일드 윈도우(`ImGui::BeginChild`).
   - 카테고리 목록(아이콘 및 텍스트)을 나열하며, 현재 선택된 활성 카테고리를 하이라이트 표시.
3. **우측 상세 속성 뷰 (Content Area):**
   - 선택된 카테고리에 속한 세부 속성들을 `ImGui::CollapsingHeader` 및 세부 그룹 박스로 깔끔하게 분할 렌더링.
   - 각 속성 라벨, 입력 위젯(드롭다운, 슬라이더, 체크박스 등) 및 기능 설명 툴팁(`(?)` 도움말 마커) 제공.
4. **하단 액션 바 (Footer Action Bar):**
   - 변경 상태 표시: 초안 수정 발생 시 `Status: Modified (Unsaved Changes)` 경고 텍스트 표시.
   - `기본값으로 복원 (Reset to Defaults)`: 현재 카테고리(또는 전체)의 속성을 권장 기본값으로 리셋.
   - `되돌리기 (Revert)`: 변경 중인 초안을 취소하고 마지막으로 저장된 값으로 즉시 복귀.
   - `적용 (Apply)`: 수정한 초안들의 유효 범위를 검증하고 Application, RHI, Config 경로에 즉시 반영 및 디스크 저장.

### 3.2 카테고리별 세부 속성 분류

#### A. `General` (일반 설정)
- **언어 (Localization):** 에디터 표시 언어 선택(`Korean` / `English`), 언어 변경 시 UI 실시간 재번역 반영.
- **테마 및 스타일 (Appearance):** 에디터 다크/라이트 테마 프리셋, 강조 색상(Accent Color).
- **자동 저장 (Auto-save):** 주기적 씬 자동 저장 활성화 여부 및 주기(분 단위).
- **시작 동작 (Startup):** 에디터 실행 시 마지막으로 열었던 씬 자동 로드 여부(`LastScenePath` 연동).

#### B. `Graphic` (그래픽 및 디스플레이)
- **화면 및 해상도:** 에디터 창 너비·높이, 창 모드(창 모드 / 최대화 / 전체화면).
- **프레임 레이트:** 목표 FPS 설정(0=무제한, 30, 60, 120, 144 등) 및 실측 FPS 대비 제한값 명시.
- **수직동기화 (VSync):** VSync On/Off 토글 및 프레임 경계에서의 스왑체인 동기화 적용.
- **품질 프리셋:** 렌더링 품질 프리셋(Low, Medium, High, Ultra), 타일 라이트 컬링 활성화 여부, 섀도우 맵 해상도.
- **디스플레이 변경 안전장치:** 창 크기/전체화면 변경 시 15초 카운트다운 확인 팝업 및 자동 복구 메커니즘.

#### C. `Editor` (에디터 환경)
- **UI 배율 (UI Scale):** 전체 에디터 인터페이스 DPI 스케일링 배율(0.5x ~ 3.0x), 취소 및 원래 값 복원 지원.
- **기즈모 스냅 (Gizmo Snapping - 방안 A 확정):**
  - 이동/회전/스케일 스냅 단위(`GizmoSnapTranslation`, `GizmoSnapRotation`, `GizmoSnapScale`)는 특정 뷰포트 인스턴스에 종속되지 않고 `EditorPreferences`에 소유권을 일원화하여 `EditorPreferences.json`에 영속화한다.
  - 모든 3D 뷰포트(`SceneViewportPanel`, 향후 프리팹 뷰포트, 분할 뷰포트 등)는 `EditorSettingsService`를 단일 진실의 원천(SSOT)으로 참조하여 일관된 스냅 단위를 유지한다.
- **뷰포트 탐색 카메라:** 씬 뷰포트 카메라 이동 속도(`CameraSpeed`), 감도, FOV(기본 60도), 직교 크기(Orthographic Size).
- **디버그 및 로깅:** 콘솔 창에 출력할 최소 로그 레벨 필터(`Trace`, `Info`, `Warning`, `Error`).

#### D. `Workspace` (작업 공간)
- **도킹 레이아웃:** 기본 에디터 도킹 레이아웃 복원(`Reset Layout`), ImGui ini 레이아웃 저장 상태.
- **뷰포트 해상도 프리셋:** Scene View 및 Game View 대상 내부 렌더 해상도 모드(Free Aspect, 16:9, 16:10, Fixed Resolution) 및 커스텀 해상도 관리.
- **렌더 패스 기본 상태:** 뷰포트별 렌더 패스(Shadow, Geometry, Lighting, PostProcess, UIOverlay 등)의 기본 활성화 토글.
- **콘텐츠 브라우저:** 기본 썸네일 그리드 크기(32px ~ 128px), 에셋 검색 캐시 갱신 주기.

#### E. `Shortcuts` (단축키 매핑)
- 기존 독립 `ShortcutSettingsPanel`의 기능을 카테고리 하위 뷰로 완전 통합.
- **액션 매핑 테이블:** 기능 도메인별(뷰포트 조작, 씬 편집, 파일 작업, 그래프 에디터 등) 단축키 목록 테이블 표시.
- **키 캡처 및 변경:** 테이블 항목 클릭 후 원하는 키/조합키(Ctrl, Shift, Alt 등) 입력 시 즉시 캡처 및 바인딩.
- **충돌 감지 (Conflict Detection):** 이미 할당된 단축키와 중복될 경우 즉각적인 붉은색 경고 표시 및 덮어쓰기/취소 선택 제공.
- **기본값 복원:** 특정 액션 또는 전체 단축키를 기본 매핑으로 원클릭 리셋.

#### F. `Project Settings` (프로젝트 설정)
- **프로젝트 메타데이터:** 프로젝트 명, 제작자, 프로젝트 버전.
- **기본 씬 (Default Scenes):** 게임 클라이언트 실행 시 시작 씬 경로(`StartupScenePath`).
- **게임 입력 액션 (Input Action Mapping):** 인게임 게임플레이에서 사용하는 `InputActionMap`(예: `MoveForward`, `Jump`, `Fire`)과 입력 장치 바인딩(키보드/마우스/게임패드).
- **패키징 기본값:** 배포 시 포함할 필수 리소스 목록 및 기본 렌더 해상도.

## 4. 저장 범위와 소유권의 엄격한 분리

모든 설정을 단일 통합 창(`UnifiedSettingsPanel`)에서 편집하더라도, 각 데이터의 본래 성격과 수명에 맞는 **저장 소유자(Owner)** 와 파일 경로를 엄격히 분리 유지한다. 패널 내부에 임의의 모놀리식 단일 저장소를 만들지 않는다.

1. **사용자 개인 설정 (`EditorPreferences`):**
   - 언어, UI 배율, 목표 FPS, VSync, 에디터 테마 등 개발자 개인 환경에 귀속되는 설정.
   - `SDL_GetPrefPath("BamEngine", "Editor")` 아래 `EditorPreferences.json`에 저장(현재 구현).
   - **기즈모 스냅 단위 (`GizmoSnapTranslation`, `GizmoSnapRotation`, `GizmoSnapScale`):** 특정 뷰포트 인스턴스의 일회성 상태가 아닌 에디터 전역 사용자 환경설정에 속하므로 `EditorPreferences`에 포함하여 영속화하고, `UnifiedSettingsPanel` 및 뷰포트에서 공통 참조한다.
2. **프로젝트별 작업 상태 (`EditorWorkspace`):**
   - 창 크기, 패널 열림 상태, 도킹 배치, 뷰포트별 해상도/카메라 상태 등 프로젝트 작업 공간에 귀속되는 상태.
   - 프로젝트 루트의 `.bam/User/Workspace.json`에 저장(현재 구현).
3. **단축키 매핑 (`ShortcutManager`):**
   - 에디터 작업 액션별 단축키 바인딩 데이터.
   - 사용자 환경설정 폴더의 `EditorShortcuts.json`을 사용한다. `Resources/Config/EditorShortcuts.json`은 레거시 입력 경로다(현재 Application 초기화).
4. **프로젝트 공통 설정 (`ProjectSettings`):**
   - 프로젝트 이름, 시작 씬 경로, 인게임 입력 액션 등 버전 관리에 포함되어 팀 전체가 공유해야 하는 설정.
   - 프로젝트 루트의 `Config/Project.json`에 저장(현재 구현).
5. **ImGui 커스텀 스타일 (`EditorStyle.json`):**
   - `ImGui::ShowStyleEditor`를 통해 사용자가 자유롭게 커스터마이징한 색상(55개 컬러 슬롯) 및 라운딩/패딩/여백 데이터.
   - 사용자 환경설정 폴더의 `EditorStyle.json`에 저장(`EditorSettingsService::GetPreferencesPath().parent_path() / "EditorStyle.json"`).
   - **Unscaled Base Style SSOT 원칙**: UI 배율(`UIScale`)이 역적용된 1.0f 기준 순수 수치로 파일에 저장하고 메모리에서는 `m_BaseStyle`로 보관하여, `SetUIScale()` 호출 시 누적 곱연산에 의한 간격 왜곡 없이 언제나 깨끗하게 1회 스케일링되도록 보장한다.

저장 데이터는 모두 기존 리플렉션 및 `ReflectionArchive` 기반 JSON 직렬화 경로를 일관되게 사용하며, 누락된 필드는 안전한 기본값으로 폴백한다.

## 5. 적용과 저장의 동작 라이프사이클

통합 설정 패널은 사용자의 의도하지 않은 설정 오염을 방지하기 위해 **초안(Draft) 기반 3단계 라이프사이클**을 따른다.

1. **진입 시 동기화 (Open & Sync):**
   - 패널을 열 때 각 소유 서비스(`EditorSettingsService`, `ShortcutManager`, `ConfigManager`)로부터 현재 적용된 최신 상태를 읽어와 UI 초안 버퍼(`m_Drafts`)에 복사한다.
2. **초안 편집 및 변경 감지 (Edit & Dirty Tracking):**
   - 사용자가 위젯을 조작할 때 실제 엔진 상태를 즉시 변동시키지 않고 초안 값만 수정한다.
   - 원본 값과 초안 값의 차이를 감지하여 `Dirty` 플래그를 활성화하고, 하단에 변경 경고 및 `Revert` / `Apply` 버튼을 활성화한다.
3. **유효성 검증 및 적용 (Validate & Commit):**
   - `Apply` 클릭 시 입력된 값(창 크기 최소값, FPS 상한, 단축키 중복 등)의 유효 범위를 먼저 검사한다.
   - 검증 통과 시 해당 서비스의 API를 호출하여 런타임에 즉각 적용(윈도우 리사이즈, UI 배율 갱신, VSync 설정 등)하고, 디스크 파일 저장을 수행한다.
   - 적용 실패 또는 디스크 쓰기 실패 시 에러 토스트/로그를 출력하고 이전 유효 상태를 안전하게 보존한다.

## 6. 관련 후속 목표: 뷰포트와 편집 카메라 복원

- 기본 뷰포트마다 해상도 모드·프리셋·사용자 크기·종횡비를 저장한다.
- 프리셋 순서 변경으로 다른 해상도가 선택되지 않도록 안정된 식별 방식이나 실제 해상도 값을 검토한다.
- 편집 카메라의 위치·회전·투영 방식·FOV 또는 직교 크기·이동 속도를 프로젝트별로 저장한다.
- 씬에 속한 게임 카메라와 에디터의 탐색용 카메라를 구분한다.
- 복원 값은 범위·유한 값·enum을 검증하고, 기존 Transform·카메라 갱신 API로 적용한다.
- 렌더 해상도는 기존 리사이즈 경로로 적용하며 GPU 객체 자체를 복원하지 않는다.
- 처음에는 기본 생성 뷰포트를 대상으로 한다. 사용자가 추가한 뷰포트의 재생성은 별도 후속 범위로 둔다.
- 뷰포트별 렌더 패스(Shadow, PointShadow, Geometry, Lighting, Forward, UIOverlay 등)의 On/Off 토글 상태를 `ViewportWorkspace`에 저장하고 에디터 재실행 시 복원한다.
- 런타임에 동적으로 변경된 패스 활성화 상태를 뷰포트 상태 캡처(`CaptureViewportState`) 시 직렬화하고, 복원(`RestoreViewportState`) 시 해당 `RenderPassID`의 `SetEnabled`로 적용한다.
- 새 패스 추가나 이름 변경 시에도 이전 작업 공간 파일을 안전하게 읽을 수 있도록 기본값(`true`) 폴백 정책을 유지한다.

## 7. 구현 순서

아래는 **통합 설정 패널 내부**의 구현 순서다. 프로젝트 전체의 첫 작업을 뜻하지 않는다.
현재는 애니메이터 문서 보호·입력 일원화, 리소스 피커 정확성, 썸네일 예산·참조 검증을 먼저 진행한다.
전역 선택과 완료 기준은 [DevelopmentPriorities.md 10절](DevelopmentPriorities.md)을 따른다.

1. **1단계 (통합 패널 프레임워크 구축):**
   - `UnifiedSettingsPanel`을 생성하고 좌측 카테고리 네비게이션(사이드바) 및 우측 콘텐츠 영역 2열 레이아웃을 구축한다.
   - 상단 실시간 검색 필터와 하단 상태바(`Apply`, `Revert`, `Reset Defaults`)를 연결한다.
2. **2단계 (기존 패널 이관 및 카테고리 연동):**
   - `GraphicSettingPanel`의 화면·해상도·VSync 로직을 `Graphic` 및 `Workspace` 카테고리로 이관한다.
   - `ShortcutSettingsPanel`의 단축키 테이블·키 캡처 로직을 `Shortcuts` 카테고리로 완전 통합한다.
   - 언어 선택 및 자동 저장 등 사용자 환경설정을 `General` 카테고리에 배치한다.
3. **3단계 (에디터 환경 및 프로젝트 설정 확장):**
   - `Editor` 카테고리에 기즈모 감도, 카메라 속도, 로그 레벨 옵션을 연결한다.
   - `Project Settings` 카테고리에 프로젝트명, `StartupScenePath`, 인게임 입력 액션 맵 인터페이스를 구축한다.
4. **4단계 (메뉴 통합 및 중복 제거):**
   - 상단 메뉴(`File > Settings`, `Window > Settings`)의 진입점을 `UnifiedSettingsPanel`로 단일화한다.
   - 기존의 파편화된 개별 창 메뉴 항목을 정리하고, 필요 시 해당 카테고리가 기본 선택된 상태로 통합 창을 팝업하도록 연결한다.

## 10. 프리팹 관련 패널과 작업 흐름

### 초기 조사에서 확인한 기반과 부족한 연결

- `SceneManager::SavePrefab()`과 `InstantiatePrefab()`이 있고, `Scene`에는 프리팹 Archive 저장·복원 코드가 있다.
- 현재 프리팹은 선택한 루트의 하위 계층과 컴포넌트를 저장하고, 배치 시 새 엔티티로 복원하는 기반이다.
  이 코드만으로 원본 에셋과 인스턴스의 지속적인 연결이나 변경 전파가 구현됐다고 판단하지 않는다.
- `Editor/Source`에서 프리팹 저장·생성 API를 호출하는 편집 UI와 전용 프리팹 편집 패널은 확인되지 않았다.
  `EResourceType::Prefab` 표시 항목의 존재도 프리팹 편집 기능의 완료 근거로 삼지 않는다.
- `WritePrefabArchive()`는 저장할 서브트리를 순회하며 로컬 ID를 부여한다.
  이 ID를 파일 편집 전후에도 유지되는 인스턴스 변경 추적 식별자로 바로 사용하지 않는다.

참고 기능: Unity는 프리팹을 별도 편집 문맥에서 여는 Prefab Mode와,
원본에 대한 인스턴스 변경값을 표시·적용·되돌리는 기능을 제공한다.
[Prefab Mode](https://docs.unity3d.com/6000.0/Documentation/Manual/EditingInPrefabMode.html),
[Instance Overrides](https://docs.unity3d.com/6000.0/Documentation/Manual/PrefabInstanceOverrides.html)

### 1단계: 프리팹 만들기와 배치 (2026-10-31 구현 완료)

- Hierarchy에서 단일 루트 엔티티를 선택해 우클릭 `Save As Prefab...` 메뉴로 하위 계층을 프리팹 파일(`*.bamprefab.json`)로 저장한다.
- Content Browser에서 프리팹 파일을 식별(`ICON_FA_CUBES` 큐브 아이콘 및 시안 틴트)하고, 더블클릭 시 프리팹 모드로 즉시 진입한다.
- Scene View 또는 Hierarchy의 대상 부모로 드래그 앤 드롭하여 배치하고, 생성된 루트와 하위 객체를 한 편집 명령으로 Undo/Redo한다.
- 파일 선택·저장 대화상자는 `EFileDialogContext::PrefabSave` Context를 사용해 다른 작업의 폴더 이력과 구분한다.
- 기존 Archive와 리플렉션 경로를 재사용하며, `.bamprefab.json` 전용 확장자로 일반 씬/JSON 파일과 구분한다.

### 2단계: 프리팹 격리 편집 모드 (`PrefabModeManager`) (2026-10-31 구현 완료)

- 프리팹 파일을 열어 전용 독립 씬(`m_PrefabScene`)에서 계층·컴포넌트·기즈모를 100% 활용해 편집한다.
- 메인 씬은 `Safe_AddRef`로 메모리에 안전 보존하고, 메인 뷰포트(`SceneViewportPanel`), 하이어라키, 인스펙터, `ImGuizmo`를 그대로 재사용한다.
- 뷰포트 상단에 `◀ Back to Scene (씬으로 복귀)` 및 `Save` 배너를 렌더링하여 원클릭으로 메인 씬에 복귀한다.
- 메인 씬의 선택과 편집 데이터를 보존하고, 프리팹 세션에 게임 실행이나 PIE 변경이 섞이지 않게 한다.
- 미저장 변경 플래그(`m_HasUnsavedChanges`) 및 토스트 알림을 제공한다. 저장 기준점과 Undo/Redo 연동은 아래 후속 기록을 따른다.

### 2026-11-01 후속: 저장 기준점과 Undo/Redo 변경 표시

- 상태: 코드 반영 / 빌드·실제 UI 검증 미확인. 기존 단계의 완료 표시는 이번 변경의 실행 검증 근거로 사용하지 않는다.
- `HasUnsavedChanges()`는 현재 프리팹을 대상으로 하는 편집 이력의 저장 기준점과 현재 상태를 비교한다. 별표와 종료 확인은 같은 조회 결과를 사용한다.
- 프리팹 진입 전 메인 씬의 미저장 여부를 보관하고, 전환이 확인되면 `ResetDocument()`로 프리팹의 시작 기준점을 설정한다.
- 저장 성공 시 기존 `MarkSaved()` 경로를 사용한다. 메인 씬 복귀가 성공하면 이력 대상을 되돌리고, 진입 전에 미저장 상태였다면 그 사실을 복원한다.
- 메인 씬의 이전 Undo/Redo 명령 목록을 복원하는 기능은 포함하지 않는다. 코드 및 검증 범위는 [ImplementationLog.md](ImplementationLog.md)의 2026-11-01 기록을 따른다.

Visual Studio F5 수동 확인 항목:

- [ ] 프리팹을 처음 열면 별표가 없고, 이력에 기록되는 속성을 편집하면 별표가 나타난다.
- [ ] 입력 편집을 확정한 뒤 씬 뷰에 포커스를 두고 Undo하면 시작 기준점에서 별표가 사라진다. Redo하면 다시 나타난다.
- [ ] 저장 후 추가 편집을 Undo해 저장 기준점으로 돌아오면 별표가 사라진다. 저장 상태에서 과거 상태로 Undo하면 다시 나타난다.
- [ ] 저장 기준점에서는 종료 확인이 뜨지 않고, 변경 상태에서는 저장·버리기·취소를 선택할 수 있다.
- [ ] 저장 실패에서는 편집 내용과 종료 확인창이 유지된다.
- [ ] 메인 씬이 미저장인 상태로 프리팹을 열었다가 복귀해도 메인 씬의 미저장 표시가 유지된다.
- [ ] 메인 씬이 저장된 상태였다면 프리팹 복귀 후 잘못된 미저장 표시가 생기지 않는다.

### 3단계: 원본 연결과 인스턴스 오버라이드 관리 (2026-10-31 구현 완료)

- **단일 원천 루트 전용 설계**: 데이터 중복(Single Source of Truth 위반)을 방지하기 위해 `PrefabInstanceComponent`는 프리팹 서브트리의 루트 엔티티에만 부착한다.
- **자식 엔티티 동적 판별**: `HierarchyComponent::parent`를 탐색하는 `FindPrefabRootHandle` 헬퍼를 통해 자식 엔티티도 즉시 자신의 프리팹 루트 및 원본 에셋 경로를 식별한다.
- **Hierarchy 시각화**: 프리팹 루트는 `ICON_FA_CUBES`, 자식은 `ICON_FA_CUBE`/`ICON_FA_FOLDER`와 함께 유니티 스타일 청록색(`ImVec4(0.35f, 0.78f, 1.0f, 1.0f)`)으로 강조 표시된다.
- **Hierarchy 컨텍스트 메뉴**: 루트 및 자식 엔티티 우클릭 시 `Open Prefab`, `Select in Content Browser`, `Unpack Prefab` 메뉴를 제공한다.
- **InspectorPanel 상단 프리팹 헤더 바**:
  - 루트 엔티티: `Prefab: 에셋명`, 자식 엔티티: `(Child of 에셋명)`으로 명확히 구분 표시.
  - `Open`: 클릭 시 `PrefabModeManager::Get().EnterPrefabMode`로 프리팹 뷰포트 편집 모드 즉시 진입.
  - `Select`: `SelectionManager::Get().SetSelectedAsset`으로 Content Browser에서 에셋 위치 즉시 강조.
  - `Overrides` 드롭다운 메뉴:
    - **Apply All**: 현재 인스턴스의 변경사항을 원본 `.bamprefab.json` 에셋에 덮어써서 원본 파일 갱신.
    - **Revert All**: 원본 프리팹 에셋으로부터 다시 인스턴스화하고 기존 Transform을 복원하여 원래 상태로 되돌리기.
    - **Unpack**: `world.remove<PrefabInstanceComponent>(rootHandle)`로 단번에 프리팹 연결을 해제하고 일반 독립 엔티티로 전환.
- **다국어 로캘 원본 동기화**: `Engine.csv`(컴포넌트 리플렉션) 및 `Editor.csv`(UI/메뉴/알림/히스토리)에 다국어 키 등록 완료.

### 프리팹 완료 검증

- [x] 선택 루트와 자식 계층·컴포넌트·지원하는 리소스 참조가 저장 후 재실행에서도 복원된다.
- [x] 여러 번 배치해도 엔티티 ID가 충돌하지 않고, 부모 지정과 Undo/Redo가 올바르게 동작한다.
- [x] 프리팹 편집(`PrefabModeManager`)이 메인 씬·선택·PIE 상태를 의도치 않게 변경하지 않는다.
- [x] 저장 실패와 손상된 프리팹 로드 실패에서 기존 파일·씬·편집 초안이 보존된다.
- [x] 3단계 원본 에셋 연결, 인스펙터 헤더 바, Apply All / Revert All / Unpack, 다국어 지원이 구현되었다.

## 11. 다른 엔진을 참고한 추가 목표

아래는 현재 소스와 전용 UI 연결을 확인해 선정한 개발 후보다.
저장소 전체에 해당 기반이 전혀 없다는 뜻은 아니며, 이미 있는 기능과 새로 필요한 기반을 구분한다.
패널 이름은 제안이다. 기존 Inspector나 Content Browser 확장으로 해결되는 기능은 그 위치에 통합할 수 있다.

### A. 씬 문서 상태·미저장 변경 보호와 `HistoryPanel` — 우선순위 높음

- 현재 기반: `ToolBar`의 씬 생성·열기·저장·닫기, `SceneEditHistory`와 `CommandHistory`의 Undo/Redo,
  `SceneDocument`·`EditorDocumentController`의 저장/교체 보호와 `HistoryPanel`이 있다(2026-11-02 정적 대조).
- 남은 범위: 씬의 실제 실패/취소 검증과 각 리소스 편집기의 보호 일관성. 특히 AnimatorGraphPanel은 저장/로드 반환값과 미저장 교체 보호를 보완해야 한다(점검 F01).
- 목표: 씬 경로·변경 표시·일반 저장·다른 이름으로 저장을 구분하고, 씬 교체·닫기·종료 전에 저장 여부를 확인한다.
- 이력 패널은 명령 이름·현재 위치·저장 기준점을 보여준다. 기존 Undo/Redo를 재사용하고 명령 컨테이너를 외부에서 수정하게 노출하지 않는다.
- 저장 기준점은 명령 개수만으로 판단하지 않는다. Undo 후 분기, 이력 제한, 명령을 거치지 않는 편집도 고려한다.
- 자동 백업·복구는 후속 범위다. 원본과 별도 파일, 복구 시점, 복구 실패와 보관 한도를 정의한다.
- 완료 기준: 저장 취소가 씬 교체를 취소하고, 저장 실패 시 문서와 변경 표시를 유지한다. 이력 표시와 실제 Undo/Redo가 일치한다.
- 참고: Unity의 [Undo History](https://docs.unity3d.com/6000.0/Documentation/Manual/UndoWindow.html)는 이력을 시각적으로 탐색하는 창이다.

### B. `AssetReferencePanel`과 에셋 검증 — 우선순위 높음

- 현재 기반: ResourceManagerInspector와 MetricsPanel에서 로드된 리소스와 통계를 조회한다.
  확인한 등록 패널 목록에는 에셋의 정방향·역방향 참조를 탐색하는 전용 UI가 없다.
- 목표: 선택 에셋이 사용하는 파일, 해당 에셋을 사용하는 씬·프리팹·머티리얼, 누락된 참조를 목록과 그래프로 보여준다.
- 기반 작업: 저장된 문서의 참조를 수집·색인하고 에셋 변경 시 갱신한다. 현재 로드된 핸들 목록만으로 프로젝트 전체 참조를 판단하지 않는다.
- 참조 해석 실패, 순환 관계와 동적 로드로 정적 수집할 수 없는 항목을 구분한다.
- 삭제·이동 전 영향 조회와 배포 포함 검사에 연결한다. 자동 참조 수정은 식별·검증·실패 복구 정책 이후에 구현한다.
- 완료 기준: 알려진 씬 → 머티리얼 → 텍스처 관계를 양방향으로 찾고, 누락된 파일의 사용 위치를 표시한다.
- 참고: Unreal의 [Reference Viewer](https://dev.epicgames.com/documentation/en-us/unreal-engine/reference-viewer-in-unreal-engine)는 에셋 참조 그래프와 참조·역참조 조회를 제공한다.

### C. `AssetImportSettingsPanel` 또는 Inspector 확장 — 우선순위 보통

- 현재 기반: TextureInspector에 임포트 설정 UI가 있고, ModelImportDesc와 Content Browser의 모델 재임포트 경로가 있다.
  임포트 기능 전체가 없는 것으로 취급하지 않는다.
- 목표: 원본 파일·출력 에셋·실제로 적용한 임포트 옵션을 연결해 보여주고, 저장한 옵션으로 재임포트한다.
- 모델·텍스처부터 적용하며, 타입별 미지원 옵션은 실제 지원 범위를 표시한다.
- 기반 작업: 원본과 생성 파일의 연결, 옵션 메타데이터 저장, 출력 충돌과 실패 시 보존을 정한다.
- 완료 기준: 에디터 재실행 후에도 옵션을 다시 읽고, 같은 원본을 같은 설정으로 재임포트할 수 있다.
- 참고: Unity의 [Model Import Settings](https://docs.unity3d.com/6000.0/Documentation/Manual/class-FBXImporter.html)는 선택한 모델 파일의 임포트 옵션을 Inspector에서 편집한다.

### D. `ProjectSettingsPanel`과 게임 입력 액션 편집 — 우선순위 보통

- 현재 기반: ProjectSettings와 ConfigManager, 에디터 ShortcutSettingsPanel과 InputManager가 있다.
  파일 메뉴의 설정 항목은 비어 있고, 검색한 소스에서 게임용 InputAction·ActionMap 편집 연결은 확인되지 않았다.
- 목표: 프로젝트 이름과 공통 실행 설정을 편집·검증·저장하고, 게임 액션과 키·마우스 바인딩을 편집한다.
- 에디터 단축키와 게임 입력 액션은 데이터와 적용 문맥을 구분한다. 처음에는 현재 InputManager가 지원하는 입력부터 연결한다.
- 액션 이름·바인딩·입력 문맥을 Engine에서 해석하는 기반이 선행돼야 하며, 패널이 입력 상태를 직접 수집하지 않는다.
- Client 시작 씬·배포 기본값의 실행 연결은 기존 빌드·패키징 계획과 함께 진행한다.
- 완료 기준: 액션 설정이 재실행 후 복원되고, 같은 데이터가 PIE와 Client의 공통 입력 경로에서 해석된다.
- 참고: Godot의 [Project Settings](https://docs.godotengine.org/en/stable/tutorials/editor/project_settings.html)에는 Input Map을 비롯한 프로젝트 설정 편집이 있다.

### E. `ProfilerPanel` 또는 MetricsPanel 확장 — 우선순위 보통

- 현재 기반: MetricsPanel에 프레임 시간, 렌더 호출, 리소스와 에셋 작업 통계가 있다.
  RHIFrameMetrics의 드로 호출 통계는 GPU 실행 시간 측정과 구분한다.
- 목표: 프레임 선택·일시정지·CPU 작업 구간·스레드별 시간 흐름을 조회하고, 캡처를 저장·비교한다.
- 기반 작업: 측정 구간과 프레임 ID, 스레드별 수집과 보관 한도를 정의한다. GPU 시간은 RHI 타임스탬프 수집을 연결한 뒤 표시한다.
- 현재 MetricsPanel을 요약 화면으로 재사용한다. 시간 측정과 단순 호출 횟수·추정 메모리를 구분한다.
- 완료 기준: 측정 오버헤드와 지원 범위를 기록하고, 동일 조건의 캡처로 변경 전후를 비교할 수 있다.
- 참고: Unity의 [Profiler](https://docs.unity3d.com/6000.0/Documentation/Manual/ProfilerWindow.html)는 프레임별 모듈과 선택 프레임의 상세 정보를 제공한다.

### F. `AnimationTimelinePanel`과 애니메이션 미리보기 — 장기 목표

- 현재 기반: Animation 리소스에 트랙·길이 데이터가 있지만, 확인한 에디터 등록 목록에는 타임라인 패널이 없다.
  재생·보간·모델 연결과 지원하는 임포트 범위는 별도 확인 대상이다.
- 목표: 지원하는 클립의 재생·정지·스크러빙과 트랙 조회부터 시작하고, 키 편집·보간·저장을 단계적으로 추가한다.
- 우선 Transform 또는 단순 속성 트랙으로 흐름을 완성한다. 스키닝·블렌딩·상태 머신은 런타임 기반 이후에 연결한다.
- 미리보기는 원본 씬의 편집 데이터를 보존하고, 재생 중 상태와 저장할 키 데이터를 구분한다.
- 완료 기준: 같은 클립을 미리보기와 런타임에서 해석하고, 키 편집·Undo·저장·재실행 복원이 일치한다.
- 참고: Godot의 [Animation 편집](https://docs.godotengine.org/en/stable/tutorials/animation/introduction.html)은 트랙·키프레임·타임라인과 속성 편집을 연결한다.

### G. `BuildProfilePanel` — 설정, Client 빌드와 폴더 내보내기 연결

- 현재 목표 문서: [BuildAndPackagingPlan.md](BuildAndPackagingPlan.md).
- 대상 구성·시작 씬·출력 폴더·필수 에셋과 포함 모듈을 선택하고 진행 단계·로그·실패 원인을 보여준다.
- `파일 > 빌드 및 패키징…`에서 설정, 씬 참조 검사와 Windows Release Client 빌드를 진행한다. 시작 씬과 출력 폴더 다이얼로그는 서로 다른 문자열 이력 키를 사용한다.
- Client 빌드와 폴더 내보내기는 Editor 내부 작업에서 실행하며, 패널에 최종 배포 경로, 진행 상태, 완료 로그를 표시한다. 기존 출력과 충돌하면 오류를 표시한다. 변경 후 실제 UI와 독립 실행은 검증해야 한다.
- 완료 기준은 UI 버튼 동작뿐 아니라 개발 경로 밖의 배포 폴더에서 Client가 실행되는 것이다.

  4. **파라미터 독(Dock):** `Float`, `Int`, `Bool`, `Trigger` 파라미터 추가·삭제 및 실시간 값 조작.
  5. **실시간 디버깅 및 직렬화:** `.animator` JSON 저장/복원(`FileDialogs` 연동) 및 씬 선택 엔티티의 현재 활성 상태 노드 청록색 발광 테두리 시각화 완료.
- **후속 범위:** 패널 내부 격리된 3D 모델 프리뷰 뷰포트(`PreviewViewport`) 내장.

## 12. 확장 목표의 권장 진행 순서

아래는 Editor 기능 내부 순서다. 다른 계획과의 작업 선택·보류 조건은 통합 우선순위 계획을 따른다.
미저장 보호·공통 설정·기본 에셋 판정/캐시 예산을 P1으로 우선하고, 전용 패널보다 필요한 런타임 계약을 먼저 연결한다.

1. 현재 설정·뷰포트 저장 코드의 빌드와 재실행 검증을 마무리한다.
2. `GraphicsSettingPanel`과 씬 문서의 미저장 보호를 구현한다.
3. 17절의 엔티티 복사·붙여넣기를 기존 선택·편집 이력에 연결하고, 프리팹 만들기·배치 후 `PrefabEditorPanel`의 독립 편집·저장 흐름을 완성한다.
4. 14절의 공통 타입 판정·열기 경로와 미리보기 비용 제한부터 정리하고, 리소스 검색·썸네일 선택을 연결한다.
5. 에셋 참조 조회와 임포트 옵션 저장·재임포트를 연결한다.
6. 안정된 프리팹 식별·인스턴스 연결을 마련하고 변경값 비교·적용·되돌리기를 추가한다.
7. 프로젝트 설정·게임 입력 액션·상세 프로파일링을 실제 사용 요구에 따라 진행한다.
8. 파티클·스플라인은 15절의 최소 런타임·저장·편집 흐름부터 만들고, 같은 타입 분류와 썸네일 경로에 연결한다.
9. 빌드·패키징 UI는 해당 단계에서, 애니메이션·중첩 프리팹·Variant는 필요한 런타임 기반 이후에 진행한다.

이 순서는 제안이다. 다른 엔진에 있다는 이유만으로 모든 창을 먼저 만들지 않는다.
각 항목은 사용자가 수행할 작업, 필요한 데이터·API, 저장 위치와 실패 경로를 먼저 정한 뒤 구현한다.

빌드·테스트·실제 프리팹 및 다른 엔진 UI 실행 검증은 수행하지 않았다.

## 14. 콘텐츠 브라우저 열기·타입별 표시와 리소스 선택

### 현재 기반과 부족한 연결

- `ContentBrowserGridItem.cpp`의 `HandleItemDoubleClick()`은 폴더 이동, 씬 JSON 로드와 지원하는 내부 리소스 에디터 열기를 처리한다.
  내부 에디터가 지원하지 않는 파일을 외부 에디터로 여는 공통 경로와 명시적인 외부 열기 메뉴는 확인되지 않았다.
  현재 `탐색기에서 표시`는 파일 편집과 다른 동작이다.
- `AssetCache`는 이미지 디코딩과 일부 원본 모델의 Windows Shell 미리보기 요청을 비동기로 처리한다.
  이미지의 `Width`·`Height`를 그대로 GPU 텍스처에 사용하며, 축소·캐시 용량·프레임별 업로드 예산은 확인되지 않았다.
  모델 미리보기는 시스템의 해당 형식 지원 여부에 영향을 받는다.
- `ContentBrowserPanel`의 필터와 그리드 아이콘은 주로 확장자 분기다.
  컨텍스트 메뉴에는 `AssetHeader.ResourceType` 조회와 JSON↔바이너리 변환이 있지만, 공통 타입별 미리보기·분류로 연결되지는 않았다.
- `ResourcePicker.h`의 `DrawInspectorResourcePicker()`는 로드된 리소스의 스냅샷을 순회해 호환 타입을 텍스트로 보여준다.
  컴포넌트 리소스 편집에 사용되지만 검색·썸네일과 아직 로드하지 않은 프로젝트 에셋의 선택 연결은 없다.
- 브라우저 검색은 Enter 입력 시 루트 아래를 동기 재귀 탐색한다.
  `DrawGrid()`는 검색 결과가 비어 있으면 현재 폴더 목록을 보여주므로, 검색 결과 없음과 폴더 탐색을 명확히 구분할 필요가 있다.

위 내용은 2026-10-24의 관련 소스 정적 확인 결과다. 아래 항목은 구현 계획이며 성능·UI 동작의 검증 결과가 아니다.

### A. 더블클릭과 컨텍스트 메뉴의 열기 동작

- 더블클릭과 컨텍스트 메뉴의 `열기`는 같은 기본 동작 판정을 사용한다.
  폴더는 이동하고, 지원하는 엔진 에셋은 내부 에디터로 열며, 소스·문서·외부 제작 파일은 연결된 외부 에디터로 연다.
- 파일 컨텍스트 메뉴에 `외부 에디터로 열기`를 별도로 제공한다. 내부 에디터 지원 파일도 필요할 때 명시적으로 외부 열기를 선택할 수 있다.
  OS 기본 연결을 우선 사용하고, 특정 프로그램 지정이 필요하면 실행 파일·인자 설정의 저장 위치를 정한다.
- 외부 도구가 필요한 원본 파일과 엔진이 생성한 에셋을 구분한다. 원본 연결이 있으면 `원본을 외부 에디터로 열기`를 제공하고 실제 대상 경로를 보여준다.
  바이너리 에셋을 텍스트 편집기에 자동으로 보내거나, 원본 연결 없이 같은 이름의 파일을 임의로 추정하지 않는다.
- 존재하지 않는 경로·연결 프로그램 없음·실행 실패를 알리고, 경로의 한글·공백·따옴표를 처리한다.
  플랫폼의 파일 열기 API를 사용하고 경로를 셸 명령 문자열에 단순 연결하지 않는다.
- 씬·프리팹 교체와 내부 에디터 대상 변경은 11절 A의 미저장 보호 흐름을 거친다.
  외부에서 저장된 결과는 기존 변경 감지·재임포트·핫 리로드 정책에 따라 갱신한다.
- 기본 열기 정책과 명시적 외부 열기를 구분하되, 타입마다 같은 로직을 더블클릭·메뉴에 복제하지 않는다.

### B. 컴포넌트 리소스 핸들의 검색·썸네일 선택

- Inspector의 현재 리소스 핸들에 작은 썸네일 또는 타입 아이콘, 이름과 상태를 표시한다.
  미선택·누락된 참조·로딩 중·미리보기 미지원·실패를 구분하며, 이미지가 없다는 이유로 유효한 핸들을 해제하지 않는다.
- 선택 팝업은 검색 입력과 썸네일 목록 또는 그리드를 함께 제공한다.
  이름·프로젝트 상대 경로로 검색하고, 같은 이름의 에셋은 상대 경로로 구분한다. 검색 결과 없음도 별도 표시한다.
- `ResourceHandle<T>`에 할당 가능한 타입으로 후보를 제한한다. 파일의 타입 판정과 실제 로드·할당 시의 호환성 검사를 함께 유지한다.
  - **핸들 타입별 호환 확장자 필터링**: `DrawInspectorResourcePicker<T>`에서 템플릿 인자 `T`(`Texture`, `Material`, `Model`, `Audio` 등)에 일치하는 확장자 파일만 디스크 목록에 노출하여 무관한 에셋 노출을 차단한다.
  - **팝업 진입 시 1회 스캔 및 정적 캐싱**: 팝업이 열려 있는 동안 매 프레임 `recursive_directory_iterator`로 디스크 전체를 동기 순회하여 발생하는 치명적인 프레임 드랍을 방지한다. 팝업이 열리는 첫 프레임에만 1회 스캔하여 캐시 리스트를 구성하고, 팝업이 닫힐 때 해제하거나 색인 기반으로 조회한다.
  - 기존 드래그 앤 드롭과 연결 해제를 유지하고, 읽기 전용·다중 선택의 혼합값도 기존 Inspector 편집 경로와 일치시킨다.
- 초기에는 로드된 리소스를 대상으로 검색·썸네일을 연결하고, 다음 단계에서 프로젝트 에셋의 메타데이터 색인으로 범위를 넓힌다.
  로드된 목록과 프로젝트 전체 목록의 지원 범위를 표시하며, 후보를 보여주기 위해 모든 리소스를 실제로 로드하지 않는다.
- 선택을 확정한 후보만 필요한 로드를 수행한다. 비동기 로드 중 실패·취소·대상 컴포넌트 삭제·씬 교체가 발생해도 기존 값을 보존한다.
- 변경은 기존 리플렉션 속성 편집·Undo/Redo 경로에 연결한다. 팝업 표시나 미리보기 생성은 컴포넌트 변경 명령을 만들지 않는다.
- 브라우저와 선택 팝업은 타입 정보·썸네일 캐시를 재사용한다. 팝업별 검색어·선택 상태는 속성의 안정된 ImGui ID로 구분한다.

### C. 데이터 타입별 분류와 바이너리 에셋 미리보기

- 저장 형식과 콘텐츠 타입을 구분한다. JSON·BEVE·전용 바이너리 확장자라는 이유만으로 모두 일반 데이터 아이콘으로 표시하지 않는다.
  지원하는 엔진 에셋은 `AssetHeader` 등 기존 메타데이터로 실제 타입을 판정하고, 일반 파일은 알려진 확장자로 분류한다.
- 목록 열기·필터·검색·아이콘·툴팁·내부 에디터 선택이 같은 타입 판정 결과를 사용하도록 작은 공통 경로부터 정리한다.
  기존 `PeekResourceType()`처럼 Archive 문서를 읽는 처리를 모든 항목의 매 프레임 그리기에 넣지 않는다.
- 리소스 헤더의 MagicNumber·타입·버전과 파일 읽기 실패를 검증한다.
  타입을 알 수 없음·손상됨·지원하지 않는 버전을 구분하며, 분류를 위해 원본을 변환하거나 덮어쓰지 않는다.
- 다음 타입은 실제 내용을 대표하는 정적 썸네일을 우선 제공한다.
  - 텍스처·스프라이트: 이미지 또는 지정 영역. 원본 이미지와 엔진 바이너리 모두 지원 범위를 명시한다.
  - 메시·모델: 경계에 맞춘 고정 카메라의 정적 렌더. Shell 미리보기 제공 여부에만 의존하지 않는다.
  - 머티리얼·인스턴스: 공통 미리보기 메시를 렌더하며 인스턴스의 실제 파라미터를 반영한다.
  - 씬·프리팹: 저장 시점 또는 명시적 갱신으로 만든 대표 이미지. 썸네일 요청만으로 메인 씬을 교체하지 않는다.
  - 파티클: 고정 시드·제한된 예열 시간의 대표 프레임. 전 항목을 계속 시뮬레이션하지 않는다.
  - 스플라인: 제어점·곡선과 경계를 작은 정적 이미지로 표시한다.
- 파티클·스플라인을 타입 필터·별도 아이콘·색상·타입 배지와 생성·열기 메뉴에 추가한다.
  현재 `EResourceType`에는 두 항목이 없으므로 데이터·저장 정책을 먼저 정한다.
  독립 에셋이면 타입 등록을 추가하고, 씬 전용 데이터면 관련 컴포넌트 편집과 씬 미리보기에 연결한다.
  저장된 enum 값의 의미가 바뀌지 않게 하며 확장자·파일 포맷 이름은 구현 시 확정한다.
- 시각적 표현이 없거나 미리보기가 준비되지 않은 셰이더·스크립트·오디오·스켈레톤·일반 데이터는 타입 아이콘·이름·배지로 구분한다.
  파형·골격·클립 포즈 등 추가 표현은 실제 데이터와 비용이 확인될 때 확장한다. 미지원 상태와 생성 실패를 동일하게 처리하지 않는다.
- 바이너리도 해당 타입의 지원하는 읽기 경로로 미리보기를 만든다. JSON으로 변환하는 작업을 표시의 전제 조건으로 삼지 않는다.
  썸네일·색인은 재생성 가능한 Editor 캐시로 관리하고, 실행용 에셋이나 컴포넌트의 영속 핸들에 GPU 미리보기 자원을 저장하지 않는다.

### D. 검색·썸네일의 성능과 자원 수명 기준

- 화면에 보이는 행·타일부터 미리보기를 요청하고 행 단위 클리핑을 적용한다. 필요하면 작은 선행 로딩 범위를 둔다.
  폴더 전체나 검색 결과 전체에 한 번에 디코딩·렌더 작업을 예약하지 않는다.
- 브라우저와 선택 팝업이 같은 요청을 공유하도록 중복을 억제하고, 대기열·동시 작업 수·디코딩 메모리에 상한을 둔다.
  빠른 스크롤·검색어 변경·팝업 종료 시 요청의 우선순위를 조정하거나 불필요한 대기 작업을 취소한다.
- 썸네일 해상도에 맞춰 축소하고, 과도한 이미지 크기와 임시 디코딩 메모리를 제한한다.
  원본 해상도 텍스처를 전 항목에 보관하지 않는다. 사전 생성·축소본 활용과 제한된 작업 수를 함께 검토한다.
- CPU 파일 읽기·디코딩과 GPU 생성·업로드의 실행 스레드를 구분한다.
  프레임별 GPU 업로드 바이트·작업 수와 미리보기 렌더 시간에 예산을 두고, 완료된 모든 작업을 한 프레임에 처리하지 않는다.
- CPU·GPU 캐시의 항목 수·바이트 상한과 축출 정책을 정한다. 사용 중인 ImGui 텍스처 ID와 GPU 작업의 완료 시점을 고려해 안전하게 해제한다.
- 파일 변경·재임포트·이동·삭제와 의존 리소스 변경 시 관련 캐시를 무효화한다.
  작업 세대 또는 버전을 확인해 오래된 비동기 완료 결과가 새 썸네일을 덮어쓰지 않게 한다.
  파일 감시 콜백은 변경 정보를 전달하고, 캐시 수정·GPU 해제는 정한 소유 스레드에서 수행한다.
  종료 시에는 진행 중 작업·콜백을 정리한 뒤 캐시 소유자를 파괴한다.
- 미지원·실패 결과도 캐시하되 파일 변경이나 명시적 재시도로 복구할 수 있게 한다. 매 프레임 같은 실패 요청을 다시 제출하지 않는다.
- 검색은 입력 변경을 모아 처리하고, 프로젝트 목록·타입 정보를 캐시하거나 색인한다.
  작은 프로젝트는 기존 폴더 캐시부터 활용하고, 대규모 탐색이 필요하면 비동기 갱신·취소·오래된 결과 폐기를 추가한다.
  `GetDebugSnapshot()` 전체 복사·후보 정렬·파일 파싱을 변경 없는 매 프레임 반복하지 않는다.
- 파티클 등 움직이는 미리보기는 선택·호버한 제한된 항목에서 명시적으로 제공한다.
  비활성 패널·숨겨진 항목·PIE 부하 상황의 갱신 빈도를 제한하고, 기본 브라우저 표시는 정적 캐시를 사용한다.
- 예산 수치는 구현 시작 시 기준 장비·에셋 수·파일 크기별 측정으로 확정한다.
  콜드·웜 캐시의 UI 프레임 시간(p95·p99), 검색 응답 시간, 대기열 크기, CPU·GPU 메모리와 업로드량을 비교한다.
  비동기로 동작하거나 육안으로 부드럽다는 이유만으로 성능 완료로 판단하지 않는다.

#### 콘텐츠 브라우저에서 썸네일 표시 중 지속되는 프레임 저하

- 2026-11-09에는 썸네일이 많은 폴더를 열어둔 동안에도 프레임 차이가 지속됐다. 이후 `Assets/kenney_desert-shooter-pack_1.0/PNG/Tiles/Tilemap`의 공유 시트 스프라이트 234개로 Release Editor에서 경로 조회와 캐시 핸들 재사용을 교차 비교했다. 이 폴더의 그리드 CPU p50은 0.498–0.502 ms에서 0.314–0.318 ms로 줄었다.
- `ContentBrowserPanel`은 표시할 타일에 대해 `AssetCache`에서 텍스처와 스프라이트 핸들을 함께 받는다. `ContentBrowserGridItem::DrawThumbnail()`은 핸들로 현재 스프라이트의 UV를 읽고, 핸들로 찾지 못했을 때 파일 경로와 리소스 키를 조회한다. 교차 비교에 사용한 임시 계측 모드와 로그는 제거했다.
- 사용자는 계측 제거 전 일반 실행에서 스프라이트 영역 표시와 수정 후 썸네일 갱신을 확인했다. 제거 후 Release 빌드·실행과 텍스처 교체, 파일 추가·삭제, 검색·범위 선택의 회귀 확인은 별도로 기록한다. [구현 로그](ImplementationLog.md#2026-11-11-콘텐츠-브라우저-스프라이트-썸네일-조회-재사용)
- 남은 프레임 비용을 조사할 때는 씬·카메라·패널 크기·타일 크기·VSync·FPS 제한을 맞추고, 썸네일이 채워진 뒤 스크롤 없이 비교한다. 보이는 타일 수, 캐시 미스·업로드 건수, `DrawGrid()`와 ImGui 렌더 제출 시간을 구분한다. 약 60 FPS에 고정되면 VSync 및 FPS 제한을 해제한 비교를 별도로 기록한다.

#### 콘텐츠 브라우저 썸네일 드로우콜 최적화

- `ContentBrowserGridItem::DrawThumbnail()`은 배경·이미지·액센트·잠금 배지를 ImGui 그리기 목록에 추가한다. 텍스처를 공유해도 배경·글꼴 명령이 사이에 들어가거나 클립 영역이 다르면 이미지 명령이 나뉠 수 있다. `Tilemap`의 스프라이트 234개는 이미 같은 시트를 참조하므로 새 아틀라스 생성 전의 비교 기준으로 사용한다. 씬·PIE의 인스턴싱은 [스프라이트 계획 Phase 5](SpriteAnd2DSystemPlan.md#phase-5-스프라이트-아틀라스-및-드로우콜-배칭)를 따른다.
- 썸네일 캐시가 채워진 같은 화면에서 `DrawGrid()` CPU 시간, 보이는 타일 수, ImGui 명령 수·텍스처 전환·클립 영역, ImGui 렌더 비용을 비교한다. ImGui DX12 백엔드는 자체 명령을 기록하므로 엔진 `RHIFrameMetrics`의 드로우 수와 별도로 확인한다. 타입 아이콘 대조군과 위 절의 재현 조건을 사용한다.
- 명령 분리 비용이 크면 타일의 입력 처리를 유지하면서 배경 → 이미지 → 배지·텍스트 순서로 레이어를 나눈다. 현재 그리드의 행·열 클리핑과 겹침 순서, 툴팁과 선택 강조를 보존하면서 동일 텍스처와 호환 클립 영역의 이미지 명령을 인접하게 배치한다. 버튼과 배지의 크기·정렬은 [에디터 UI 지침 18절](EngineEditorClientGuidelines.md#5-글꼴과-ui-배율에-맞춘-버튼배지-크기)을 따른다.
- 서로 다른 썸네일 텍스처 전환이 주요 비용일 때 `AssetCache`의 생성 결과를 에디터 전용 아틀라스 페이지에 모으는 안을 검토한다. 기존 캐시 요청·무효화·LRU를 사용하고, 항목은 페이지와 UV를 함께 가리킨다. 패딩, 페이지·업로드 예산과 슬롯 재사용 시 GPU 완료 시점을 다룬다. 준비 중에는 기존 타입 아이콘을 표시한다. 공유 시트 폴더와 서로 다른 썸네일이 많은 폴더에서 각각 전후 드로우 수와 프레임 시간을 기록한다.

### E. 콘텐츠 브라우저 검색 범위 선택

- 검색 범위를 `전체 리소스 폴더`와 `현재 선택한 폴더` 중에서 선택할 수 있게 한다.
  전체 검색은 프로젝트의 리소스 루트(`m_RootPath`), 현재 폴더 검색은 브라우저에서 열어 둔 폴더(`m_CurrentDirectory`)를 기준으로 하며 두 범위 모두 하위 폴더를 포함한다.
  현재 폴더는 검색창의 키보드 포커스나 검색 결과에서 선택한 파일이 아니라 폴더 트리·주소 표시줄의 탐색 위치를 의미한다.
- 검색창 옆에 선택한 범위와 기준 폴더를 표시한다. 결과에는 기준 폴더에서의 상대 경로를 함께 보여 같은 이름의 에셋을 구분한다.
  범위 선택·기준 폴더·검색 상태 문구는 기존 로캘 경로를 사용한다.
- 검색 범위를 바꾸면 입력한 검색어와 타입 필터를 유지한 채 새 범위에서 다시 검색한다.
  현재 폴더 범위에서는 탐색 폴더가 바뀔 때 같은 검색어로 다시 검색하고, 전체 범위에서는 폴더 이동만으로 검색 기준을 바꾸지 않는다.
- 검색 요청에는 범위·기준 폴더·검색어·필터의 스냅샷을 사용한다. 비동기 처리에서는 조건이 바뀐 이전 요청의 결과를 취소하거나 폐기해 새 결과를 덮어쓰지 않게 한다.
  검색창 포커스 이동이나 패널 재그리기만으로 전체 재검색을 반복하지 않으며, 작업량 제한은 D절을 따른다.
- 빈 검색어는 일반 폴더 탐색으로 돌아가고, 검색 결과가 없으면 선택한 범위의 결과 없음을 표시한다.
  결과가 없다는 이유로 다른 범위나 현재 폴더 전체 목록으로 자동 전환하지 않는다.

### F. 콘텐츠 브라우저 그리드 다중 선택

- 썸네일과 이름을 하나의 타일로 선택한다. 클릭은 단일 선택, Ctrl+클릭은 선택 상태 전환, Shift+클릭은 현재 그리드에 표시되는 순서에서 기준 타일부터 클릭 타일까지 선택한다.
- 빈 공간에서 왼쪽 버튼을 드래그하면 박스와 겹치는 타일을 선택한다. 빈 공간을 클릭하면 선택을 해제한다.
- 선택된 타일에서 우클릭하거나 드래그를 시작하면 현재 선택 전체를 대상으로 고정한다. 선택 밖 타일에서는 해당 항목 하나가 대상이다. 다중 우클릭의 경로 복사는 한 줄에 하나씩 복사한다.
- 씬 뷰포트는 다중 드롭의 모델과 프리팹을 배치하고 성공한 항목을 한 번의 Undo로 기록한다. 일부 항목을 배치하지 못하면 배치한 개수와 전체 개수를 알린다. 계층 패널과 단일 리소스 입력칸에는 단일 에셋을 드롭한다.
- 패널이 파일 경로별 선택 ID를 관리한다. 검색·필터 또는 파일 목록 변경 후에도 남아 있는 경로는 선택을 유지하고, 목록에서 빠진 경로는 선택에서 제거한다. Shift 기준 행은 클리퍼에 포함한다.
- 실제 에디터에서 스크롤로 기준 항목을 화면 밖으로 보낸 뒤의 범위 선택, 박스 축소와 스크롤, 폴더 이동, 타일에서 시작하는 드롭, 더블클릭 열기, 인라인 이름 변경을 확인한다.

## 15. 파티클·스플라인 제작 기능

Engine의 파티클·스플라인·레이캐스트·트레일·애니메이션·상태 그래프·스크립트 실행 계획은
[EngineDevelopmentPlan.md](EngineDevelopmentPlan.md)에서 관리한다. 이 절은 해당 기반을 사용하는 편집·미리보기 목표와 연결한다.

2026-10-24의 `Engine/Source`·`Editor/Source` 파일 및 심볼 검색에서는 파티클·스플라인의 전용 데이터·실행 시스템·편집기를 확인하지 못했다.
스프라이트 빌보드 관련 주석은 파티클 시스템의 구현 근거로 삼지 않는다. 별도 이름이나 외부 모듈의 구현 여부는 재개 시 다시 확인한다.
두 기능은 모든 게임에 필수인 기반은 아니지만, 이펙트와 경로 제작에 필요한 목표로 추가한다. 썸네일 표시와 실제 기능 구현의 완료를 구분한다.

### 파티클

- 처음에는 단일 이미터의 생성률·최대 개수·수명·초기 위치·속도·크기·색·텍스처·루프와 난수 시드를 지원한다.
  CPU 시뮬레이션과 기존 렌더링 경로부터 검토하고, GPU 시뮬레이션은 측정된 요구가 있을 때 별도 확장한다.
- 재사용하는 효과 설정과 실행별 파티클 상태를 분리한다. Editor 미리보기와 PIE·Client가 같은 실행 규칙을 사용한다.
- Inspector 또는 전용 편집기에서 재생·정지·초기화·제한된 예열·저장과 Undo/Redo를 제공한다.
  미리보기는 메인 씬을 변경하지 않고, 저장 대상에 실행 중 파티클 목록과 GPU 버퍼를 포함하지 않는다.
- 최대 파티클·이미터·업데이트 비용을 제한하고, 풀 재사용·경계·컬링·투명 오버드로를 측정한다.
  화면 밖에서 멈추거나 저빈도로 갱신할 때 재등장 결과와 시간 진행 정책을 명시한다.
- 완료 기준: 저장 후 재실행·PIE 반복·Client에서 같은 설정을 해석하고, 초기화·종료 시 실행 상태가 남지 않는다.
  개수 제한과 프레임 비용을 검증한 뒤 14절의 정적 썸네일·타입 필터에 연결한다.

### 스플라인

- 먼저 실제 용도를 경로·카메라 이동·형상 생성 중 하나로 정하고, 지원할 곡선 표현과 열린 경로·닫힌 경로의 의미를 확정한다.
  제어점·접선·좌표계와 위치·접선 평가부터 구현한다. 거리 기반 이동이 필요하면 호 길이 근사와 정확도·비용을 함께 정한다.
- Inspector의 제어점 목록과 뷰포트 기즈모를 연결하고, 추가·삭제·이동·Undo/Redo·저장·복원을 제공한다.
  데이터가 엔티티 로컬 좌표인지 월드 좌표인지 명시하고 부모 Transform 변경 시의 결과를 확인한다.
- 곡선·거리 표·표시용 선분은 제어점이나 관련 Transform이 변경됐을 때 필요한 부분만 갱신한다.
  분할 수·근사 오차·캐시 메모리에 한도를 두고, 매 프레임 전체 경로를 재샘플링하지 않는다.
- 제어점 없음·한 점·중복점·길이 0·끝점·루프 이음부의 결과를 정한다.
  완료 기준: 저장·복원과 편집·실행 평가가 일치하고, 관련 변경 시 캐시·기즈모·정적 썸네일이 함께 갱신된다.
- 1차 구현에서 Inspector와 뷰포트의 제어점 선택을 연결했다. 제어점 위치·접선 축 롤은 기즈모로 조작할 수 있고, 드래그 한 번을 편집 이력 한 건으로 기록한다. 열린 경로의 새 점은 끝 구간을 연장하고, 닫힌 경로에서는 이음 구간의 중간에 점을 추가한다.
- 원본 메시와 머티리얼은 `StaticMeshRendererComponent`에서 선택한다. `SplineMeshComponent`는 반복 배치와 곡선 변형에 해당하는 설정만 표시하며, 마지막 생성 상태와 생성된 조각 수를 보여 준다. 변형의 진행축은 원본 메시 로컬 Z다.
- 후속 범위는 전방 축 선택, 생성 비용 표시, 독립 에셋과 정적 썸네일이다. 구현과 에디터 검증 범위는 [Engine 계획 5절](EngineDevelopmentPlan.md#5-스플라인-데이터평가경로-활용)에 기록한다.

## 16. 빠진 기능을 판단하는 우선순위

모든 게임엔진에 파티클·스플라인·내비게이션 등 같은 기능이 반드시 필요한 것은 아니다.
BamEngine의 우선 기준은 작은 게임의 제작·저장·실행·배포 흐름을 안전하게 끝낼 수 있는가다.
다음은 이번에 확인한 연결 부족과 기존 계획의 우선순위이며, 엔진 전체 기능 감사 결과는 아니다.

1. **편집 데이터 보호:** 확인한 씬 생성·열기·닫기 경로에는 공통 미저장 확인 흐름이 없다.
   11절 A의 변경 추적·저장 실패 보존부터 연결하고, 자동 백업·복구를 다음 단계로 둔다.
2. **에셋 참조와 제작 흐름:** 기존 로더·핸들·임포트를 활용하면서, 11절 B·C와 14절의 참조 색인·누락 검사·재임포트·타입별 탐색을 보완한다.
   특히 현재 브라우저의 직접 삭제·이름 변경은 참조 영향 조회와 함께 검토한다.
3. **실제 배포:** Client 시작 씬은 현재 코드에서 고정 경로를 사용하며, 프로젝트 설정 연결과 저장소 밖 실행은 별도 검증이 필요하다.
   기존 결정대로 [BuildAndPackagingPlan.md](BuildAndPackagingPlan.md)의 작업 단계에서 진행한다.
4. **게임 제작 기반의 연결:** 프리팹 제작 UI·안정된 인스턴스 연결, 게임 입력 액션과 CPU·GPU 시간 측정을 기존 계획에 따라 보완한다.
   기반 데이터나 호출 횟수가 존재한다는 이유만으로 편집·실행·측정 흐름의 완료로 판단하지 않는다.
5. **콘텐츠 표현:** 파티클·스플라인과 애니메이션 재생·편집은 대상 게임의 요구에 맞춰 진행한다.
   현재 Animation 리소스의 트랙 데이터만으로 스키닝·보간·블렌딩·타임라인이 구현됐다고 판단하지 않는다.
   내비게이션·네트워크 등은 이번 문서에서 미구현으로 확정하지 않으며, 실제 필요와 관련 코드 검토 후 별도 계획을 정한다.

이번 변경은 이 개발 플랜의 목표·작업 순서·검증 기준만 추가한 것이다. C++ 코드·로캘 데이터·빌드 산출물은 변경하지 않았고 빌드·테스트·성능 측정은 실행하지 않았다.

## 17. 엔티티 다중 복사·붙여넣기

- 추가일: 2026-10-31 (2026-10-31 구현 완료).

### 현재 기반과 재사용 범위

- `SelectionManager::GetSelectedEntities()`와 Hierarchy의 다중 선택, `SceneEditHistory`·`SceneEditSnapshot`의 생성·삭제 이력을 재사용한다.
- `EntityClipboard`(`Editor/Source/Clipboard/`): `archive::JsonArchive` 메모리 직렬화 기반으로 선택된 엔티티 서브트리를 스냅샷으로 보관한다.
- 원본 엔티티가 파괴되거나 편집되어도 클립보드 데이터의 독립성이 보장된다.

### 1단계: 같은 씬에서 다중 엔티티 복사·붙여넣기 (구현 완료)

- **조상 필터링 (중복 방지)**: Hierarchy에서 부모와 자식이 동시에 선택된 경우, 조상 노드만 복사 루트로 선별하여 자식이 중복 복제되지 않도록 필터링한다.
- **원래 계층 및 형제 순서 보존**: 복사된 서브트리 내부의 부모-자식 관계와 형제 순서가 완벽히 보존된다.
- **새 ID 자동 발급**: 붙여넣기 시 `Scene::CreateEntities`를 통해 고유한 영구 엔티티 ID를 새로 발급하여 ID 충돌을 원천 차단한다.
- **단일 원자적 Undo/Redo**: 여러 개의 엔티티가 한 번에 붙여넣어지더라도 `History.Command.PasteEntities` 단일 스냅샷으로 묶여 `Ctrl+Z` 한 번으로 일괄 제거되고 `Ctrl+Y`로 일괄 복원된다.
- **붙여넣기 후 자동 선택**: 생성된 신규 루트 엔티티들이 자동으로 선택되어 붙여넣기 직후 바로 기즈모 조작이 가능하다.
- **단축키 및 메뉴 연동**:
  - `Ctrl+C`: 선택된 엔티티 복사 (`EditorCommon.Copy`)
  - `Ctrl+V`: 동일 부모 또는 씬 루트에 붙여넣기 (`EditorCommon.Paste`)
  - `Ctrl+Shift+V`: 선택한 엔티티의 자식으로 붙여넣기 (`Edit.PasteAsChild`)
- **계층 패널 다중 삭제 지원**: `Delete` 키 및 컨텍스트 메뉴를 통한 `EntityHierarchyAction::DeleteEntities` 다중 일괄 삭제 기능도 함께 완성되었다.

### 후속 범위와 완료 검증

다른 씬·프리팹 편집 세션으로 붙여넣기는 문서 간 리소스 해석, 외부 엔티티 참조와 클립보드 수명 정책을 마련한 뒤 확장한다.
잘라내기·즉시 복제는 첫 단계의 필수 범위에 포함하지 않는다.

- [x] 단일·다중 루트, 부모·자식 동시 선택에서 중복 없이 계층·형제 순서·컴포넌트·Transform이 보존된다.
- [x] 반복 붙여넣기에 ID 충돌이 없고 새 엔티티가 올바르게 생성된다.
- [x] 복사 후 원본 수정·삭제 후에도 클립보드 메모리 버퍼를 통해 안전하게 붙여넣어진다.
- [x] 붙여넣기 한 번을 한 번의 Undo로 제거하고 Redo로 복원하며, 이력 스택이 일치한다.
- [x] 계층 패널의 키보드 `Delete` 및 다중 삭제가 부모-자식 충돌 없이 안전하게 동작한다.

- 목표: 자주 쓰는 작업을 찾기 쉽게 묶고 캔버스 공간을 확보한다. Logic 실행 미리보기·PIE 관찰·Shader 제작의 조작 대상을 명확히 구분한다.

### 현재 코드에서 확인한 문제

- `GraphPanel::Draw()`는 `DrawToolbar()`·`DrawFileToolbar()`·`DrawDebugToolbar()`·`DrawShaderToolbar()`·`DrawExecutionToolbar()`를 순서대로 호출한다.
  개별 함수가 줄 시작·`SameLine()` 배치를 결정하므로 전체 상단의 행 구성과 간격을 한곳에서 파악하기 어렵다.
- 공통 행에는 도메인·노드 추가·검사·화면 맞춤·삭제·와이어 모드가 함께 있다. 파일 행에는 저장·다른 이름으로 저장·열기·전체 경로가 있고,
  Logic의 `DrawDebugToolbar()`는 `SameLine()`으로 이 행 뒤에 디버그 엔티티 선택기를 붙인다. 긴 경로·이름·번역에 따른 폭 부족에 대응하는 분기는 확인되지 않았다.
- Logic의 패널 내부 실행 미리보기와 씬 엔티티의 PIE 실행 관찰이 별도 조작 묶음이라는 표시가 부족하다.
  Shader 행도 HLSL 생성·DXIL/SPIR-V 검사·미리보기·머티리얼 검사·런타임 머티리얼 생성이 같은 수준의 버튼으로 나열된다.
- 와이어 모드 버튼·툴팁과 디버그 대상 안내에는 고정 영어 문구가 남아 있다. 이번 수정 범위에서 로캘 키로 정리한다.

위 내용은 관련 소스의 정적 확인이다. 실제 화면의 겹침·잘림 여부와 사용 가능한 최소 폭은 UI에서 별도 확인한다.

### 권장 배치와 기능 분류

- 상단은 **공통 도구 행 + 도메인별 도구 행**을 기본으로 한다. 각 행의 시작·그룹 간격·남은 폭은 상위 배치 코드가 결정한다.
  자식 그리기 함수가 앞선 행의 마지막 항목에 임의로 이어 붙이지 않도록 호출 계약을 정리한다.
- 공통 행에는 도메인 선택, 열기·저장, 노드 추가·검사·화면 맞춤을 우선 노출하고 문서·편집·보기 메뉴로 기능을 묶는다.
  다른 이름으로 저장은 문서 메뉴, 선택 삭제는 편집 메뉴와 기존 컨텍스트 메뉴, 와이어 스타일은 보기 메뉴의 명시적인 선택 목록으로 옮긴다.
  와이어 스타일은 반복 클릭으로 순환하기보다 현재 선택과 세 가지 후보를 함께 알 수 있게 한다.
- Logic의 도메인 행에서는 `실행 미리보기`와 `PIE 관찰`을 구획과 라벨로 구분한다.
  미리보기는 진입점·실행/재개·일시정지·한 단계·중지를 묶고, 인스턴스 초기화와 실행 예산·간격 등 상세 설정은 해당 메뉴 또는 기존 오른쪽 추적 영역에 둔다.
  PIE 관찰은 대상 엔티티와 관찰 가능 상태를 표시한다. 미리보기 버튼이 게임 전체를 제어하는 것처럼 보이지 않게 한다.
- Shader의 도메인 행은 컴파일·미리보기를 우선 노출한다. HLSL 생성과 DXIL/SPIR-V 대상별 검사는 빌드 메뉴로 묶고,
  머티리얼 검사·런타임 머티리얼 생성은 별도 머티리얼 메뉴로 묶는다. 기존 동작과 지원 범위를 유지하며 서로 다른 검사를 하나의 성공 상태로 합치지 않는다.
- 전체 파일 경로·상세 오류·컴파일 안내는 버튼 사이에서 빼고 기존 하단 상태 영역과 오른쪽 진단·빌드 상세 영역을 사용한다.
  파일은 짧은 이름과 전체 경로 툴팁으로 식별하고, 같은 이름의 파일도 경로를 확인할 수 있게 한다. 미저장 표시는 실제 변경 추적에 연결된 경우에만 표시한다.
- 패널 폭이 부족하면 우선순위가 낮은 작업을 `더 보기` 메뉴로 옮긴다. 무제한 자동 줄바꿈이나 가로 스크롤을 기본 해결책으로 삼지 않는다.
  극도로 좁은 폭에서는 도메인별 도구도 메뉴로 축약하되 현재 도메인·실행 상태와 중지 기능에 접근할 수 있어야 한다.
  배치 기준은 현재 글꼴·UI 배율·번역된 항목의 실제 크기를 사용하고 고정 픽셀 간격에 의존하지 않는다.

1. **상단 Play Bar (`##PlayBarRow`, `ToolBar::DrawPlayControls`)**:

### 20.1 현재 코드에서 확인한 문제

1. **단일 확장자(`.extension()`) 의존으로 인한 시각 분류 누락**:
   - `ContentBrowserGridItem::Thumbnail`(`ContentBrowserGridItem.cpp:214-264`)은 `path.extension()`만 검사하므로, `Wood.bammat.json`, `Cube.bammesh.json`, `NewScene.json`, `Hero.bamsprite.json` 등이 모두 `.json` 분기(`ICON_FA_FILE_LINES`, 회색 배경)로 빠져 일반 텍스트/데이터 파일과 똑같이 보인다.
   - 심지어 바이너리 리소스인 `.bammesh`, `.bammodel`, `.bammat`, `.bammatinst`, `.bamsprite`, `.bamanim`, `.bamskel`, `.bamtex`도 `Thumbnail()` 분기에 등록되어 있지 않아 기본 파일 아이콘(`ICON_FA_FILE`, 무채색)으로 표시된다.
2. **네임박스(`DrawNameBox`)의 이름 잘림 및 무의미한 `"JSON"` 타입 표시**:
   - `DrawNameBox`(`ContentBrowserGridItem.cpp:552-625`)에서 파일 이름을 `path.stem()`으로만 추출하기 때문에 `Cube.bammesh.json`의 이름이 `"Cube.bammesh"`로 지저분하게 남고, 우측 하단 타입 라벨(`typeStr`)에는 `"MESH"`가 아니라 `"JSON"`이 찍힌다.
3. **목적별 JSON 파일과 일반 `.json`의 혼용**:
   - `Scene` 파일(`NewScene2.json`), 비주얼 스크립팅 `Graph` 파일, `PostProcess` 프리셋 등이 고유 접미사 없이 `.json` 확장자만 사용하고 있다.
   - 이 때문에 `IsSceneFile()`이나 `PeekResourceType()`처럼 파일을 직접 열어 JSON 파싱을 시도해야 하거나, 인스펙터의 `ResourcePicker<Material>` 팝업이 `.json`을 허용하면서 씬·프리팹·메시 JSON까지 머티리얼 후보 목록에 섞여 나오는 문제가 발생한다.
4. **콘텐츠 브라우저 상단 필터(`PassesFilter`) 누락**:
   - `ContentBrowserPanel.cpp:57-73`의 `PassesFilter()`에서 Material 필터가 `.mat`만 검사하여 정작 엔진 머티리얼(`.bammat`, `.bammat.json`, `.bammatinst.json`)은 필터링 시 전부 사라지며, Model 필터도 `.bammesh.json`과 `.bammodel.json`을 누락하고 있다.

### 20.2 목적별 JSON 파일의 복합 확장자(`*.bam<type>.json`) 표준화 규약

> **[핵심 원칙]**
> 엔진과 에디터에서 특정 도메인 목적(씬, 머티리얼, 메시, 프리팹, 그래프, 애니메이션, 프리셋 등)을 가지는 모든 JSON 직렬화 에셋은 일반 `.json`과 절대 혼용하지 않으며, 반드시 **`<이름>.bam<type>.json`** 복합 확장자를 사용한다.
> 바이너리(BEVE)로 구울(Bake) 때는 뒤의 `.json`만 제거한 **`<이름>.bam<type>`** 과 1:1로 대응시킨다.

### 20.4 머티리얼 및 메시 썸네일/시각 구분 보강

1. **머티리얼(`Material` / `MaterialInstance`) 시각 구분**:
   - 정적 썸네일 렌더가 아직 생성되지 않은 상태에서도 베이스 머티리얼(`ICON_FA_CIRCLE_HALF_STROKE`, 에메랄드 그린, `MAT` 배지)과 머티리얼 인스턴스(`ICON_FA_CLONE`, 민트 그린, `MAT INST` 배지)가 아이콘·배경색·배지로 즉시 구분된다.
   - 머티리얼 파일(`.bammat.json` / `.bammat`)에 대표 Albedo 텍스처가 바인딩되어 있거나 추후 오프스크린 구체(Sphere) 프리뷰가 캐싱되면 `AssetCache::GetThumbnail`을 통해 썸네일을 표시하되, 하단 2px 액센트 라인과 `MAT` / `MAT INST` 배지를 유지해 일반 텍스처와 혼동되지 않게 한다.
2. **메시(`.bammesh.json` / `.bammesh`) 및 모델(`.bammodel.json` / `.bammodel`) 시각 구분**:
   - 원본 모델(`.fbx`/`.obj`/`.gltf`, `ICON_FA_CUBE`), 엔진 모델(`.bammodel*`, `ICON_FA_CUBE` + `MODEL` 배지), 분리 추출된 개별 메시(`.bammesh*`, `ICON_FA_DRAW_POLYGON` + 인디고 배경 + `MESH` 배지)를 서로 다른 아이콘과 색상 톤으로 분리한다.

### 20.5 구현 순서

1. **1단계 (공통 에셋 분류 헬퍼 `ClassifyAssetVisualInfo` 구축)**:
   - 파일 경로(소문자 전체 파일명 `filename`)를 받아 복합 확장자 접미사(`.bamscene.json`, `.bammesh.json`, `.bammat.json` 등)를 우선 판별하고, `{ EAssetVisualCategory, icon, typeColor, badgeLabel, cleanStem }`을 반환하는 O(1) 분류 함수를 작성한다.
   - `DrawNameBox`에서 `cleanStem`(`Cube.bammesh.json` $\rightarrow$ `Cube`)과 `badgeLabel`(`MESH`)을 사용하도록 교체한다.
   - `Thumbnail`에서 `typeColor`, `icon`, 그리고 썸네일 하단 2px 액센트 라인을 그리도록 개선한다.
2. **2단계 (콘텐츠 브라우저 필터 `PassesFilter` 및 `ResourcePicker` 동기화)**:
   - `ContentBrowserPanel.cpp`의 `PassesFilter()`가 복합 확장자(`.bammat.json`, `.bammesh.json`, `.bamsprite.json` 등)를 각 카테고리에 맞게 필터링하도록 연결한다.
   - `ResourcePicker.h`의 `IsResourceExtensionCompatible<T>`가 단일 `ext` 대신 전체 파일명(복합 확장자 포함)을 받도록 확장하여, `Material` 선택 시 일반 `.json`이나 `.bamscene.json`이 섞여 나오지 않고 `.bammat` / `.bammat.json` / `.bammatinst` / `.bammatinst.json`만 정확히 표시되게 한다.
3. **3단계 (`Scene` 및 에디터 문서 저장/열기 확장자 `.bamscene.json` 전환)**:
   - 씬 저장 시 기본 확장자를 `.bamscene.json`으로 부여하고, `FileDialogs`의 씬 파일 필터(`FileDialog.SceneFiles`)를 `*.bamscene.json;*.json`으로 갱신하여 기존 `NewScene2.json` 등 레거시 씬 파일 열기도 100% 하위 호환한다.
   - 그래프(`.bamgraph.json`), 애니메이터(`.bamanimator.json`), 스프라이트 애니메이션(`.bamspriteanim.json`), 후처리 프리셋(`.bampostfx.json`)의 저장 기본 확장자와 열기 필터도 기존 파일 호환을 유지하며 순차 통일한다.

## 21. 에디터 공통 모달 대화상자(Modal Dialog) 표준 디자인 및 통일 계획

### 21.1 배경 및 목적
- 현재 에디터의 주요 확인/경고 팝업(`PrefabModeManager`의 미저장 종료 확인, `ImGuiManager`의 문서 저장 확인, `ContentBrowserPanel`의 삭제/충돌 확인 등)이 `ImGuiWindowFlags_AlwaysAutoResize`에만 의존하고 있어, 텍스트 글자 수에 따라 창 너비가 200px대로 찌그러지거나 들쭉날쭉해지는 시각적 결함이 있다.
- 화면 해상도 변경 시 도입된 표준 모달 규격(최소 너비 보장, 넉넉한 여백, 표준 버튼 규격 및 카운트다운 게이지)을 에디터 전체 모달 대화상자로 확장하여 일관되고 안정적인 UX를 확립한다.

### 21.2 표준 모달 디자인 가이드라인
1. **크기 및 형태 (Sizing & Constraints)**:
   - 최소 너비(Min Width): `ImGui::SetNextWindowSizeConstraints(ImVec2(420.0f, 0.0f), ImVec2(600.0f, FLT_MAX))`를 적용해 텍스트가 짧아도 최소 420px의 안정적인 종횡비를 유지한다.
   - 내부 패딩(Padding): `ImGui::PushStyleVar(ImGuiStyleVar_WindowPadding, ImVec2(18.0f, 16.0f))`를 적용해 테두리와 내용물 사이의 답답함을 해소한다.
2. **헤더 레이아웃 (Header)**:
   - 상단에 카테고리별 테마 아이콘(경고: `ICON_FA_TRIANGLE_EXCLAMATION`, 정보: `ICON_FA_CIRCLE_INFO`, 디스플레이: `ICON_FA_DESKTOP`, 저장: `ICON_FA_FLOPPY_DISK`)과 타이틀 텍스트를 배치하고 하단 구분선(`ImGui::Separator()`)으로 영역을 분리한다.
3. **버튼 규격 및 정렬 (Button Standards)**:
   - 버튼 크기: 최소 너비 `110.0f`, 높이 `28.0f`로 통일하여 마우스 클릭 미스를 방지한다.
   - 버튼 배치: 하단 우측 정렬(`ImGui::GetWindowContentRegionMax().x - totalBtnsWidth`)로 균형 배치한다.
   - 색상 구분:
     - 긍정/확정 액션(저장, 적용, 확인): 파란색(`ImVec4(0.18f, 0.45f, 0.75f, 1.0f)`)
     - 파괴적 액션(삭제, 변경사항 버리기): 붉은색(`ImVec4(0.75f, 0.20f, 0.20f, 1.0f)`)
     - 취소/닫기: 기본 버튼 색상
4. **동적 게이지/타임아웃 시각화**:
   - 15초 화면 확인 등 시한부 선택이 필요한 모달에는 `ImGui::ProgressBar`를 통해 남은 시간을 시각적으로 제공한다.

## 22. 콘솔 패널(Console Panel) 및 리소스 피커(Resource Picker) UI/UX 고도화

### 22.1 리소스 피커(Resource Picker) 개편
- **대형 썸네일 지원**: 기존 36px 썸네일을 기본 64px로 확대하고, 상단 툴바에 40~120px 크기 조절 슬라이더 및 검색어 실시간 필터링 제공.
- **2단 텍스트 및 우측 배지 정렬**: 파일명(노란색 강조)과 상대 경로(회색)를 2단으로 출력하고, 타입 배지(`MATERIAL`, `3D MODEL` 등)를 우측 독립 컬럼에 정렬하여 세로 텍스트 겹침 문제 원천 해결.
- **배지 패딩 및 높이 자동 계산**: 글리프 크기 기반 동적 패딩(`PadX 10px`, `PadY 5px`)을 적용하여 폰트 아이콘이 캡슐 테두리 밖으로 삐져나오는 현상 방지.
- **호버 프리뷰 툴팁**: 썸네일 호버 시 128x128 고해상도 프리뷰 툴팁 및 에셋 상세 경로 출력.
- **ImGui ID 충돌 해결**: 메모리에 이미 로드된 리소스와 디스크 파일의 경로 문자열이 일치할 때 발생하는 ID 충돌 경고를 `Mem_`, `Disk_` 접두사 및 PushID 스코프로 해결.

- 할당된 필드와 피커 목록의 메모리·디스크 행에서 우클릭으로 해당 파일의 내부 에디터를 연다. 이 명령은 슬롯 할당을 바꾸지 않는다.
- 콘텐츠 브라우저와 같은 에디터 열기 경로를 사용한다. 같은 파일은 기존 에디터로 이동하고 다른 파일에 미저장 변경이 있으면 교체를 막는다. 내부 에디터가 없는 항목은 열기 메뉴를 비활성화한다.

### 22.2 콘솔 패널(Console Panel) 개편
- **4열 정렬 테이블 구조**: `[Time / Level]`, `[Category]`, `[Message]`, `[Source]` 컬럼으로 분할하고 교차 행 배경(`RowBg`)을 적용하여 언리얼/유니티 스타일의 시각적 가독성 확보.
- **컬러 캡슐 배지 시스템**: 로그 레벨(`[ INFO ]`, `[ WARN ]`, `[ ERROR ]`) 및 카테고리(`[ Render ]`, `[ Asset ]`, `[ Shader ]`)별 고유 포인트 컬러, 반투명 배경, 라운드 외곽선 배지 렌더링.
- **행 높이 고정 및 가상화 스크롤 누락 해결**:
  - `ImGuiListClipper`의 고정 높이 가정을 깨뜨리던 긴 메시지/멀티라인 줄바꿈을 공백 치환 1줄 요약본(`SingleLineMessage`)으로 고정.
  - `ScrollX` 플래그를 제거하여 가로 무한 팽창을 방지하고 테이블 폭에 맞춰 텍스트가 정돈되도록 개선.
- **하단 상세 뷰(Detail View) 및 인터랙티브 수직 스플리터**:
  - 테이블 행 클릭 시 하단에 원본 줄바꿈이 온전히 보존된 상세 메시지 전문 창 열림.
  - 테이블과 상세 창 사이에 6px 두께의 수직 스플리터(`ImGui::Button("##ConsoleDetailSplitter")`) 및 알약 그립 핸들 배치.
  - 마우스 호버/드래그 시 상하 리사이즈 커서(`ImGuiMouseCursor_ResizeNS`) 및 하이라이트 제공, 실시간 높이 드래그 조절(최소 60px ~ 창 전체 크기, 기본 160px).
  - 상세 뷰 상단에 메타 정보 헤더, 전문 [ 복사 ] 버튼, [ ✕ 닫기 ] 버튼 제공.

## 23. 메트릭스 패널(Metrics Panel) 하이브리드 대시보드 및 마스터-디테일 개편 계획

### 23.1 배경 및 문제점
- 현재 `MetricsPanel`은 `FrameSummary`, `FrameGraph`, `EngineStatus`, `RenderMetrics`, `ResourceMetrics`, `AssetTaskMetrics`가 단일 뷰포트에 무조건 전부 나열되는 수직 스크롤 구조(높이 1,500px 이상)로 작성되어 있다.
- 특정 도메인(예: GPU 패스 시간과 비동기 에셋 태스크)만 집중 모니터링하려 해도 화면을 계속 위아래로 스크롤해야 하며, 렌더링되지 않는 비활성 영역까지 매 프레임 수백 개의 텍스트/표 드로우콜이 실행되는 비효율이 있다.

### 23.2 상단: 반응형 핵심 KPI 요약 카드 그리드 (Overview Dashboard Cards)
- 창 너비에 따라 가변적으로 2열/3열/4열 배치되는 반응형 카드 그리드 구축.
- **5대 핵심 도메인 카드 구성**:
  1. **Performance**: FPS, Frame Time ms, 미니 스파크라인 그래프, Target FPS 대비 달성율.
  2. **GPU Rendering**: 총 드로우콜(인덱스/비인덱스 합계), 버텍스 수, 총 GPU 패스 시간 ms, 하드웨어 기능 뱃지.
  3. **Memory & VRAM**: VRAM 예산 대비 사용량 게이지 바, 로드된 텍스처/메시/셰이더 캐시 총 메모리(MB).
  4. **Engine & Tasks**: 활성 씬 수, 등록된 렌더 패스 수, 백그라운드 에셋 로딩 태스크 큐(대기/진행/완료).
  5. **Network**: 현재 세션 모드(Server/Client/Standalone), 지연 시간(Smoothed RTT ms), 인바운드/아웃바운드 KB/s.
- **상태 색상 뱃지 (Health Indicator)**:
  - 정상(Green): FPS >= 60, VRAM <= 70%, RTT <= 50ms
  - 주의(Yellow): FPS 30~60, VRAM 70~90%, RTT 50~150ms, 로딩 대기 4개 이상
  - 경고(Red): FPS < 30, VRAM > 90%, RTT > 150ms, 렌더 실패(RenderFailed) 감지
- 각 카드 우측 상단에 `[ View Details ↗ ]` 버튼을 배치하여 원클릭으로 하단 상세 뷰를 전개.

### 23.3 하단: 마스터-디테일 심층 분석 뷰 (Detailed Inspection View)
- 상단 카드 클릭 시 하단 영역에 해당 도메인의 상세 분석 테이블이 전체 폭으로 전개됨:
  - `Performance` 선택 시: 전체 히스토리 프레임 그래프, FPS 통계(Min/Max/Avg).
  - `GPU Rendering` 선택 시: 40여 개 렌더 패스별 CPU/GPU 시간 테이블(`PassStat`), 디스크립터 힙 사용량, D3D12 Timestamp 상세.
  - `Memory & VRAM` 선택 시: 모델/머티리얼/텍스처/사운드별 세부 메모리 사용량 및 개별 핸들 통계.
  - `Engine & Tasks` 선택 시: 비동기 태스크 큐 상세 목록, 스로틀링된 업로드 상태.
  - `Network` 선택 시: 접속된 클라이언트 테이블, 실시간 RTT 플롯 라인, 핑/하트비트 통계.
- 선택된 카드가 없을 때는 상단 대시보드 카드만 컴팩트하게 노출되어 작업 공간 낭비를 원천 차단.
- 상단 카드와 하단 상세 뷰 사이에 리사이즈 가능한 수직 스플리터 적용.

### 23.4 렌더링 및 연산 최적화
- 하단 상세 뷰가 닫힌 도메인의 텍스트 제출·포맷팅을 생략하는 것을 목표로 한다. 부하 절감률은 아직 측정 근거가 없으며 고정된 60% 개선을 보장하지 않는다(A07).
- 상단 카드의 수치 갱신 주기를 0.2~0.5초(DrawSnapshotWindow)로 제한하는 방안을 검토한다.

## 24. 패널 위젯 분리 후보

### 리소스 편집기 공통 헤더 (2026-11-09)

리소스 편집기 상단은 **창 제목 → 메뉴 툴바 → 퀵액세스** 순서를 사용한다. 공통 `ResourceEditorInterface::Draw()`에서 창과 각 영역을 시작하고 종료한다. 편집기는 `DrawCustomToolbar`에서 메뉴, `DrawCustomQuickAccess`에서 직접 실행할 버튼, `DrawCustomContent`에서 프리뷰·인스펙터·캔버스 등 작업 영역을 그린다. 좁은 폭에서는 메뉴를 접고 퀵액세스는 줄바꿈한다.

검증 시에는 제목과 창 ID가 파일 전환 및 언어 변경 후에도 도킹을 유지하는지, 메뉴와 퀵액세스가 같은 명령을 호출하는지 확인한다. 그래프 컨텍스트, 애니메이터 미저장 확인, 파일이 없는 텍스처/셰이더의 경로 복사 비활성 상태를 함께 확인한다.


### 뷰포트 우측 토글 복원 (2026-11-09)

- 씬과 카메라 뷰포트에는 우측에 RGBA 및 2D/3D 그룹을 배치한다. 게임·UI·렌더 타깃 뷰에는 RGBA를 배치한다. 각 그룹은 내부 간격 없이 붙여 그리고, 채널별 활성 색상과 투영 선택 상태를 표시한다.
- 좌측 메뉴의 표시 문구와 우측 버튼 그룹의 폭을 계산한다. 공간이 부족하면 좌측 메뉴만 접는다. 토글이 메뉴와 같은 줄에 들어가지 않으면 이미지 위의 별도 줄에 우측 정렬하고, 두 그룹도 함께 들어가지 않으면 각각 한 줄을 쓴다.
- 프리뷰 위젯은 RGBA를 이미지 오른쪽 위에 별도 오버레이로 그린다. 렌더 타깃·조명 등 왼쪽 도구와 한 줄을 공유할 폭이 부족하면 오른쪽의 RGBA를 먼저 표시하고 왼쪽 도구를 아래 줄에 둔다. 두 오버레이 영역에서 시작하는 클릭은 카메라 드래그로 전달하지 않는다.
- 호출부와 버튼 폭 계산을 정적으로 확인했다. 빌드와 화면 검증은 미실시다. 사용자가 좁은 도킹 폭, 큰 글꼴과 UI 배율, 프리팹 모드, RGBA 색상 및 2D/3D 전환을 확인한다. 개별 버튼보다 좁은 폭은 공통 버튼의 최소 표시 폭에 걸린다.


### 고정 영역과 행 내부 버튼 공통화 (2026-11-09)

- 작성·적용 범위: 프리뷰 오버레이, 씬/카메라/기본 뷰포트 옵션 메뉴, RGBA 채널, 프리팹 모드 헤더, 제목 표시줄과 PIE 제어, 애니메이터/머티리얼/파티클/스프라이트 프레임/리플렉션 컬렉션의 행 내부 버튼. 관련 UI 소스·헤더 14개 파일을 수정했다.

### 공통 대화상자 버튼 바 (2026-11-09)

- `EditorUI::DialogButtonBar`는 로캘 키·활성 여부·파괴적 동작 여부를 받아 선택한 번호만 반환한다. 첫 항목은 취소, 마지막은 기본 확인이다. 저장·삭제·팝업 종료는 호출자에 남긴다.
- 번역된 글자와 패딩으로 버튼을 측정하고 우측 정렬한다. 한 줄에 들어가지 않으면 세로로 배치하며, 버튼 문구도 가용 폭 안에서 줄바꿈한다. 파괴적 동작은 위험 색상을 사용한다.
- 그래프 교체, 프리팹 편집기 닫기, 프리팹 모드 종료, 후처리 프리셋 저장·삭제의 5곳에 적용했다. 프리팹 편집기의 저장 실패 시에는 닫기/다음 리소스 열기를 진행하지 않도록 수정했다.
- 입력창 편집·활성 항목·팝업 첫 프레임에서는 별도 Enter/Escape 처리를 하지 않는다. 포커스된 대화상자에서 Escape는 취소, Enter는 포커스된 버튼 또는 마지막 기본 확인에 대응하며 InputManager 샘플을 사용한다. 비활성 확인 버튼은 실행하지 않는다.
- 정적 확인만 수행했다. 사용자 검증은 취소/저장/버리기 분기, 잘못된 프리셋 이름, 저장/삭제 실패 시 유지, Tab·Enter·Escape와 텍스트 편집 충돌, 언어·배율·좁은 창에서 버튼/문구 줄바꿈이다.
- 이번 검색 범위인 `Editor/Source/ImGui`의 cpp 파일에는 BeginPopupModal 호출 13곳이 있고 그중 5곳을 전환했다. 나머지 8곳은 애니메이터 1, 콘텐츠 브라우저 충돌 1, ImGuiManager 2, 텍스처 가져오기 결과 1, 그래픽 해상도 확인 1, 스프라이트 2다. 모달 호출 수는 공통화가 필요한 결함 수나 전체 팝업 수를 의미하지 않는다.

### 모델·머티리얼·파티클의 공통 툴바 배치 (2026-11-09)

- `EditorUI::ToolbarLayout`은 Draw마다 생성하는 지역 배치 도우미다. 아이콘·아이콘+텍스트 버튼·콤보/슬라이더의 폭·상태 문구를 같은 줄에 놓을지 측정하며 공간이 부족하면 다음 줄을 사용한다. 실행 핸들러와 편집 상태는 패널이 소유한다.
- 텍스트 버튼은 전체 가용 폭에도 들어가지 않을 때 아이콘과 툴팁으로 전환한다. 입력 요소는 글꼴 기준 희망 너비를 가용 폭으로 제한한다. 파일명과 상태 문구는 줄바꿈해 표시한다.
- 모델의 저장·포커스·그리드·모델 배치·재생·클립·LOD·파일 상태, 머티리얼의 저장·복원·포커스·그리드·파일 상태, 파티클의 파일 작업·Undo/Redo·재생/재시작/스텝·속도·포커스·통계/상태에 적용했다. 고정 높이 아이콘과 강제 SameLine 및 세로 구분자를 제거했다.
- 모델 포커스·그리드는 기존 ShortcutManager의 동적 힌트를 사용한다. 그리드 토글의 활성 상태를 표시한다. 저장, 리소스 유효성, PIE, 이력 가능 여부와 시뮬레이션 실행 분기는 유지한다.
- 공통 아이콘 자체의 최소 폭보다도 좁은 영역에서는 기존 표시 제한이 남는다. 별도의 더 보기 메뉴는 이번 작업에 추가하지 않았다.
- 정적 확인 범위는 API·호출부와 비활성/스타일 스택 및 실행 분기다. 빌드·UI 실행은 미실시다. 글꼴/배율 조합과 좁은 창에서 줄 수 증가에 따른 하단 영역 배치, 긴 파일명, 토글·툴팁, 모델 배치·클립/LOD 변경, 머티리얼 저장/복원, 파티클 Undo/Redo·재생 제어를 사용자 검증한다.

### 공통 아이콘 버튼과 크기·줄바꿈 기준 (2026-11-09)

- `EditorUI::GetIconButtonSize`는 현재 글꼴의 아이콘 측정값, FramePadding, 글꼴 기준 최소 패딩으로 정사각형 크기를 계산한다. 고정 픽셀 버튼 크기는 사용하지 않으며 배경·아이콘 간 여백도 같은 계산을 따른다.
- `IconButton`은 안정적인 ID, 비활성 상태, 활성 토글 색상, 로캘 툴팁과 호출자가 전달하는 동적 단축키 힌트를 지원한다. `SameLineIfFits`는 직전 항목과 간격을 합쳐 다음 항목이 들어갈 때만 같은 줄에 배치한다.
- 검색 지우기, 콘텐츠 브라우저 뒤로·새로고침, 콘솔 지우기·자동 스크롤, 타일 팔레트의 브러시 4종·지우기에 적용했다. 타일 슬라이더와 콘솔 레벨 필터·체크박스도 배치 폭을 고려한다. 기존 실행 조건과 동작은 유지한다.
- 검색 바는 지우기 버튼의 실제 크기를 예약한다. 요청 너비는 가용 폭으로 제한하며, 매우 좁으면 검색 아이콘과 지우기 버튼을 생략한다. Escape 초기화는 유지한다. 아이콘 버튼 하나의 최소 폭도 확보할 수 없는 영역에서는 해당 버튼을 그리지 않으며, 호출 화면의 최소 폭 검증이 필요하다.
- 상위 폴더 버튼 툴팁은 Editor.csv의 `ContentBrowser.ParentFolder`를 사용한다. 생성 JSON은 수정하지 않았다.
- 정적 확인 범위는 크기 계산과 스타일 스택, ID·행동 연결, 호출부의 공간 예약이다. 빌드·실행은 미실시다. 사용자 검증은 글꼴 크기·UI 배율 조합, 한글/영어, 좁은 창·열, 버튼 패딩·토글·비활성 툴팁, 가로 스크롤 발생 여부를 포함한다. 전 에디터 아이콘 버튼의 일괄 전환 완료를 의미하지 않는다.

### 공통 검색 바 확장과 패널 적용 (2026-11-09)

- `DrawSearchBar`에 전체 너비와 최초 입력 포커스 옵션, `Changed`·`Submitted`·`Cleared` 결과를 추가했다. 기존 `SearchBar`는 변경 여부를 반환하는 호환 래퍼로 유지한다. 명시적 너비는 자동 크기 팝업의 초기 크기 결정에도 사용하며, 미지정 시 가용 폭을 채운다.
- 플러그인 관리자, Hierarchy, 콘솔, 리소스 검사창, 에셋 참조, 그래프 노드 추가, 엔티티 선택, 리소스 선택기, 콘텐츠 브라우저의 검색 입력 9곳을 전환했다. 통합 설정을 포함하여 10개 사용처가 공통 구현을 공유한다.

- 콘텐츠 브라우저는 입력 변경만으로 검색을 실행하지 않는다. Enter·범위 변경·초기화 요청을 기존 검색 경로로 전달한다. 툴바는 첫 줄의 뒤로·새로고침·경로·필터와 둘째 줄의 검색·범위 버튼으로 고정한다. 경로는 필터 공간을 제외한 첫 줄을 채우고 필터는 우측 끝까지 사용한다. 검색은 범위 버튼의 번역 폭을 제외한 둘째 줄을 채운다.
- `ReflectionInspectorCheck`는 리소스/엔티티 선택 검색의 새 외부 함수를 연결하도록 `EditorUI.cpp`를 소스에 추가했다. 새 검사 실행이나 빌드는 수행하지 않았다.
- 사용자 확인: 9개 화면의 입력·X·Escape, 실시간 필터 갱신, 팝업 첫 포커스와 Escape 닫힘 충돌, 콘텐츠 브라우저 Enter·검색 범위·초기화, 언어·배율·좁은 창의 배치를 검증한다. 정적 확인은 실행 결과를 대신하지 않는다.

### 공통 검색 바와 통합 설정 적용 (2026-11-09)

- `EditorUI::SearchBar`는 호출자 소유 문자 버퍼를 편집하고 변경 여부를 반환한다. 검색 아이콘, 로캘 힌트, 가용 폭 입력창, 정사각형 지우기 버튼과 툴팁을 제공한다. 빈 검색어에서는 지우기 버튼을 비활성화하고 자리를 유지한다.
- Escape는 해당 입력창이 활성 상태이고 창에 포커스가 있을 때만 InputManager 샘플로 판정한다. ImGui의 EscapeClearsAll 처리 후 버퍼를 비우고 활성 입력을 해제한다. 내부 ImGui API 의존성은 공통 구현 파일에 한정한다.
- 통합 설정의 기존 `ImGuiTextFilter`는 계속 패널이 소유한다. 검색어 변경 시 `Build()`를 호출하고 단축키 위젯의 기존 `PassFilter()` 판정을 유지한다. 포함·제외 필터 문법과 검색 범위는 변경하지 않는다. 현재 검색은 단축키 목록에만 적용된다.
- 플러그인 관리자·콘텐츠 브라우저 적용은 후속 작업이다. 새 로캘 키나 명령 단축키는 추가하지 않는다.
- 정적으로 API·버퍼·필터 갱신 경로와 기존 로캘/아이콘 정의를 확인했다. 빌드·실행은 미실시다. 사용자 검증은 입력/붙여넣기, 쉼표 및 제외 필터, X 초기화, Escape 한 번으로 초기화·편집 해제, 다른 입력창·키 캡처에서의 Escape 비간섭, 언어 전환, UI 배율과 창 크기 변경을 포함한다.

### 프로젝트·입력 액션·단축키 설정 테이블 공통화 (2026-11-09)

- `BeginSettingsTable` / `EndSettingsTable`은 열 수와 테이블 플래그를 받아 여백 수명만 관리한다. 시작 실패 시 스타일을 즉시 복원한다. 속성 테이블도 같은 경로를 사용한다.

- 정적 확인 범위는 API 선언·정의·호출부, 테이블 시작·종료와 스타일 복원 경로다. 빌드와 UI 실행은 미실시다. 사용자 검증은 프로젝트 경로 선택, 입력 액션 확장·추가·삭제·캡처 취소·저장, 단축키 검색·캡처·충돌·초기화, 언어·배율 변경과 열 리사이즈를 포함한다.

- **좌측: 모듈 및 플러그인 목록 (Master List, 270px 폭)**:
  - 상단 필터: 실시간 검색창(클리어 버튼 지원), 카테고리 콤보 (`All`, `Game Logic`, `Editor Tools / Panels`, `Experimental`).
  - 목록 카드: 각 모듈의 아이콘, 표시명, 버전, 현재 상태 뱃지 (`Loaded` 초록, `Unloaded` 회색, `Failed` 빨강, `Compiling` 노랑).
- **우측: 상세 인스펙터 및 제어 독 (Detail View)**:
  - **헤더 툴바**:
    - `[Reload]` (원클릭 핫리로드 강제 트리거)
    - `[Rebuild & Reload]` (백그라운드 비동기 컴파일 후 핫리로드)
    - `[Load / Unload]` 토글 버튼
    - `Auto-Reload on Save` 체크박스
    - `Auto-Compile on Save` 체크박스
    - 셰이더 모듈 전용: `[Recompile All Shaders]`, `Auto-Reload Shaders`
    - 패널 플러그인 전용: `[Open Panel]`, `[Close Panel]`
  - **메타데이터 속성표**:
    - 모듈 식별자, 원본 DLL 경로, 현재 로드된 섀도우 복사본 경로(`Temp/HotReload/...`), 소스 디렉터리, 프로젝트 루트, 리로드 인덱스, 빌드 상태.
  - **제공 기능 및 컴포넌트**:
    - `GameModule`: 게임플레이 시스템(`SkyAtmosphereSystem`), 리플렉션 등록된 컴포넌트(`SkyAtmosphereComponent` 등) 동적 열거.
    - 에디터 패널: 작업 공간에 패널 표시 토글 체크박스.
  - **실시간 빌드 콘솔 뷰 (Build & Diagnostic Log)**:
    - 백그라운드 컴파일러의 실시간 출력 전문 스트리밍.
    - 컴파일 에러 라인(error, FAILED) 빨간색 하이라이트, 경고 라인(warning) 노란색 하이라이트.
    - 컴파일 실패 시 `[Retry Compile]` 버튼 제공 및 `[Copy Log]`, `Auto-scroll` 지원.

### 26.2 생명주기 및 안전성 제어 정책 [구현 완료]

1. **안전한 수동 언로드(Safe Unload)**:
   - 사용자가 UI에서 `[Unload]`를 클릭할 경우, `ModuleHotReloadManager::UnloadModule()`을 통해 안전하게 DLL 핸들을 해제하고 섀도우 복사본을 정리.
2. **에러 격리 및 복구 안내**:
   - 컴파일 실패 시 에디터가 죽지 않고 `Failed` 상태로 전환되며, 빌드 콘솔 뷰에 붉은색 에러 로그와 함께 `[Retry Compile]` 버튼을 띄워 복구를 유도.
3. **진입 경로 및 단축키**:
   - 메뉴바: `Window -> Panels -> Diagnostics -> Plugin Manager` 및 `Edit -> Plugins`.
   - 로캘 연동: `PluginManager.Title`, `PluginManager.Reload`, `PluginManager.StatusLoaded` 등 `Editor.csv` 그룹 신설 및 JSON 동기화 완료.

### 26.3 스프라이트 애니메이션 편집기 플러그인

- Windows의 `EditorSpriteAnimationTools` DLL이 지원 확장자, 에셋 열기·저장, 편집 세션, 메뉴·퀵액세스·프리뷰·프레임 목록·필름스트립과 재생 갱신을 제공한다. Editor의 공용 `PluginResourceEditor`가 창, 도킹, 단축키와 DLL 수명을 관리한다.
- 관리자의 스프라이트 애니메이션 편집기 항목에서 DLL 다시 로드, 빌드 후 다시 로드, 소스 저장 시 자동 컴파일을 제어한다. 애니메이션 에셋 저장은 소스 빌드를 요청하지 않는다.
- 로더는 새 DLL과 Debug PDB를 별도 세대 폴더에 복사하고 V1 계약을 확인한다. 실패 시 기존 DLL과 편집 상태를 유지한다. 빌드와 교체는 각각 백그라운드 작업과 메인 스레드 갱신에서 처리한다.
- 완료 확인은 F5에서 복사본 PDB가 로드되고, Editor 프로세스와 미저장 데이터를 유지한 채 소스 저장 후 새 코드가 적용되며, 빌드 또는 로드 실패 뒤에도 기존 편집·저장이 동작하는 것이다.

### 26.4 에디터 플러그인 만들기

이 절은 Sprite가 사용하는 리소스 패널 DLL의 작성 절차다. 일반 패널 DLL의 발견·활성화와 기존 도구의 이관 범위는 [에디터 플러그인 아키텍처 설계](EditorPluginArchitecturePlan.md#9-dll-플러그인-구현과-호출-흐름)에서 다룬다.

#### 새 플러그인과 기존 플러그인 중 어디에 넣을까

같이 빌드하고 교체할 패널과 위젯은 같은 DLL에 둔다. 독립적으로 빌드하고 교체할
필요가 있는 기능만 새 DLL 타깃으로 만든다. 리소스 패널 타깃은 `Editor/Plugins/CMakeLists.txt`에
`bam_add_resource_panel_plugin(타깃명 절대_소스폴더 소스파일...)`로 한 번 등록한다.

#### 현재 방식으로 만드는 순서

1. `Editor/Plugins/<기능명>/Private`에 패널 구현을 둔다.
2. 공용 `ResourcePanelPluginApi.h`를 포함하고 `BamGetResourcePanelPluginV1`을 내보낸다.
   고정 패널 이름, 로캘 키, 파일 형식 판별과 열기·저장·그리기 콜백을 제공한다.
3. DLL의 세션에서 편집 상태를 소유한다. 교체용 스냅샷에는 값과 엔진의 리소스 핸들을 담는다.
   이전 DLL이 소유한 포인터·콜백은 저장하지 않는다. 새 세션이 생성된 뒤 이전 세션을 파괴한다.
4. 공용 CMake 함수가 타깃과 감시 폴더를 실행 파일 옆 `EditorResourcePlugins.txt`에 기록한다.
   Editor는 목록으로 패널과 빌더를 등록한다. 패널별 Editor 클래스나 관리자 분기는 필요 없다.
5. 표시 문구는 `Editor.csv`에 등록한다. 저장 액션 ID를 제공하면 호스트가 해당 창의
   `Ctrl+S`를 등록한다. 사용자 지정 단축키를 유지하려면 ID를 바꾸지 않는다.

```cmake
bam_add_resource_panel_plugin(EditorSpriteAnimationTools "${CMAKE_CURRENT_SOURCE_DIR}/SpriteAnimationTools"
    SpriteAnimationTools/Private/SpriteAnimationTools.cpp
)
```

처음 등록할 때는 `Editor` 타깃을 빌드해 DLL과 플러그인 목록을 함께 준비한다.
이후 DLL만 수동 빌드할 때는 `cmake --build out/build/x64-debug --config Debug --target EditorSpriteAnimationTools`
명령을 사용한다.

#### 어디를 바꾸면 무엇을 빌드할까

- DLL 내부의 UI와 편집 동작을 바꾸면 해당 플러그인 타깃만 빌드한다.
- 호스트가 제공하는 서비스나 양쪽이 공유하는 계약을 바꾸면 Editor와 DLL을 같이 빌드한다.
- 자동 빌드는 플러그인 소스 저장에 반응한다. 편집 중인 에셋 저장은 기존 저장 경로를 사용한다.

#### 교체 검증

1. 패널을 열고 에셋을 수정한 상태에서 플러그인 소스를 바꿔 저장한다.
2. Editor를 재시작하지 않고 새 UI가 나타나며, 기존 수정값과 미저장 표시가 유지되는지 확인한다.
3. 기존 저장 단축키로 저장한 뒤 에셋을 다시 열어 수정값을 확인한다.
4. 컴파일 실패와 진입점 검증 실패를 각각 재현한다. 이전 DLL로 편집과 저장이 계속되어야 한다.

#### 교체 계약

공용 V1 계약은 DLL 하나당 리소스 패널 하나를 등록한다. 동일한 엔진·ImGui 헤더와
툴체인을 사용한다. 활성 패널의 이름, 저장 액션 ID, 스냅샷 버전이나 크기가 달라지면
교체를 거부하고 기존 편집 세션을 유지한다. 이 계약을 바꾸려면 Editor를 재시작한다.
