## 1. 목표

화면 크기, 프레임 제한과 렌더링 관련 설정을 `GraphicsSettingPanel`에서 쉽게 확인·변경·저장한다.
에디터를 다시 실행하면 저장한 설정을 복원하고, 패널을 닫았다 다시 열어도 실제 적용 상태를 정확히 보여준다.
프리팹 제작·편집·배치 패널을 추가하고, 다른 엔진의 제작 도구를 참고해 현재 빠져 있거나 연결이 부족한 기능을 단계적으로 보완한다.
콘텐츠 브라우저의 내부·외부 에디터 열기와 타입별 미리보기를 연결하고, 컴포넌트의 리소스 핸들을 검색·썸네일로 선택한다.
파티클·스플라인 제작 기능과 바이너리 에셋의 타입별 표시도 후속 목표에 포함하며, 검색·미리보기의 CPU·GPU·메모리 비용을 제한한다.

이 문서는 다음 구현 목표를 기록한다. 패널 생성이나 설정 적용·복원 검증이 완료됐다는 뜻은 아니다.
이번 문서 작성에서는 C++ 코드와 기존 설정 파일을 변경하지 않는다.

## 2. 현재 코드에서 확인한 상태

- 확인일: 2026-10-31.
- 화면 설정은 독립 GraphicSettingPanel에서 편집한다.
  파일 메뉴와 창 메뉴가 같은 패널에 연결되어 있다.
- EditorPreferences는 언어·UI 배율·목표 FPS·VSync를 사용자 설정 경로에 저장한다.
- EditorWorkspace는 창 상태·패널 열림·도킹·콘텐츠 브라우저·뷰포트 상태를 프로젝트별로 저장한다.
- EditorSettingsService가 시작 시 로드·검증과 실행 중 적용 요청·저장 결과를 조정한다.
- 기본 Scene/Game View의 해상도는 대상별 초안으로 편집한다.
  기존 뷰포트 Update에서 리사이즈하고 결과 확인 후 저장한다.
- Scene View의 편집 카메라와 렌더 패스 활성화 상태는 ViewportWorkspace로 캡처·복원한다.
- VSync는 시작 시 복원과 프레임 경계의 변경 요청에 연결되어 있다.
- 손상되거나 지원하지 않는 설정 파일은 기본값으로 대체하고 원본 덮어쓰기를 차단한다.
  시작 알림과 설정 패널에서 저장 차단 상태를 안내한다.
- 프리팹 파이프라인(생성·배치, 뷰포트 격리 편집 모드 `PrefabModeManager`, 단일 원천 루트 `PrefabInstanceComponent` 및 Apply/Revert/Unpack)과 엔티티 다중 복사·붙여넣기(`EntityClipboard`)가 구현 완료되었다.
- 인스펙터 리소스 피커(`ResourcePicker.h`)의 템플릿 인자 `T`별 호환 확장자 필터링 및 팝업 진입 시 1회 스캔 캐싱이 구현되어 프레임 드랍 병목이 해결되었다.
- EditorSettingsCheck의 파일 입출력·데이터 검사는 통과했다.
  이는 실제 UI·GPU·재실행 복원 검증 완료를 의미하지 않는다.

8절의 실행 검증 항목은 실제 확인 결과에 따라 완료 처리한다.

## 3. 통합 설정 패널(Unified Settings Panel)의 구성과 카테고리 분류

여러 설정이 개별 독립 패널(`GraphicSettingPanel`, `ShortcutSettingsPanel` 등)로 파편화되거나 한 화면에 무질서하게 나열되는 문제를 해결하기 위해,
언리얼의 `Editor Preferences / Project Settings` 및 Visual Studio의 `Options` 구조를 벤치마크하여 **좌측 카테고리 네비게이션 + 우측 상세 속성 뷰**의 2열 구조를 갖춘 **통합 설정 패널(`UnifiedSettingsPanel` 또는 `EditorSettingsPanel`)** 로 일원화한다.

`ImGuiManager`의 기본 패널 목록과 상단 메뉴(`File > Settings` 및 `Window > Settings`)에서 단일 진입점으로 제공하며, 기존의 개별 설정 UI를 카테고리별 하위 뷰로 통합한다.

### 3.1 레이아웃 구조

```
+---------------------------------------------------------------------------------+
| Settings                                                                      x |
+---------------------------------------------------------------------------------+
| [Q Search settings...                                                        ] |
+-----------------------+---------------------------------------------------------+
| Category              | General Settings                                        |
| --------------------- | ------------------------------------------------------- |
| > General             | [v] Language                                            |
|   Graphic             |     Language: [ Korean               v ]                |
|   Editor              |                                                         |
|   Workspace           | [v] Auto Save                                           |
|   Shortcuts           |     Enable Auto Save: [x]                               |
|   Project Settings    |     Interval (Minutes): [ 5 ]                           |
|                       |                                                         |
|                       | [v] Startup                                             |
|                       |     Restore Last Scene: [x]                             |
+-----------------------+---------------------------------------------------------+
| Status: Modified      |                 [ Reset Defaults ]  [ Revert ]  [ Apply ] |
+-----------------------+---------------------------------------------------------+
```

1. **상단 검색창 (Search Filter):**
   - `ImGuiTextFilter` 기반의 실시간 키워드 검색.
   - 검색어 입력 시 매칭되는 속성을 포함하는 카테고리에 검색 결과 개수 배지(Badge)를 표시하고, 검색 결과 목록에서 선택 시 해당 카테고리 및 속성 섹션으로 자동 스크롤 점프.
2. **좌측 카테고리 사이드바 (Navigation Sidebar):**
   - 너비 조절 가능한 좌측 차일드 윈도우(`ImGui::BeginChild`).
   - 카테고리 목록(아이콘 및 텍스트)을 나열하며, 현재 선택된 활성 카테고리를 하이라이트 표시.
3. **우측 상세 속성 뷰 (Content Area):**
   - 선택된 카테고리에 속한 세부 속성들을 `ImGui::CollapsingHeader` 및 세부 그룹 박스로 깔끔하게 분할 렌더링.
   - 각 속성 라벨, 입력 위젯(드롭다운, 슬라이더, 체크박스 등) 및 기능 설명 툴팁(`(?)` 도움말 마커) 제공.
4. **하단 액션 바 (Footer Action Bar):**
   - 변경 상태 표시: 초안 수정 발생 시 `Status: Modified (Unsaved Changes)` 경고 텍스트 표시.
   - `기본값으로 복원 (Reset to Defaults)`: 현재 카테고리(또는 전체)의 속성을 권장 기본값으로 리셋.
   - `되돌리기 (Revert)`: 변경 중인 초안을 취소하고 마지막으로 저장된 값으로 즉시 복귀.
   - `적용 (Apply)`: 수정한 초안들의 유효 범위를 검증하고 Application, RHI, Config 경로에 즉시 반영 및 디스크 저장.

### 3.2 카테고리별 세부 속성 분류

#### A. `General` (일반 설정)
- **언어 (Localization):** 에디터 표시 언어 선택(`Korean` / `English`), 언어 변경 시 UI 실시간 재번역 반영.
- **테마 및 스타일 (Appearance):** 에디터 다크/라이트 테마 프리셋, 강조 색상(Accent Color).
- **자동 저장 (Auto-save):** 주기적 씬 자동 저장 활성화 여부 및 주기(분 단위).
- **시작 동작 (Startup):** 에디터 실행 시 마지막으로 열었던 씬 자동 로드 여부(`LastScenePath` 연동).

#### B. `Graphic` (그래픽 및 디스플레이)
- **화면 및 해상도:** 에디터 창 너비·높이, 창 모드(창 모드 / 최대화 / 전체화면).
- **프레임 레이트:** 목표 FPS 설정(0=무제한, 30, 60, 120, 144 등) 및 실측 FPS 대비 제한값 명시.
- **수직동기화 (VSync):** VSync On/Off 토글 및 프레임 경계에서의 스왑체인 동기화 적용.
- **품질 프리셋:** 렌더링 품질 프리셋(Low, Medium, High, Ultra), 타일 라이트 컬링 활성화 여부, 섀도우 맵 해상도.
- **디스플레이 변경 안전장치:** 창 크기/전체화면 변경 시 15초 카운트다운 확인 팝업 및 자동 복구 메커니즘.

#### C. `Editor` (에디터 환경)
- **UI 배율 (UI Scale):** 전체 에디터 인터페이스 DPI 스케일링 배율(0.5x ~ 3.0x), 취소 및 원래 값 복원 지원.
- **기즈모 (Gizmo):** 이동/회전/스케일 기즈모 크기, 그리드 스냅 단위(Grid Snap Unit: 0.1, 0.5, 1.0 등).
- **뷰포트 탐색 카메라:** 씬 뷰포트 카메라 이동 속도(`CameraSpeed`), 감도, FOV(기본 60도), 직교 크기(Orthographic Size).
- **디버그 및 로깅:** 콘솔 창에 출력할 최소 로그 레벨 필터(`Trace`, `Info`, `Warning`, `Error`).

#### D. `Workspace` (작업 공간)
- **도킹 레이아웃:** 기본 에디터 도킹 레이아웃 복원(`Reset Layout`), ImGui ini 레이아웃 저장 상태.
- **뷰포트 해상도 프리셋:** Scene View 및 Game View 대상 내부 렌더 해상도 모드(Free Aspect, 16:9, 16:10, Fixed Resolution) 및 커스텀 해상도 관리.
- **렌더 패스 기본 상태:** 뷰포트별 렌더 패스(Shadow, Geometry, Lighting, PostProcess, UIOverlay 등)의 기본 활성화 토글.
- **콘텐츠 브라우저:** 기본 썸네일 그리드 크기(32px ~ 128px), 에셋 검색 캐시 갱신 주기.

#### E. `Shortcuts` (단축키 매핑)
- 기존 독립 `ShortcutSettingsPanel`의 기능을 카테고리 하위 뷰로 완전 통합.
- **액션 매핑 테이블:** 기능 도메인별(뷰포트 조작, 씬 편집, 파일 작업, 그래프 에디터 등) 단축키 목록 테이블 표시.
- **키 캡처 및 변경:** 테이블 항목 클릭 후 원하는 키/조합키(Ctrl, Shift, Alt 등) 입력 시 즉시 캡처 및 바인딩.
- **충돌 감지 (Conflict Detection):** 이미 할당된 단축키와 중복될 경우 즉각적인 붉은색 경고 표시 및 덮어쓰기/취소 선택 제공.
- **기본값 복원:** 특정 액션 또는 전체 단축키를 기본 매핑으로 원클릭 리셋.

#### F. `Project Settings` (프로젝트 설정)
- **프로젝트 메타데이터:** 프로젝트 명, 제작자, 프로젝트 버전.
- **기본 씬 (Default Scenes):** 게임 클라이언트 실행 시 시작 씬 경로(`StartupScenePath`).
- **게임 입력 액션 (Input Action Mapping):** 인게임 게임플레이에서 사용하는 `InputActionMap`(예: `MoveForward`, `Jump`, `Fire`)과 입력 장치 바인딩(키보드/마우스/게임패드).
- **패키징 기본값:** 배포 시 포함할 필수 리소스 목록 및 기본 렌더 해상도.

## 4. 저장 범위와 소유권의 엄격한 분리

모든 설정을 단일 통합 창(`UnifiedSettingsPanel`)에서 편집하더라도, 각 데이터의 본래 성격과 수명에 맞는 **저장 소유자(Owner)** 와 파일 경로를 엄격히 분리 유지한다. 패널 내부에 임의의 모놀리식 단일 저장소를 만들지 않는다.

1. **사용자 개인 설정 (`EditorPreferences`):**
   - 언어, UI 배율, 목표 FPS, VSync, 에디터 테마 등 개발자 개인 환경에 귀속되는 설정.
   - 사용자 설정 디렉터리(`Config/EditorPreferences.json`)에 저장.
2. **프로젝트별 작업 상태 (`EditorWorkspace`):**
   - 창 크기, 패널 열림 상태, 도킹 배치, 뷰포트별 해상도/카메라 상태 등 프로젝트 작업 공간에 귀속되는 상태.
   - 프로젝트 설정 디렉터리(`Config/EditorWorkspace.json`)에 저장.
3. **단축키 매핑 (`ShortcutManager`):**
   - 에디터 작업 액션별 단축키 바인딩 데이터.
   - 단축키 설정 파일(`Config/Shortcuts.json`)에 저장.
4. **프로젝트 공통 설정 (`ProjectSettings`):**
   - 프로젝트 이름, 시작 씬 경로, 인게임 입력 액션 등 버전 관리에 포함되어 팀 전체가 공유해야 하는 설정.
   - 프로젝트 루트 디렉터리(`Config/ProjectSettings.json`)에 저장.

저장 데이터는 모두 기존 리플렉션 및 `ReflectionArchive` 기반 JSON 직렬화 경로를 일관되게 사용하며, 누락된 필드는 안전한 기본값으로 폴백한다.

## 5. 적용과 저장의 동작 라이프사이클

통합 설정 패널은 사용자의 의도하지 않은 설정 오염을 방지하기 위해 **초안(Draft) 기반 3단계 라이프사이클**을 따른다.

1. **진입 시 동기화 (Open & Sync):**
   - 패널을 열 때 각 소유 서비스(`EditorSettingsService`, `ShortcutManager`, `ConfigManager`)로부터 현재 적용된 최신 상태를 읽어와 UI 초안 버퍼(`m_Drafts`)에 복사한다.
2. **초안 편집 및 변경 감지 (Edit & Dirty Tracking):**
   - 사용자가 위젯을 조작할 때 실제 엔진 상태를 즉시 변동시키지 않고 초안 값만 수정한다.
   - 원본 값과 초안 값의 차이를 감지하여 `Dirty` 플래그를 활성화하고, 하단에 변경 경고 및 `Revert` / `Apply` 버튼을 활성화한다.
3. **유효성 검증 및 적용 (Validate & Commit):**
   - `Apply` 클릭 시 입력된 값(창 크기 최소값, FPS 상한, 단축키 중복 등)의 유효 범위를 먼저 검사한다.
   - 검증 통과 시 해당 서비스의 API를 호출하여 런타임에 즉각 적용(윈도우 리사이즈, UI 배율 갱신, VSync 설정 등)하고, 디스크 파일 저장을 수행한다.
   - 적용 실패 또는 디스크 쓰기 실패 시 에러 토스트/로그를 출력하고 이전 유효 상태를 안전하게 보존한다.

## 6. 관련 후속 목표: 뷰포트와 편집 카메라 복원

- 기본 뷰포트마다 해상도 모드·프리셋·사용자 크기·종횡비를 저장한다.
- 프리셋 순서 변경으로 다른 해상도가 선택되지 않도록 안정된 식별 방식이나 실제 해상도 값을 검토한다.
- 편집 카메라의 위치·회전·투영 방식·FOV 또는 직교 크기·이동 속도를 프로젝트별로 저장한다.
- 씬에 속한 게임 카메라와 에디터의 탐색용 카메라를 구분한다.
- 복원 값은 범위·유한 값·enum을 검증하고, 기존 Transform·카메라 갱신 API로 적용한다.
- 렌더 해상도는 기존 리사이즈 경로로 적용하며 GPU 객체 자체를 복원하지 않는다.
- 처음에는 기본 생성 뷰포트를 대상으로 한다. 사용자가 추가한 뷰포트의 재생성은 별도 후속 범위로 둔다.
- 뷰포트별 렌더 패스(Shadow, PointShadow, Geometry, Lighting, Forward, UIOverlay 등)의 On/Off 토글 상태를 `ViewportWorkspace`에 저장하고 에디터 재실행 시 복원한다.
- 런타임에 동적으로 변경된 패스 활성화 상태를 뷰포트 상태 캡처(`CaptureViewportState`) 시 직렬화하고, 복원(`RestoreViewportState`) 시 해당 `RenderPassID`의 `SetEnabled`로 적용한다.
- 새 패스 추가나 이름 변경 시에도 이전 작업 공간 파일을 안전하게 읽을 수 있도록 기본값(`true`) 폴백 정책을 유지한다.

## 10. 프리팹 관련 패널과 작업 흐름

### 초기 조사에서 확인한 기반과 부족한 연결

- `SceneManager::SavePrefab()`과 `InstantiatePrefab()`이 있고, `Scene`에는 프리팹 Archive 저장·복원 코드가 있다.
- 현재 프리팹은 선택한 루트의 하위 계층과 컴포넌트를 저장하고, 배치 시 새 엔티티로 복원하는 기반이다.
  이 코드만으로 원본 에셋과 인스턴스의 지속적인 연결이나 변경 전파가 구현됐다고 판단하지 않는다.
- `Editor/Source`에서 프리팹 저장·생성 API를 호출하는 편집 UI와 전용 프리팹 편집 패널은 확인되지 않았다.
  `EResourceType::Prefab` 표시 항목의 존재도 프리팹 편집 기능의 완료 근거로 삼지 않는다.
- `WritePrefabArchive()`는 저장할 서브트리를 순회하며 로컬 ID를 부여한다.
  이 ID를 파일 편집 전후에도 유지되는 인스턴스 변경 추적 식별자로 바로 사용하지 않는다.

참고 기능: Unity는 프리팹을 별도 편집 문맥에서 여는 Prefab Mode와,
원본에 대한 인스턴스 변경값을 표시·적용·되돌리는 기능을 제공한다.
[Prefab Mode](https://docs.unity3d.com/6000.0/Documentation/Manual/EditingInPrefabMode.html),
[Instance Overrides](https://docs.unity3d.com/6000.0/Documentation/Manual/PrefabInstanceOverrides.html)

### 1단계: 프리팹 만들기와 배치 (2026-10-31 구현 완료)

- Hierarchy에서 단일 루트 엔티티를 선택해 우클릭 `Save As Prefab...` 메뉴로 하위 계층을 프리팹 파일(`*.bamprefab.json`)로 저장한다.
- Content Browser에서 프리팹 파일을 식별(`ICON_FA_CUBES` 큐브 아이콘 및 시안 틴트)하고, 더블클릭 시 프리팹 모드로 즉시 진입한다.
- Scene View 또는 Hierarchy의 대상 부모로 드래그 앤 드롭하여 배치하고, 생성된 루트와 하위 객체를 한 편집 명령으로 Undo/Redo한다.
- 파일 선택·저장 대화상자는 `EFileDialogContext::PrefabSave` Context를 사용해 다른 작업의 폴더 이력과 구분한다.
- 기존 Archive와 리플렉션 경로를 재사용하며, `.bamprefab.json` 전용 확장자로 일반 씬/JSON 파일과 구분한다.

### 2단계: 프리팹 격리 편집 모드 (`PrefabModeManager`) (2026-10-31 구현 완료)

- 프리팹 파일을 열어 전용 독립 씬(`m_PrefabScene`)에서 계층·컴포넌트·기즈모를 100% 활용해 편집한다.
- 메인 씬은 `Safe_AddRef`로 메모리에 안전 보존하고, 메인 뷰포트(`SceneViewportPanel`), 하이어라키, 인스펙터, `ImGuizmo`를 그대로 재사용한다.
- 뷰포트 상단에 `◀ Back to Scene (씬으로 복귀)` 및 `Save` 배너를 렌더링하여 원클릭으로 메인 씬에 복귀한다.
- 메인 씬의 선택과 편집 데이터를 보존하고, 프리팹 세션에 게임 실행이나 PIE 변경이 섞이지 않게 한다.
- 미저장 변경 플래그(`m_HasUnsavedChanges`) 및 토스트 알림을 제공한다. 저장 기준점과 Undo/Redo 연동은 아래 후속 기록을 따른다.

### 2026-11-01 후속: 저장 기준점과 Undo/Redo 변경 표시

- 상태: 코드 반영 / 빌드·실제 UI 검증 미확인. 기존 단계의 완료 표시는 이번 변경의 실행 검증 근거로 사용하지 않는다.
- `HasUnsavedChanges()`는 현재 프리팹을 대상으로 하는 편집 이력의 저장 기준점과 현재 상태를 비교한다. 별표와 종료 확인은 같은 조회 결과를 사용한다.
- 프리팹 진입 전 메인 씬의 미저장 여부를 보관하고, 전환이 확인되면 `ResetDocument()`로 프리팹의 시작 기준점을 설정한다.
- 저장 성공 시 기존 `MarkSaved()` 경로를 사용한다. 메인 씬 복귀가 성공하면 이력 대상을 되돌리고, 진입 전에 미저장 상태였다면 그 사실을 복원한다.
- 메인 씬의 이전 Undo/Redo 명령 목록을 복원하는 기능은 포함하지 않는다. 코드 및 검증 범위는 [ImplementationLog.md](ImplementationLog.md)의 2026-11-01 기록을 따른다.

Visual Studio F5 수동 확인 항목:

- [ ] 프리팹을 처음 열면 별표가 없고, 이력에 기록되는 속성을 편집하면 별표가 나타난다.
- [ ] 입력 편집을 확정한 뒤 씬 뷰에 포커스를 두고 Undo하면 시작 기준점에서 별표가 사라진다. Redo하면 다시 나타난다.
- [ ] 저장 후 추가 편집을 Undo해 저장 기준점으로 돌아오면 별표가 사라진다. 저장 상태에서 과거 상태로 Undo하면 다시 나타난다.
- [ ] 저장 기준점에서는 종료 확인이 뜨지 않고, 변경 상태에서는 저장·버리기·취소를 선택할 수 있다.
- [ ] 저장 실패에서는 편집 내용과 종료 확인창이 유지된다.
- [ ] 메인 씬이 미저장인 상태로 프리팹을 열었다가 복귀해도 메인 씬의 미저장 표시가 유지된다.
- [ ] 메인 씬이 저장된 상태였다면 프리팹 복귀 후 잘못된 미저장 표시가 생기지 않는다.

### 3단계: 원본 연결과 인스턴스 오버라이드 관리 (2026-10-31 구현 완료)

- **단일 원천 루트 전용 설계**: 데이터 중복(Single Source of Truth 위반)을 방지하기 위해 `PrefabInstanceComponent`는 프리팹 서브트리의 루트 엔티티에만 부착한다.
- **자식 엔티티 동적 판별**: `HierarchyComponent::parent`를 탐색하는 `FindPrefabRootHandle` 헬퍼를 통해 자식 엔티티도 즉시 자신의 프리팹 루트 및 원본 에셋 경로를 식별한다.
- **Hierarchy 시각화**: 프리팹 루트는 `ICON_FA_CUBES`, 자식은 `ICON_FA_CUBE`/`ICON_FA_FOLDER`와 함께 유니티 스타일 청록색(`ImVec4(0.35f, 0.78f, 1.0f, 1.0f)`)으로 강조 표시된다.
- **Hierarchy 컨텍스트 메뉴**: 루트 및 자식 엔티티 우클릭 시 `Open Prefab`, `Select in Content Browser`, `Unpack Prefab` 메뉴를 제공한다.
- **InspectorPanel 상단 프리팹 헤더 바**:
  - 루트 엔티티: `Prefab: 에셋명`, 자식 엔티티: `(Child of 에셋명)`으로 명확히 구분 표시.
  - `Open`: 클릭 시 `PrefabModeManager::Get().EnterPrefabMode`로 프리팹 뷰포트 편집 모드 즉시 진입.
  - `Select`: `SelectionManager::Get().SetSelectedAsset`으로 Content Browser에서 에셋 위치 즉시 강조.
  - `Overrides` 드롭다운 메뉴:
    - **Apply All**: 현재 인스턴스의 변경사항을 원본 `.bamprefab.json` 에셋에 덮어써서 원본 파일 갱신.
    - **Revert All**: 원본 프리팹 에셋으로부터 다시 인스턴스화하고 기존 Transform을 복원하여 원래 상태로 되돌리기.
    - **Unpack**: `world.remove<PrefabInstanceComponent>(rootHandle)`로 단번에 프리팹 연결을 해제하고 일반 독립 엔티티로 전환.
- **다국어 로캘 원본 동기화**: `Engine.csv`(컴포넌트 리플렉션) 및 `Editor.csv`(UI/메뉴/알림/히스토리)에 다국어 키 등록 완료.

- [x] 여러 번 배치해도 엔티티 ID가 충돌하지 않고, 부모 지정과 Undo/Redo가 올바르게 동작한다.

### A. 씬 문서 상태·미저장 변경 보호와 `HistoryPanel` — 우선순위 높음

- 현재 기반: `ToolBar`의 씬 생성·열기·저장·닫기, `SceneEditHistory`와 `CommandHistory`의 Undo/Redo가 있다.
  MaterialEditor에는 자체 변경 표시가 있지만, 확인한 씬 메뉴에는 공통 미저장 확인 흐름이 없다.
- 목표: 씬 경로·변경 표시·일반 저장·다른 이름으로 저장을 구분하고, 씬 교체·닫기·종료 전에 저장 여부를 확인한다.
- 이력 패널은 명령 이름·현재 위치·저장 기준점을 보여준다. 기존 Undo/Redo를 재사용하고 명령 컨테이너를 외부에서 수정하게 노출하지 않는다.
- 저장 기준점은 명령 개수만으로 판단하지 않는다. Undo 후 분기, 이력 제한, 명령을 거치지 않는 편집도 고려한다.
- 자동 백업·복구는 후속 범위다. 원본과 별도 파일, 복구 시점, 복구 실패와 보관 한도를 정의한다.
- 완료 기준: 저장 취소가 씬 교체를 취소하고, 저장 실패 시 문서와 변경 표시를 유지한다. 이력 표시와 실제 Undo/Redo가 일치한다.
- 참고: Unity의 [Undo History](https://docs.unity3d.com/6000.0/Documentation/Manual/UndoWindow.html)는 이력을 시각적으로 탐색하는 창이다.

### B. `AssetReferencePanel`과 에셋 검증 — 우선순위 높음

- 현재 기반: ResourceManagerInspector와 MetricsPanel에서 로드된 리소스와 통계를 조회한다.
  확인한 등록 패널 목록에는 에셋의 정방향·역방향 참조를 탐색하는 전용 UI가 없다.
- 목표: 선택 에셋이 사용하는 파일, 해당 에셋을 사용하는 씬·프리팹·머티리얼, 누락된 참조를 목록과 그래프로 보여준다.
- 기반 작업: 저장된 문서의 참조를 수집·색인하고 에셋 변경 시 갱신한다. 현재 로드된 핸들 목록만으로 프로젝트 전체 참조를 판단하지 않는다.
- 참조 해석 실패, 순환 관계와 동적 로드로 정적 수집할 수 없는 항목을 구분한다.
- 삭제·이동 전 영향 조회와 배포 포함 검사에 연결한다. 자동 참조 수정은 식별·검증·실패 복구 정책 이후에 구현한다.
- 완료 기준: 알려진 씬 → 머티리얼 → 텍스처 관계를 양방향으로 찾고, 누락된 파일의 사용 위치를 표시한다.
- 참고: Unreal의 [Reference Viewer](https://dev.epicgames.com/documentation/en-us/unreal-engine/reference-viewer-in-unreal-engine)는 에셋 참조 그래프와 참조·역참조 조회를 제공한다.

### H. `AnimatorGraphPanel` (애니메이터 그래프 및 상태 머신 에디터) — P3 목표

- 상세 계획: [AnimatorGraphPlan.md](AnimatorGraphPlan.md) Phase 4.
- 현재 기반: `Editor/Source/ImGui/GraphPanel/`에 `imgui-node-editor` 기반 줌/패닝, 노드 배치 및 링크 시각화 인프라가 구축되어 있음.
- 목표:
  1. **상태 머신 캔버스:** `Entry`, `Any State`, 상태 노드(`AnimState`)를 배치하고 노드 간 드래그로 트랜지션 화살표(Transition Wire)를 연결한다.
  2. **트랜지션 및 상태 인스펙터:** 상태 노드 선택 시 클립 핸들·루프·재생 속도를 지정하고, 트랜지션 선택 시 지속 시간(`Duration`), 종료 시간(`Exit Time`) 및 파라미터 조건식 테이블을 편집한다.
  3. **파라미터 독(Dock):** `Float`, `Int`, `Bool`, `Trigger` 파라미터를 추가·삭제하고, PIE 실행 중 슬라이더/체크박스로 실시간 값을 변경해 전이를 즉시 테스트한다.
  4. **실시간 디버깅 및 프리뷰:** PIE 실행 중 현재 활성화된 상태 노드에 발광 테두리를 표시하고, 패널 내부 독립 3D 뷰포트를 통해 메인 씬 영향 없이 애니메이션 재생 결과를 즉각 확인한다.
- 완료 기준: `AnimatorGraphAsset` 파일을 생성·편집하고 JSON으로 저장·복원할 수 있으며, PIE에서 활성 상태 및 전이 과정이 실시간으로 시각화된다.

## 12. 확장 목표의 권장 진행 순서

아래는 Editor 기능 내부 순서다. 다른 계획과의 작업 선택·보류 조건은 통합 우선순위 계획을 따른다.
미저장 보호·공통 설정·기본 에셋 판정/캐시 예산을 P1으로 우선하고, 전용 패널보다 필요한 런타임 계약을 먼저 연결한다.

1. 현재 설정·뷰포트 저장 코드의 빌드와 재실행 검증을 마무리한다.
2. `GraphicsSettingPanel`과 씬 문서의 미저장 보호를 구현한다.
3. 17절의 엔티티 복사·붙여넣기를 기존 선택·편집 이력에 연결하고, 프리팹 만들기·배치 후 `PrefabEditorPanel`의 독립 편집·저장 흐름을 완성한다.
4. 14절의 공통 타입 판정·열기 경로와 미리보기 비용 제한부터 정리하고, 리소스 검색·썸네일 선택을 연결한다.
5. 에셋 참조 조회와 임포트 옵션 저장·재임포트를 연결한다.
6. 안정된 프리팹 식별·인스턴스 연결을 마련하고 변경값 비교·적용·되돌리기를 추가한다.
7. 프로젝트 설정·게임 입력 액션·상세 프로파일링을 실제 사용 요구에 따라 진행한다.
8. 파티클·스플라인은 15절의 최소 런타임·저장·편집 흐름부터 만들고, 같은 타입 분류와 썸네일 경로에 연결한다.
9. 빌드·패키징 UI는 해당 단계에서, 애니메이션·중첩 프리팹·Variant는 필요한 런타임 기반 이후에 진행한다.

이 순서는 제안이다. 다른 엔진에 있다는 이유만으로 모든 창을 먼저 만들지 않는다.
각 항목은 사용자가 수행할 작업, 필요한 데이터·API, 저장 위치와 실패 경로를 먼저 정한 뒤 구현한다.

## 13. 추가 목표의 공통 기준과 확인 범위

- 기존 Inspector·Hierarchy·Content Browser·명령 이력·리플렉션 직렬화를 재사용하고, 패널마다 동일 기능을 복제하지 않는다.
- 새로 제안한 패널과 기반 API의 이름은 구현 완료 표시가 아니다.
- 콘텐츠, 프로젝트 설정, 사용자 작업 상태와 일시적인 실행 상태의 소유자·저장 위치를 구분한다.
- 고정 UI 문구의 영어·한국어 로캘 키, 안정된 ImGui ID와 InputManager 사용을 각 기능에 함께 적용한다.
- 정상 흐름과 함께 취소·저장 실패·잘못된 파일·사라진 에셋·씬 교체·PIE 반복 진입을 확인한다.
- 다른 엔진 자료는 기능의 사용 흐름을 참고한 것이다. 같은 내부 구조나 기능 전체를 복제할 요구로 해석하지 않는다.

이번 확장에서는 등록 패널 목록, 프리팹 Archive, 씬 메뉴, 명령 이력, 임포트·리소스·통계 코드를 정적으로 확인했다.
전용 패널이나 연결을 찾지 못한 항목을 저장소 전체의 절대적인 미구현 증명으로 사용하지 않는다.
빌드·테스트·실제 프리팹 및 다른 엔진 UI 실행 검증은 수행하지 않았다.

## 14. 콘텐츠 브라우저 열기·타입별 표시와 리소스 선택

### 현재 기반과 부족한 연결

- `ContentBrowserGridItem.cpp`의 `HandleItemDoubleClick()`은 폴더 이동, 씬 JSON 로드와 지원하는 내부 리소스 에디터 열기를 처리한다.
  내부 에디터가 지원하지 않는 파일을 외부 에디터로 여는 공통 경로와 명시적인 외부 열기 메뉴는 확인되지 않았다.
  현재 `탐색기에서 표시`는 파일 편집과 다른 동작이다.
- `AssetCache`는 이미지 디코딩과 일부 원본 모델의 Windows Shell 미리보기 요청을 비동기로 처리한다.
  이미지의 `Width`·`Height`를 그대로 GPU 텍스처에 사용하며, 축소·캐시 용량·프레임별 업로드 예산은 확인되지 않았다.
  모델 미리보기는 시스템의 해당 형식 지원 여부에 영향을 받는다.
- `ContentBrowserPanel`의 필터와 그리드 아이콘은 주로 확장자 분기다.
  컨텍스트 메뉴에는 `AssetHeader.ResourceType` 조회와 JSON↔바이너리 변환이 있지만, 공통 타입별 미리보기·분류로 연결되지는 않았다.
- `ResourcePicker.h`의 `DrawInspectorResourcePicker()`는 로드된 리소스의 스냅샷을 순회해 호환 타입을 텍스트로 보여준다.
  컴포넌트 리소스 편집에 사용되지만 검색·썸네일과 아직 로드하지 않은 프로젝트 에셋의 선택 연결은 없다.
- 브라우저 검색은 Enter 입력 시 루트 아래를 동기 재귀 탐색한다.
  `DrawGrid()`는 검색 결과가 비어 있으면 현재 폴더 목록을 보여주므로, 검색 결과 없음과 폴더 탐색을 명확히 구분할 필요가 있다.

위 내용은 2026-10-24의 관련 소스 정적 확인 결과다. 아래 항목은 구현 계획이며 성능·UI 동작의 검증 결과가 아니다.

### A. 더블클릭과 컨텍스트 메뉴의 열기 동작

- 더블클릭과 컨텍스트 메뉴의 `열기`는 같은 기본 동작 판정을 사용한다.
  폴더는 이동하고, 지원하는 엔진 에셋은 내부 에디터로 열며, 소스·문서·외부 제작 파일은 연결된 외부 에디터로 연다.
- 파일 컨텍스트 메뉴에 `외부 에디터로 열기`를 별도로 제공한다. 내부 에디터 지원 파일도 필요할 때 명시적으로 외부 열기를 선택할 수 있다.
  OS 기본 연결을 우선 사용하고, 특정 프로그램 지정이 필요하면 실행 파일·인자 설정의 저장 위치를 정한다.
- 외부 도구가 필요한 원본 파일과 엔진이 생성한 에셋을 구분한다. 원본 연결이 있으면 `원본을 외부 에디터로 열기`를 제공하고 실제 대상 경로를 보여준다.
  바이너리 에셋을 텍스트 편집기에 자동으로 보내거나, 원본 연결 없이 같은 이름의 파일을 임의로 추정하지 않는다.
- 존재하지 않는 경로·연결 프로그램 없음·실행 실패를 알리고, 경로의 한글·공백·따옴표를 처리한다.
  플랫폼의 파일 열기 API를 사용하고 경로를 셸 명령 문자열에 단순 연결하지 않는다.
- 씬·프리팹 교체와 내부 에디터 대상 변경은 11절 A의 미저장 보호 흐름을 거친다.
  외부에서 저장된 결과는 기존 변경 감지·재임포트·핫 리로드 정책에 따라 갱신한다.
- 기본 열기 정책과 명시적 외부 열기를 구분하되, 타입마다 같은 로직을 더블클릭·메뉴에 복제하지 않는다.

### B. 컴포넌트 리소스 핸들의 검색·썸네일 선택

- Inspector의 현재 리소스 핸들에 작은 썸네일 또는 타입 아이콘, 이름과 상태를 표시한다.
  미선택·누락된 참조·로딩 중·미리보기 미지원·실패를 구분하며, 이미지가 없다는 이유로 유효한 핸들을 해제하지 않는다.
- 선택 팝업은 검색 입력과 썸네일 목록 또는 그리드를 함께 제공한다.
  이름·프로젝트 상대 경로로 검색하고, 같은 이름의 에셋은 상대 경로로 구분한다. 검색 결과 없음도 별도 표시한다.
- `ResourceHandle<T>`에 할당 가능한 타입으로 후보를 제한한다. 파일의 타입 판정과 실제 로드·할당 시의 호환성 검사를 함께 유지한다.
  - **핸들 타입별 호환 확장자 필터링**: `DrawInspectorResourcePicker<T>`에서 템플릿 인자 `T`(`Texture`, `Material`, `Model`, `Audio` 등)에 일치하는 확장자 파일만 디스크 목록에 노출하여 무관한 에셋 노출을 차단한다.
  - **팝업 진입 시 1회 스캔 및 정적 캐싱**: 팝업이 열려 있는 동안 매 프레임 `recursive_directory_iterator`로 디스크 전체를 동기 순회하여 발생하는 치명적인 프레임 드랍을 방지한다. 팝업이 열리는 첫 프레임에만 1회 스캔하여 캐시 리스트를 구성하고, 팝업이 닫힐 때 해제하거나 색인 기반으로 조회한다.
  - 기존 드래그 앤 드롭과 연결 해제를 유지하고, 읽기 전용·다중 선택의 혼합값도 기존 Inspector 편집 경로와 일치시킨다.
- 초기에는 로드된 리소스를 대상으로 검색·썸네일을 연결하고, 다음 단계에서 프로젝트 에셋의 메타데이터 색인으로 범위를 넓힌다.
  로드된 목록과 프로젝트 전체 목록의 지원 범위를 표시하며, 후보를 보여주기 위해 모든 리소스를 실제로 로드하지 않는다.
- 선택을 확정한 후보만 필요한 로드를 수행한다. 비동기 로드 중 실패·취소·대상 컴포넌트 삭제·씬 교체가 발생해도 기존 값을 보존한다.
- 변경은 기존 리플렉션 속성 편집·Undo/Redo 경로에 연결한다. 팝업 표시나 미리보기 생성은 컴포넌트 변경 명령을 만들지 않는다.
- 브라우저와 선택 팝업은 타입 정보·썸네일 캐시를 재사용한다. 팝업별 검색어·선택 상태는 속성의 안정된 ImGui ID로 구분한다.

### C. 데이터 타입별 분류와 바이너리 에셋 미리보기

- 저장 형식과 콘텐츠 타입을 구분한다. JSON·BEVE·전용 바이너리 확장자라는 이유만으로 모두 일반 데이터 아이콘으로 표시하지 않는다.
  지원하는 엔진 에셋은 `AssetHeader` 등 기존 메타데이터로 실제 타입을 판정하고, 일반 파일은 알려진 확장자로 분류한다.
- 목록 열기·필터·검색·아이콘·툴팁·내부 에디터 선택이 같은 타입 판정 결과를 사용하도록 작은 공통 경로부터 정리한다.
  기존 `PeekResourceType()`처럼 Archive 문서를 읽는 처리를 모든 항목의 매 프레임 그리기에 넣지 않는다.
- 리소스 헤더의 MagicNumber·타입·버전과 파일 읽기 실패를 검증한다.
  타입을 알 수 없음·손상됨·지원하지 않는 버전을 구분하며, 분류를 위해 원본을 변환하거나 덮어쓰지 않는다.
- 다음 타입은 실제 내용을 대표하는 정적 썸네일을 우선 제공한다.
  - 텍스처·스프라이트: 이미지 또는 지정 영역. 원본 이미지와 엔진 바이너리 모두 지원 범위를 명시한다.
  - 메시·모델: 경계에 맞춘 고정 카메라의 정적 렌더. Shell 미리보기 제공 여부에만 의존하지 않는다.
  - 머티리얼·인스턴스: 공통 미리보기 메시를 렌더하며 인스턴스의 실제 파라미터를 반영한다.
  - 씬·프리팹: 저장 시점 또는 명시적 갱신으로 만든 대표 이미지. 썸네일 요청만으로 메인 씬을 교체하지 않는다.
  - 파티클: 고정 시드·제한된 예열 시간의 대표 프레임. 전 항목을 계속 시뮬레이션하지 않는다.
  - 스플라인: 제어점·곡선과 경계를 작은 정적 이미지로 표시한다.
- 파티클·스플라인을 타입 필터·별도 아이콘·색상·타입 배지와 생성·열기 메뉴에 추가한다.
  현재 `EResourceType`에는 두 항목이 없으므로 데이터·저장 정책을 먼저 정한다.
  독립 에셋이면 타입 등록을 추가하고, 씬 전용 데이터면 관련 컴포넌트 편집과 씬 미리보기에 연결한다.
  저장된 enum 값의 의미가 바뀌지 않게 하며 확장자·파일 포맷 이름은 구현 시 확정한다.
- 시각적 표현이 없거나 미리보기가 준비되지 않은 셰이더·스크립트·오디오·스켈레톤·일반 데이터는 타입 아이콘·이름·배지로 구분한다.
  파형·골격·클립 포즈 등 추가 표현은 실제 데이터와 비용이 확인될 때 확장한다. 미지원 상태와 생성 실패를 동일하게 처리하지 않는다.
- 바이너리도 해당 타입의 지원하는 읽기 경로로 미리보기를 만든다. JSON으로 변환하는 작업을 표시의 전제 조건으로 삼지 않는다.
  썸네일·색인은 재생성 가능한 Editor 캐시로 관리하고, 실행용 에셋이나 컴포넌트의 영속 핸들에 GPU 미리보기 자원을 저장하지 않는다.

### D. 검색·썸네일의 성능과 자원 수명 기준

- 화면에 보이는 행·타일부터 미리보기를 요청하고 행 단위 클리핑을 적용한다. 필요하면 작은 선행 로딩 범위를 둔다.
  폴더 전체나 검색 결과 전체에 한 번에 디코딩·렌더 작업을 예약하지 않는다.
- 브라우저와 선택 팝업이 같은 요청을 공유하도록 중복을 억제하고, 대기열·동시 작업 수·디코딩 메모리에 상한을 둔다.
  빠른 스크롤·검색어 변경·팝업 종료 시 요청의 우선순위를 조정하거나 불필요한 대기 작업을 취소한다.
- 썸네일 해상도에 맞춰 축소하고, 과도한 이미지 크기와 임시 디코딩 메모리를 제한한다.
  원본 해상도 텍스처를 전 항목에 보관하지 않는다. 사전 생성·축소본 활용과 제한된 작업 수를 함께 검토한다.
- CPU 파일 읽기·디코딩과 GPU 생성·업로드의 실행 스레드를 구분한다.
  프레임별 GPU 업로드 바이트·작업 수와 미리보기 렌더 시간에 예산을 두고, 완료된 모든 작업을 한 프레임에 처리하지 않는다.
- CPU·GPU 캐시의 항목 수·바이트 상한과 축출 정책을 정한다. 사용 중인 ImGui 텍스처 ID와 GPU 작업의 완료 시점을 고려해 안전하게 해제한다.
- 파일 변경·재임포트·이동·삭제와 의존 리소스 변경 시 관련 캐시를 무효화한다.
  작업 세대 또는 버전을 확인해 오래된 비동기 완료 결과가 새 썸네일을 덮어쓰지 않게 한다.
  파일 감시 콜백은 변경 정보를 전달하고, 캐시 수정·GPU 해제는 정한 소유 스레드에서 수행한다.
  종료 시에는 진행 중 작업·콜백을 정리한 뒤 캐시 소유자를 파괴한다.
- 미지원·실패 결과도 캐시하되 파일 변경이나 명시적 재시도로 복구할 수 있게 한다. 매 프레임 같은 실패 요청을 다시 제출하지 않는다.
- 검색은 입력 변경을 모아 처리하고, 프로젝트 목록·타입 정보를 캐시하거나 색인한다.
  작은 프로젝트는 기존 폴더 캐시부터 활용하고, 대규모 탐색이 필요하면 비동기 갱신·취소·오래된 결과 폐기를 추가한다.
  `GetDebugSnapshot()` 전체 복사·후보 정렬·파일 파싱을 변경 없는 매 프레임 반복하지 않는다.
- 파티클 등 움직이는 미리보기는 선택·호버한 제한된 항목에서 명시적으로 제공한다.
  비활성 패널·숨겨진 항목·PIE 부하 상황의 갱신 빈도를 제한하고, 기본 브라우저 표시는 정적 캐시를 사용한다.
- 예산 수치는 구현 시작 시 기준 장비·에셋 수·파일 크기별 측정으로 확정한다.
  콜드·웜 캐시의 UI 프레임 시간(p95·p99), 검색 응답 시간, 대기열 크기, CPU·GPU 메모리와 업로드량을 비교한다.
  비동기로 동작하거나 육안으로 부드럽다는 이유만으로 성능 완료로 판단하지 않는다.

### E. 콘텐츠 브라우저 검색 범위 선택

- 검색 범위를 `전체 리소스 폴더`와 `현재 선택한 폴더` 중에서 선택할 수 있게 한다.
  전체 검색은 프로젝트의 리소스 루트(`m_RootPath`), 현재 폴더 검색은 브라우저에서 열어 둔 폴더(`m_CurrentDirectory`)를 기준으로 하며 두 범위 모두 하위 폴더를 포함한다.
  현재 폴더는 검색창의 키보드 포커스나 검색 결과에서 선택한 파일이 아니라 폴더 트리·주소 표시줄의 탐색 위치를 의미한다.
- 검색창 옆에 선택한 범위와 기준 폴더를 표시한다. 결과에는 기준 폴더에서의 상대 경로를 함께 보여 같은 이름의 에셋을 구분한다.
  범위 선택·기준 폴더·검색 상태 문구는 기존 로캘 경로를 사용한다.
- 검색 범위를 바꾸면 입력한 검색어와 타입 필터를 유지한 채 새 범위에서 다시 검색한다.
  현재 폴더 범위에서는 탐색 폴더가 바뀔 때 같은 검색어로 다시 검색하고, 전체 범위에서는 폴더 이동만으로 검색 기준을 바꾸지 않는다.
- 검색 요청에는 범위·기준 폴더·검색어·필터의 스냅샷을 사용한다. 비동기 처리에서는 조건이 바뀐 이전 요청의 결과를 취소하거나 폐기해 새 결과를 덮어쓰지 않게 한다.
  검색창 포커스 이동이나 패널 재그리기만으로 전체 재검색을 반복하지 않으며, 작업량 제한은 D절을 따른다.
- 빈 검색어는 일반 폴더 탐색으로 돌아가고, 검색 결과가 없으면 선택한 범위의 결과 없음을 표시한다.
  결과가 없다는 이유로 다른 범위나 현재 폴더 전체 목록으로 자동 전환하지 않는다.

### 구현 순서와 완료 검증

1. 타입 판정·기본 열기·외부 열기 메뉴를 연결하고, 검색 범위 선택·범위 변경 시 재검색·검색 결과 없음의 표시를 정리한다.
2. 기존 이미지 캐시의 축소·예산·무효화·수명 처리를 먼저 보완한다.
3. 로드된 리소스의 검색·썸네일 선택을 연결한 뒤 프로젝트 에셋 색인으로 확장한다.
4. 바이너리 텍스처·스프라이트·머티리얼·메시부터 타입별 미리보기를 추가한다.

## 15. 파티클·스플라인 제작 기능

Engine의 파티클·스플라인·레이캐스트·트레일·애니메이션·상태 그래프·스크립트 실행 계획은
[EngineDevelopmentPlan.md](EngineDevelopmentPlan.md)에서 관리한다. 이 절은 해당 기반을 사용하는 편집·미리보기 목표와 연결한다.

2026-10-24의 `Engine/Source`·`Editor/Source` 파일 및 심볼 검색에서는 파티클·스플라인의 전용 데이터·실행 시스템·편집기를 확인하지 못했다.
스프라이트 빌보드 관련 주석은 파티클 시스템의 구현 근거로 삼지 않는다. 별도 이름이나 외부 모듈의 구현 여부는 재개 시 다시 확인한다.
두 기능은 모든 게임에 필수인 기반은 아니지만, 이펙트와 경로 제작에 필요한 목표로 추가한다. 썸네일 표시와 실제 기능 구현의 완료를 구분한다.

### 파티클

- 처음에는 단일 이미터의 생성률·최대 개수·수명·초기 위치·속도·크기·색·텍스처·루프와 난수 시드를 지원한다.
  CPU 시뮬레이션과 기존 렌더링 경로부터 검토하고, GPU 시뮬레이션은 측정된 요구가 있을 때 별도 확장한다.
- 재사용하는 효과 설정과 실행별 파티클 상태를 분리한다. Editor 미리보기와 PIE·Client가 같은 실행 규칙을 사용한다.
- Inspector 또는 전용 편집기에서 재생·정지·초기화·제한된 예열·저장과 Undo/Redo를 제공한다.
  미리보기는 메인 씬을 변경하지 않고, 저장 대상에 실행 중 파티클 목록과 GPU 버퍼를 포함하지 않는다.
- 최대 파티클·이미터·업데이트 비용을 제한하고, 풀 재사용·경계·컬링·투명 오버드로를 측정한다.
  화면 밖에서 멈추거나 저빈도로 갱신할 때 재등장 결과와 시간 진행 정책을 명시한다.
- 완료 기준: 저장 후 재실행·PIE 반복·Client에서 같은 설정을 해석하고, 초기화·종료 시 실행 상태가 남지 않는다.
  개수 제한과 프레임 비용을 검증한 뒤 14절의 정적 썸네일·타입 필터에 연결한다.

### 스플라인

- 먼저 실제 용도를 경로·카메라 이동·형상 생성 중 하나로 정하고, 지원할 곡선 표현과 열린 경로·닫힌 경로의 의미를 확정한다.
  제어점·접선·좌표계와 위치·접선 평가부터 구현한다. 거리 기반 이동이 필요하면 호 길이 근사와 정확도·비용을 함께 정한다.
- Inspector의 제어점 목록과 뷰포트 기즈모를 연결하고, 추가·삭제·이동·Undo/Redo·저장·복원을 제공한다.
  데이터가 엔티티 로컬 좌표인지 월드 좌표인지 명시하고 부모 Transform 변경 시의 결과를 확인한다.
- 곡선·거리 표·표시용 선분은 제어점이나 관련 Transform이 변경됐을 때 필요한 부분만 갱신한다.
  분할 수·근사 오차·캐시 메모리에 한도를 두고, 매 프레임 전체 경로를 재샘플링하지 않는다.
- 제어점 없음·한 점·중복점·길이 0·끝점·루프 이음부의 결과를 정한다.
  완료 기준: 저장·복원과 편집·실행 평가가 일치하고, 관련 변경 시 캐시·기즈모·정적 썸네일이 함께 갱신된다.

## 16. 빠진 기능을 판단하는 우선순위

모든 게임엔진에 파티클·스플라인·내비게이션 등 같은 기능이 반드시 필요한 것은 아니다.
BamEngine의 우선 기준은 작은 게임의 제작·저장·실행·배포 흐름을 안전하게 끝낼 수 있는가다.
다음은 이번에 확인한 연결 부족과 기존 계획의 우선순위이며, 엔진 전체 기능 감사 결과는 아니다.

1. **편집 데이터 보호:** 확인한 씬 생성·열기·닫기 경로에는 공통 미저장 확인 흐름이 없다.
   11절 A의 변경 추적·저장 실패 보존부터 연결하고, 자동 백업·복구를 다음 단계로 둔다.
2. **에셋 참조와 제작 흐름:** 기존 로더·핸들·임포트를 활용하면서, 11절 B·C와 14절의 참조 색인·누락 검사·재임포트·타입별 탐색을 보완한다.
   특히 현재 브라우저의 직접 삭제·이름 변경은 참조 영향 조회와 함께 검토한다.
3. **실제 배포:** Client 시작 씬은 현재 코드에서 고정 경로를 사용하며, 프로젝트 설정 연결과 저장소 밖 실행은 별도 검증이 필요하다.
   기존 결정대로 [BuildAndPackagingPlan.md](BuildAndPackagingPlan.md)의 작업 단계에서 진행한다.
4. **게임 제작 기반의 연결:** 프리팹 제작 UI·안정된 인스턴스 연결, 게임 입력 액션과 CPU·GPU 시간 측정을 기존 계획에 따라 보완한다.
   기반 데이터나 호출 횟수가 존재한다는 이유만으로 편집·실행·측정 흐름의 완료로 판단하지 않는다.
5. **콘텐츠 표현:** 파티클·스플라인과 애니메이션 재생·편집은 대상 게임의 요구에 맞춰 진행한다.
   현재 Animation 리소스의 트랙 데이터만으로 스키닝·보간·블렌딩·타임라인이 구현됐다고 판단하지 않는다.
   내비게이션·네트워크 등은 이번 문서에서 미구현으로 확정하지 않으며, 실제 필요와 관련 코드 검토 후 별도 계획을 정한다.

이번 변경은 이 개발 플랜의 목표·작업 순서·검증 기준만 추가한 것이다. C++ 코드·로캘 데이터·빌드 산출물은 변경하지 않았고 빌드·테스트·성능 측정은 실행하지 않았다.

## 17. 엔티티 다중 복사·붙여넣기

- 추가일: 2026-10-31 (2026-10-31 구현 완료).
- 상태: 구현 완료 / 세션 내 다중 복사·붙여넣기 및 Undo/Redo 연동 완료.
- 범위: 씬의 엔티티와 하위 계층 복사·붙여넣기다. 블루프린트 노드의 클립보드 기능과 구분한다.

### 현재 기반과 재사용 범위

- `SelectionManager::GetSelectedEntities()`와 Hierarchy의 다중 선택, `SceneEditHistory`·`SceneEditSnapshot`의 생성·삭제 이력을 재사용한다.
- `EntityClipboard`(`Editor/Source/Clipboard/`): `archive::JsonArchive` 메모리 직렬화 기반으로 선택된 엔티티 서브트리를 스냅샷으로 보관한다.
- 원본 엔티티가 파괴되거나 편집되어도 클립보드 데이터의 독립성이 보장된다.

### 1단계: 같은 씬에서 다중 엔티티 복사·붙여넣기 (구현 완료)

- **조상 필터링 (중복 방지)**: Hierarchy에서 부모와 자식이 동시에 선택된 경우, 조상 노드만 복사 루트로 선별하여 자식이 중복 복제되지 않도록 필터링한다.
- **원래 계층 및 형제 순서 보존**: 복사된 서브트리 내부의 부모-자식 관계와 형제 순서가 완벽히 보존된다.
- **새 ID 자동 발급**: 붙여넣기 시 `Scene::CreateEntities`를 통해 고유한 영구 엔티티 ID를 새로 발급하여 ID 충돌을 원천 차단한다.
- **단일 원자적 Undo/Redo**: 여러 개의 엔티티가 한 번에 붙여넣어지더라도 `UI_HISTORY_PASTE` 단일 스냅샷으로 묶여 `Ctrl+Z` 한 번으로 일괄 제거되고 `Ctrl+Y`로 일괄 복원된다.
- **붙여넣기 후 자동 선택**: 생성된 신규 루트 엔티티들이 자동으로 선택되어 붙여넣기 직후 바로 기즈모 조작이 가능하다.
- **단축키 및 메뉴 연동**:
  - `Ctrl+C`: 선택된 엔티티 복사 (`EditorCommon.Copy`)
  - `Ctrl+V`: 동일 부모 또는 씬 루트에 붙여넣기 (`EditorCommon.Paste`)
  - `Ctrl+Shift+V`: 선택한 엔티티의 자식으로 붙여넣기 (`UI_HIERARCHY_PASTE_AS_CHILD`)
- **계층 패널 다중 삭제 지원**: `Delete` 키 및 컨텍스트 메뉴를 통한 `EntityHierarchyAction::DeleteEntities` 다중 일괄 삭제 기능도 함께 완성되었다.

### 후속 범위와 완료 검증

다른 씬·프리팹 편집 세션으로 붙여넣기는 문서 간 리소스 해석, 외부 엔티티 참조와 클립보드 수명 정책을 마련한 뒤 확장한다.
잘라내기·즉시 복제는 첫 단계의 필수 범위에 포함하지 않는다.

- [x] 단일·다중 루트, 부모·자식 동시 선택에서 중복 없이 계층·형제 순서·컴포넌트·Transform이 보존된다.
- [x] 반복 붙여넣기에 ID 충돌이 없고 새 엔티티가 올바르게 생성된다.
- [x] 복사 후 원본 수정·삭제 후에도 클립보드 메모리 버퍼를 통해 안전하게 붙여넣어진다.
- [x] 붙여넣기 한 번을 한 번의 Undo로 제거하고 Redo로 복원하며, 이력 스택이 일치한다.
- [x] 계층 패널의 키보드 `Delete` 및 다중 삭제가 부모-자식 충돌 없이 안전하게 동작한다.
- [x] 다국어 키 등록 및 단축키 바인딩이 완료되었다.

- 관련 문서: [GraphPanel.md](GraphPanel.md), [GraphExecution.md](GraphExecution.md), [VisualScriptingBlueprintPlan.md](VisualScriptingBlueprintPlan.md) Phase 4.2.

### 현재 코드에서 확인한 문제

- `GraphPanel::Draw()`는 `DrawToolbar()`·`DrawFileToolbar()`·`DrawDebugToolbar()`·`DrawShaderToolbar()`·`DrawExecutionToolbar()`를 순서대로 호출한다.
  개별 함수가 줄 시작·`SameLine()` 배치를 결정하므로 전체 상단의 행 구성과 간격을 한곳에서 파악하기 어렵다.
- 공통 행에는 도메인·노드 추가·검사·화면 맞춤·삭제·와이어 모드가 함께 있다. 파일 행에는 저장·다른 이름으로 저장·열기·전체 경로가 있고,
  Logic의 `DrawDebugToolbar()`는 `SameLine()`으로 이 행 뒤에 디버그 엔티티 선택기를 붙인다. 긴 경로·이름·번역에 따른 폭 부족에 대응하는 분기는 확인되지 않았다.
- Logic의 패널 내부 실행 미리보기와 씬 엔티티의 PIE 실행 관찰이 별도 조작 묶음이라는 표시가 부족하다.
  Shader 행도 HLSL 생성·DXIL/SPIR-V 검사·미리보기·머티리얼 검사·런타임 머티리얼 생성이 같은 수준의 버튼으로 나열된다.
- 와이어 모드 버튼·툴팁과 디버그 대상 안내에는 고정 영어 문구가 남아 있다. 이번 수정 범위에서 로캘 키로 정리한다.

위 내용은 관련 소스의 정적 확인이다. 실제 화면의 겹침·잘림 여부와 사용 가능한 최소 폭은 UI에서 별도 확인한다.

### 권장 배치와 기능 분류

- 상단은 **공통 도구 행 + 도메인별 도구 행**을 기본으로 한다. 각 행의 시작·그룹 간격·남은 폭은 상위 배치 코드가 결정한다.
  자식 그리기 함수가 앞선 행의 마지막 항목에 임의로 이어 붙이지 않도록 호출 계약을 정리한다.
- 공통 행에는 도메인 선택, 열기·저장, 노드 추가·검사·화면 맞춤을 우선 노출하고 문서·편집·보기 메뉴로 기능을 묶는다.
  다른 이름으로 저장은 문서 메뉴, 선택 삭제는 편집 메뉴와 기존 컨텍스트 메뉴, 와이어 스타일은 보기 메뉴의 명시적인 선택 목록으로 옮긴다.
  와이어 스타일은 반복 클릭으로 순환하기보다 현재 선택과 세 가지 후보를 함께 알 수 있게 한다.
- Logic의 도메인 행에서는 `실행 미리보기`와 `PIE 관찰`을 구획과 라벨로 구분한다.
  미리보기는 진입점·실행/재개·일시정지·한 단계·중지를 묶고, 인스턴스 초기화와 실행 예산·간격 등 상세 설정은 해당 메뉴 또는 기존 오른쪽 추적 영역에 둔다.
  PIE 관찰은 대상 엔티티와 관찰 가능 상태를 표시한다. 미리보기 버튼이 게임 전체를 제어하는 것처럼 보이지 않게 한다.
- Shader의 도메인 행은 컴파일·미리보기를 우선 노출한다. HLSL 생성과 DXIL/SPIR-V 대상별 검사는 빌드 메뉴로 묶고,
  머티리얼 검사·런타임 머티리얼 생성은 별도 머티리얼 메뉴로 묶는다. 기존 동작과 지원 범위를 유지하며 서로 다른 검사를 하나의 성공 상태로 합치지 않는다.
- 전체 파일 경로·상세 오류·컴파일 안내는 버튼 사이에서 빼고 기존 하단 상태 영역과 오른쪽 진단·빌드 상세 영역을 사용한다.
  파일은 짧은 이름과 전체 경로 툴팁으로 식별하고, 같은 이름의 파일도 경로를 확인할 수 있게 한다. 미저장 표시는 실제 변경 추적에 연결된 경우에만 표시한다.
- 패널 폭이 부족하면 우선순위가 낮은 작업을 `더 보기` 메뉴로 옮긴다. 무제한 자동 줄바꿈이나 가로 스크롤을 기본 해결책으로 삼지 않는다.
  극도로 좁은 폭에서는 도메인별 도구도 메뉴로 축약하되 현재 도메인·실행 상태와 중지 기능에 접근할 수 있어야 한다.
  배치 기준은 현재 글꼴·UI 배율·번역된 항목의 실제 크기를 사용하고 고정 픽셀 간격에 의존하지 않는다.

### 구현 순서와 책임

1. 현재 버튼·선택기·상태 문구의 이동 위치를 확정하고 Logic/Shader 각각의 기본 폭·좁은 폭 배치를 확인한다.
2. 기존 `GraphPanel`의 상단 배치와 작은 그리기 함수부터 정리한다. 저장·열기·검사·실행·컴파일 함수와 문서 상태를 재사용하고, 이번 UI 정리를 위해 범용 툴바 관리자나 새 실행 상태 소유자를 만들지 않는다.
3. 메뉴와 버튼의 실행 가능 조건·실행 경로를 공유한다. 실행 중·선택 없음·PIE 미실행·지원하지 않는 컴파일 대상은 기존 기능의 조건을 확인해 비활성화하고 이유를 안내한다.
4. 로캘과 폭 대응을 적용한 뒤 실제 도킹·분리 창에서 기존 작업 흐름을 회귀 확인한다. `GraphPanel.md`·`GraphExecution.md`의 조작 안내는 실제 구현 후 갱신한다.

필요한 새 메뉴·상태·툴팁 키는 기존 `GraphPanel.*` 키를 먼저 확인하고 `Editor.csv`에 영어·한국어를 함께 등록한다.
번역 표시와 ImGui ID를 분리한다. 이번에 추가·수정하는 단축키는 기존 `ShortcutManager`·`InputManager` 경로를 사용하고,
그래프 포커스·텍스트 입력·팝업·노드 드래그 문맥을 확인한다. 메뉴 재배치로 기존 단축키를 중복 등록하지 않는다.
