## 1. 목표와 우선순위

기존 래스터라이징 렌더러를 기준 경로로 유지하면서, 측정 가능한 단계로 현대적인 렌더링 기술을 도입한다.
단기에는 정확성과 측정 기반을 확보하고, 중기에는 많은 물체·광원 처리와 하이브리드 레이트레이싱을 확장한다.
장기에는 가상화와 고급 샘플링 기술을 실제 요구에 맞추어 연구한다.

단기·중기·장기는 확정된 주·월 단위 일정이 아니라 선행 조건과 구현 규모에 따른 구분이다.
다른 기능과의 작업 선택은 통합 우선순위 계획을 따른다. S1/S2는 P1, S3/S4/S5는 P2,
M1~M4는 조건부 P3, M5·L 계열은 P4로 대응한다. S6의 기본 반투명 합성 확인은 P2, 유리·수면·파도는 조건부 P3로 진행한다.
각 항목은 제안된 목표이며, 모든 기술을 필수 기능으로 일괄 구현하지 않는다.
측정에서 효과가 없거나 현재 콘텐츠에 필요하지 않으면 보류하고 근거를 남긴다.

- 단기: 계측 → 바인딩·기능 지원 범위 정리 → 인스턴싱·LOD → Compute 실행 기반 → 다수 광원 처리.
- 중기: GPU Driven Rendering을 확장하고, 화질 개선 경로로 DXR 그림자·반사와 프로브 GI를 단계적으로 도입한다.
- 장기: Mesh Shader 경험을 바탕으로 가상화 지오메트리를 실험하고, 필요에 따라 VSM·ReSTIR·패스 트레이싱을 검토한다.

GPU Driven과 DXR은 별도의 발전 경로다. Bindless나 Mesh Shader를 DXR의 필수 선행 조건으로 만들지 않는다.
IBL처럼 비교적 독립적인 화질 개선은 측정·바인딩 기반이 마련되면 병행할 수 있다.

## 2. 현재 출발점: 소스에서 확인한 범위 (2026-11-01 갱신)

다음 내용은 2026-11-01 시점 작업 트리의 정적 확인 및 S1·S3·S4 실측 검증 결과다.

- **S1 (CPU/GPU 계측 — 코드 구현 및 실측 확인 완료)**:
  - `RHIFrameMetrics.h`에 패스별 CPU/GPU 시간(`RHIPassMetric`), 하드웨어 지원(`RHICapabilities`), VRAM/디스크립터 통계(`RHIMemoryStats`) 구조 확장이 완료되었다.
  - `DirectX12RHI.cpp`에서 D3D12 Timestamp QueryHeap 및 ReadbackBuffer를 통한 패스별 GPU 시간 지연 회수와 VRAM 예산/사용량/디스크립터 통계 질의(`QueryMemoryStats`)가 구현되었고, 리소스 생성 실패 시 `std::terminate()` 대신 `BAM_LOG_ERROR` 및 `EResult::Fail`을 반환하도록 안정화되었다.
  - `MetricsPanel.cpp`에서 패스별 CPU/GPU 시간 테이블, VRAM/디스크립터 사용량, 하드웨어 기능 지원 여부를 시각화하며 실시간 110~116 FPS 환경에서 계측 동작이 확인되었다.
- **S2 (바인딩 레이아웃 계약 및 텍스처 슬롯 상태 누수 방지)**:
  - [Shader/BINDING_LAYOUT.md](Shader/BINDING_LAYOUT.md)를 `DirectX12RHI::CreateRootSignature()`의 실제 `space0`~`space3`(Root Parameter `[0]`~`[10]`) 구조와 일치하도록 갱신했다.
  - `MaterialInterface::Bind()`에서 G-Buffer 슬롯(0: Diffuse, 1: Normal, 2: PBR, 3: Emission) 점유 여부를 추적하고, 미지정 슬롯을 안전한 기본 더미 텍스처(`white1x1`, `blue1x1`, `black1x1`)로 리셋하여 이전 드로우콜의 텍스처 잔류 누수 현상을 즉시 차단했다 (후속으로 S2-C 플래그 기반 샘플링 분기 계획 수립).
  - `SDLGPURHI`는 `DrawIndexedInstanced`(`NotImplemented`), `BindInstanceBuffer`, Compute 인터페이스가 미구현 상태로, 미지원 시 안전 폴백 경로를 유지한다.
  - **텍스처 밉맵 상태 (2026-11-08 정적 반영):** `stb_image_resize2` 기반 CPU 밉맵 체인 생성, `DirectX12RHI` 다중 서브리소스 업로드 및 `TextureMipmapCheck` 테스트가 추가되었다(S2-D 1차 반영). 오프라인 BC7/DDS 텍스처 베이킹은 후속 범위이며, 실제 GPU 앨리어싱·프레임 비용 비교는 실측 확인이 필요하다.
- **S3 (정적 메시 인스턴싱, 다중 패스 독립 LOD 및 GPU 스키닝 제출 — 구현 및 배칭 실측 완료)**:
  - `InstanceData`(`worldMatrix`, `normalMatrix`, `pickingID`), `LODGroupComponent`가 추가되었다.
  - `MeshRenderSystem::OnSubmit()`에서 `PassTarget` 구조체를 통해 활성 뷰포트/패스별 고유 카메라(위치, `projY`) 기준으로 독립적인 화면 덮개 비율(Screen Coverage) + 히스테리시스 LOD를 평가·제출하며, 뷰마다 LOD 상태를 따로 두고 같은 뷰의 그림자 패스도 그 LOD를 쓴다(2026-11-22, 거리는 경계 상자 중심 기준).
  - `Renderer::RenderMeshes()`가 `BindInstanceBuffer()` 및 인덱스/비인덱스 여부에 따라 `DrawIndexedInstanced()` / `DrawInstanced()` 배칭 드로우를 수행하며, 인덱스 31만 개 추가 시에도 드로우콜(56 -> 57회)이 유지됨을 실측 검증했다.
  - `SkinnedMeshRendererComponent`와 `AnimatorComponent::finalBoneMatrices`를 연결한 GPU 스키닝 구조화 버퍼 제출(`SubmitSkinned` / `RenderSkinnedMeshes`)도 구축되었다.
- **S4 (Compute 기반 및 Tiled Light Culling — 구현 및 실측 검증 완료)**:
  - `ShaderBuild.cmake`에 `*CS.hlsl`(`cs_6_0`) 컴파일 추가, `DirectX12Pipeline` Compute PSO, `DirectX12RHI::Dispatch`/`ResourceBarrierUAV`, `LightManager::DispatchLightCulling` 구현 완료.
  - `tiledLightCullingCS.hlsl`에 타일의 4방향 절두체 평면(`s_FrustumPlanes[4]`) 역투영 및 구면 교차 판정이 추가되어 전체 타일 광원 과할당 문제가 해결되었다.
  - `lightingPS.hlsl`에서 선별된 타일 광원만 순회하도록 수정되어 `tileLightCount == 0`일 때의 전체 광원 순회 버그가 해결되었으며, 라이팅 비집중 영역 응시 시 `LightingPass` GPU 시간이 1.10 ms -> 0.25 ms(77% 단축)로 감소함을 실측 확인했다.
  - `SceneViewportPanel`과 `ViewportDeferredPipeline` 모두 `DispatchLightCulling` 및 버퍼 바인딩이 일관되게 연결되었다.
  - **(2026-11-18 검증 완결)**: 타일당 256개 초과 과부하 환경에서 조도 누락을 방지하는 전역 순회 폴백(`gTileLightGrid[tileIndex].y > 256u`), 절두체 평면 구면 교차 수치 정합성, 255/256개 경계값 패킹, 1,024개 광원 스트레스 및 Directional/Sky 광원 전역 포함 규칙을 포괄 검증하는 전용 단위 테스트 `TiledLightingCheck` CTest 등록 완료.
- **S5 (IBL, 그림자 안정화 및 HDR·공통 디퍼드 파이프라인 일원화 — 구현 완료 및 고도화)**:
  - `lightingPS.hlsl`에 반구형 Sky Irradiance·거칠기 기반 수렴(`LIGHT_TYPE_SKY` + `EnvBRDFApprox`), 접촉 그림자 소프트닝, `ShadowStrength` 및 큐브맵 기반 Split-Sum PBR IBL(`gLightingData.HasIBLMaps != 0u`, `gIrradianceMap`, `gPrefilteredEnvMap`, `gBRDFLut`)이 반영되었다.
  - **S5 고도화 (2026-11-18)**: Karis 2013 중요도 샘플링 기반 256x256 `R16G16_FLOAT` Split-Sum BRDF LUT 절차적 자동 생성 및 캐싱 파이프라인(`IBLManager`) 구축. 사용자 LUT 미지정 시 자동 주입 및 `PrefilteredMap` 단독 지정 시 폴백 지원. 큐브맵이 없는 기본 씬에서도 `SkyAtmosphereComponent`의 `ZenithColor`, `SkyIntensity` 기반 반구형 물리 IBL 연동. 직사광 완전 차폐 시 칠흑 현상(Pitch Black)을 방지하고 알베도를 보존하는 `ShadowAmbientFloor` 앰비언트 하한 밸런싱 도입 및 `IBLShadingCheck` 단위 검증 통과. 6,710만 회 적분 연산에 가용 CPU 스레드 기반 행 분할 병렬화(`std::thread`)를 적용하여 텍스처 베이킹 및 테스트 시간을 수 초대로 고속화 완료. ## 3. 도입 원칙

1. 기본 래스터 경로와 신규 경로를 같은 씬에서 비교할 수 있게 유지한다.
2. 고급 기능은 우선 DirectX12에서 검증하고, 공통 RHI에는 실제 사용에 필요한 계약만 추가한다.
   백엔드별 기능 지원을 조회하고, 미지원 시 기본 경로 또는 명확한 실패를 선택한다.
   Vulkan·Metal 등의 이름이나 셰이더 출력 형식이 존재한다는 이유로 동일 지원을 주장하지 않는다.
3. GPU 버퍼·디스크립터·가속 구조의 소유자와 해제 시점을 명확히 한다.
   프레임 슬롯 재사용과 핫 리로드에서는 GPU 완료 전 데이터를 덮어쓰거나 자원을 해제하지 않는다.
4. 렌더링 기능은 Engine에 두고 Editor는 설정·시각화·디버깅을 담당한다.
   Editor 없이 Client에서도 같은 장면 데이터와 실행 경로를 사용할 수 있어야 한다.
   정점·입력 레이아웃·셰이더 공통 정의는 렌더링 소유 영역에서 관리하고, 경로 정리로 바인딩 ABI를 변경하지 않는다.
   씬 렌더와 독립 프리뷰, 프리팹 썸네일은 컴포넌트 단위의 활성 상태를 확인하고 활성 렌더러만 제출한다.
5. 전체 화면 패스나 Compute 사용 여부로 후처리를 구분하지 않는다.
   가시성·조명 계산도 전체 화면에서 실행할 수 있다.
   RT·GI에 필요한 누적과 디노이징은 품질 확보 범위에 포함하되, 독립적인 후처리 효과 추가는 본 계획의 중심에서 제외한다.
6. 기능마다 CPU 비용·GPU 비용·메모리·화질을 함께 기록한다. 드로우 수 감소만으로 성능 향상을 주장하지 않는다.

## 4. 단기 목표: 기존 렌더러의 측정과 확장 기반

### S1. 재현 가능한 성능 측정과 기능 지원 조회

**목적:** CPU 제출, 그림자, 기하 처리, 조명 중 어떤 부분을 개선할지 근거를 확보한다.

- 기존 `RHIFrameMetrics`를 활용해 프레임·뷰포트·패스 통계의 집계 범위를 명시한다.
- CPU 제출 시간, 패스별 GPU timestamp와 GPU 대기 시간을 측정한다.
  결과는 완료된 프레임에서 지연 회수하고, 측정 때문에 매 프레임 GPU 전체 대기를 추가하지 않는다.
- 제출/컬링 물체 수, PSO·재질 변경, 디스크립터 사용량과 주요 GPU 메모리를 관찰한다.
- Compute, 간접 그리기, Mesh Shader, DXR, 직접 디스크립터 인덱싱의 지원 여부를 분리해 조회한다.
  필요한 OS·SDK·드라이버·Shader Model 조건은 기능 구현 시 공식 명세와 실제 장치로 확정한다.

**완료 기준:** 고정 씬·카메라·해상도에서 CPU/GPU 시간을 구분해 기록하고,
미지원 기능을 선택했을 때 기본 경로로 돌아가거나 이유를 명확히 표시한다.

### S2. 셰이더 바인딩과 렌더 자원 계약 정리

**목적:** 새 버퍼와 패스 추가 시 기존 셰이더·머티리얼·핫 리로드가 깨지는 일을 줄인다.

- Geometry·Lighting·Shadow·Sky·UI의 실제 register/space와 루트 시그니처를 대조한다.
  SDL GPU를 통한 SPIR-V 사용 경로와 GLSL 소스의 유지 범위도 확인한다.
- 기존 번호를 이상적인 순서로 재배치하기보다, 현재 패스별 예외와 새 그룹 배치 규칙을 문서화한다.
- 프레임별 디스크립터 할당·재사용·용량 초과·지연 해제를 검증한다.
- 리소스 읽기/쓰기 전환과 패스 입력·출력을 명시한다.
  자동 Render Graph는 패스 의존성 관리가 실제 문제로 확인될 때 후속으로 검토한다.

**완료 기준:** 바인딩 문서로 각 패스의 리소스를 추적할 수 있고,
리사이즈·셰이더 교체 실패·씬 교체 후에도 기존 유효 경로를 유지한다.

### S2-B. 셰이더 리플렉션 기반 머티리얼 상수 버퍼 자동 레이아웃 (중장기 목표)

**목적:** 머티리얼과 후처리 파라미터의 오프셋 하드코딩을 제거하고, 셰이더 바이너리로부터 상수 버퍼 구조를 자동 추출하여 안전성과 생산성을 극대화한다.

- DXC Shader Reflection API(`ID3D12ShaderReflection`) 및 Vulkan용 `SPIRV-Reflect`를 셰이더 컴파일/로딩 단계에 연결한다.
- 셰이더 바이너리(`.cso`, `.spv`) 파싱 시 대상 ConstantBuffer(`b0, space3` 등)의 변수 이름, 타입(Float, Vec4 등), 크기, 바이트 오프셋 메타데이터를 자동 수집한다.
- `MaterialInterface` 생성 시 수집된 리플렉션 정보를 기반으로 `m_Parameters` 테이블을 스스로 구성한다.
- 프로그래머나 아티스트가 오프셋을 전혀 몰라도 `mat->SetFloat("Name", value)` 호출 시 정확한 바이트 위치에 값이 쓰이도록 보장한다.

**완료 기준:** 셰이더 코드에서 변수 순서나 타입을 바꾸더라도 C++ 코드의 수동 수정 없이 런타임에서 오프셋 불일치나 화면 왜곡 없이 값이 올바르게 전달된다.

### S2-C. 플래그 기반 텍스처 샘플링 분기 및 머티리얼 그래프 입력 유연화

실행 순서: 현재 기본 텍스처 확보/바인딩 실패(F08)와 관련 리소스 오류를 정리한 뒤,
유효성 플래그·기본값 분기(3-A) → 그래프 상수/채널 입력(3-B)을 별도 작업으로 진행한다.
타일 용량 초과(F10)는 해당 장면을 사용하기 전에 해결하며 전체 배포 완료를 이 기능의 필수 조건으로 두지 않는다.
통합 선택·검증 기준은 [DevelopmentPriorities.md 10절](DevelopmentPriorities.md)을 따른다.

**목적:** 텍스처를 무조건 샘플링하는 고정 파이프라인에서 탈피하여, 슬롯 미지정 시의 상태 누수(오염) 방지 및 머티리얼 그래프를 통한 유연한 상수/벡터/채널 분리 입력을 지원한다.

- **1. 텍스처 유효성 비트 플래그(`MaterialFeatureFlags`) 도입**:
  - 머티리얼 상수 버퍼에 텍스처 슬롯별 유효성 플래그(`FLAG_HAS_DIFFUSE_MAP`, `FLAG_HAS_NORMAL_MAP`, `FLAG_HAS_PBR_MAP`, `FLAG_HAS_EMISSIVE_MAP` 등)를 정의한다.
  - G-Buffer 셰이더(`gbufferPS.hlsl`)에서 텍스처가 없는 슬롯은 샘플링을 수행하지 않고 안전한 수학적 기본값(Emission: 0.0, Normal: 정점 법선, PBR: 상수 거칠기/금속도/차폐 1.0)으로 즉시 분기한다.
  - 슬롯을 1x1 더미 텍스처로 채우지 않고 순수하게 비우는(Unbound/Null SRV) 방식을 취하더라도, 드로우콜 간 텍스처 잔류로 인한 PBR/Emission 오염 및 화면 폭발 버그를 원천 차단한다.
- **2. 머티리얼 그래프 기반 상수/벡터/컬러 분리 입력 연동**:
  - 텍스처 에셋 기반 샘플링뿐만 아니라, 노드 그래프에서 특정 변수나 단일 Color(RGBA), 스칼라 파라미터(Float), 분리된 채널(Split RGBA / Swizzle)을 G-Buffer의 각 속성에 직접 공급할 수 있는 평가 경로를 구축한다.
  - Albedo에 단색(Color Uniform) 직결, Roughness/Metallic에 스칼라 슬라이더 직결, Emission에 HDR Color 직결 등 텍스처 없는 절차적/상수 기반 머티리얼 작성을 완전하게 지원한다.
- **3. 샘플링 대역폭 최적화**:
  - 텍스처가 바인딩되지 않은 슬롯의 GPU 메모리 텍스처 페치(Texture Fetch) 대역폭을 0으로 절감한다.

**완료 기준:** 텍스처가 없는 머티리얼에서 이전 드로우콜의 텍스처 오염이나 하얗게 새는 현상이 발생하지 않고, 머티리얼 그래프에서 연결된 상수 컬러 및 채널 분리 데이터가 G-Buffer와 최종 라이팅에 정확히 반영된다.

### S2-D. 텍스처 밉맵(Mipmap) 체인 구축 및 GPU 블록 압축(BC7/DDS) 파이프라인

2026-11-06 순서 보완: RT 진단의 입력 차원 보호(A04)를 먼저 처리한다. 밉맵은 다중 서브리소스 계약·업로드와 품질 검증을 먼저 완성하고 압축 베이킹을 다음 단계로 둔다. 실제 병목이 기하 처리인지 텍스처 품질인지 확인해 자동 LOD와 독립적으로 선택한다. 근거는 [이번 점검](CodeDocumentationAudit-2026-11-06.md)과 통합 계획 11절이다.

**목적:** 원본 해상도(Mip 0) 단일 텍스처 사용으로 인한 원거리 텍스처 앨리어싱(자글거림) 및 텍스처 캐시 미스를 해결하고, VRAM 대역폭과 렌더링 성능을 최적화한다.

- **개선 계획 및 구현 현황:**
  1. **CPU 런타임 밉맵 체인 생성 및 RHI 다중 서브리소스 업로드 [완료 (2026-11-08)]**:
     - `Texture.h/.cpp`: `CalculateMipLevels` ($1 + \lfloor\log_2(\max(W, H))\rfloor$), `TextureCreateDesc::generateMips`, `ValidateTextureHeader` 다중 밉 크기 정합성 검증 추가.
     - `stb_image_resize2` (`stbir_resize_uint8_linear`, `STBIR_RGBA`) 기반으로 Mip 0에서 순차적으로 $1/2$ 다운샘플링하여 Mip 1 ~ Mip N-1 픽셀 체인을 연속 메모리 버퍼에 생성.
     - `DirectX12RHI::UploadTextureData`: D3D12 `GetCopyableFootprints`로 서브리소스별 풋프린트 레이아웃(256B 피치 정렬)을 일괄 획득하여 단일 업로드 버퍼에 순회 패킹 후, 모든 밉 슬라이스(`SubresourceIndex = mip`)로 일괄 복사.
     - `DirectX12Sampler` 및 `SamplerManager`: 기본 삼선형(Trilinear, `MipFilter = Linear`, `MaxLOD = D3D12_FLOAT32_MAX`) 필터링과 자동 연동.
     - 단위 테스트 `TextureMipmapCheck` 신설 및 CTest 등록 완결.
  2. **GPU 블록 압축(BC1~BC7) 및 고속 DirectDraw Surface(`.dds`) 컨테이너 로더 구축 [완료 (2026-11-18)]**:
     - `RHITextureTypes.h`: `IsBlockCompressed()`, `GetBlockCompressedBlockSize()`, `GetUncompressedBytesPerPixel()` 헬퍼 함수 추가.
     - `DirectX12Types.h`: `BC1_RGBA_UNORM_SRGB`, `BC2`, `BC3`, `BC7_RGBA_UNORM_SRGB`의 DXGI sRGB 포맷 매핑 교정.
     - `DirectX12RHI::UploadTextureData`: 4x4 블록 압축 포맷 행 피치 및 슬라이스 계산 로직 완비로 BC 포맷 텍스처의 GPU 직접 업로드 지원.
     - `DDSLoader.h/.cpp`: DX10 헤더 및 레거시 FourCC(`DXT1`, `DXT3`, `DXT5`, `ATI1/BC4U`, `ATI2/BC5U`)를 지원하는 고속 인메모리 DDS 파서 신설.
     - `Texture.h/.cpp`: `InitializeFromDDSMemory`, `CreateFromDDSMemory` 및 핫로드 경로 연동, `ResourceManager`에 `L".dds"` 확장자 등록.
     - `TextureMipmapCheck`: 256x128 9레벨 Mipmap BC7 DDS 파싱 및 75% 메모리 절감 검증 단위 테스트 추가 완결.
  3. **에디터 임포트 파이프라인 (DirectXTex 기반 DDS / BC7 블록 압축 오프라인 베이킹) [완료 (2026-11-18)]**:
     - `TextureImporter.cpp`: `kQuickTextureSanityMode` 강제 다운그레이드를 해제하고 사용자 선택 `TargetFormat` 및 `CompressFlags`를 100% 반영.
     - 노멀 맵 파일명(`_Normal`, `_norm` 등) 자동 감지 시 `BC5_RG_UNORM` 및 `NormalMap` 최적 압축 자동 지정, 일반 텍스처는 `BC7_RGBA_UNORM` 및 밉맵 체인 자동 생성.

**완료 기준:** 원거리 텍스처 샘플링 시 지글거림이 사라지고 삼선형(Trilinear) 또는 이방성(Anisotropic) 필터링이 정상 적용되며, 비압축 텍스처뿐만 아니라 BC1~BC7 블록 압축 밉맵 DDS 및 `.bamtex` 텍스처가 D3D12 서브리소스 검증 오류 없이 고속 로드 및 렌더링된다. (1~3단계 런타임/오프라인 파이프라인 전체 달성)

### S3. 정적 메시 인스턴싱과 기본 LOD

2026-11-18 갱신. `Renderer::RenderMeshes` 배칭 파이프라인에서 그림자 패스(`ShadowDepthPass`)의 메시 우선 정렬 및 동일 메시 다중 머티리얼 단일 인스턴스 배치 병합 최적화가 적용되었다. 동적 링 버퍼 오버플로 방지를 위한 1024개 분할 플러시 가드가 추가되었으며, 메모리 레이아웃(80B/112B)·여인수 기저 노멀 변환 수학 정합성·패스별 배칭 시뮬레이션·LOD 히스테리시스 진동 억제를 포괄 검증하는 전용 단위 테스트 `MeshInstancingCheck`가 구축되어 CTest에 등록되었다.

**목적:** 반복되는 메시의 CPU 제출과 불필요한 기하 처리 비용을 줄인다.

- 실제 인스턴스 수·시작 위치·인덱스 범위를 전달할 수 있는 RHI 드로우 계약을 정의한다.
- 같은 메시·호환 재질·패스 상태를 가진 불투명 정적 메시부터 배칭한다.
- 깊이만 기록하는 그림자 패스(`ShadowDepthPass`)에서는 동일 메시의 서로 다른 머티리얼을 래스터라이저 호환성(`cullMode`, `frontFace`)에 따라 단일 인스턴스 드로우콜로 통합한다.
- 월드 행렬과 Picking ID를 인스턴스 데이터로 공급한다.
  음수 스케일, 비균일 스케일의 노멀 변환과 머티리얼별 차이를 처리한다.
- 화면 크기 기반의 단순 메시 LOD를 작은 예제로 추가하고, 경계 진동을 완화한다.
  투명 정렬, 지형 변위, 스키닝을 처음부터 같은 배칭 경로에 강제하지 않는다.

**완료 기준:** 반복 메시 씬에서 단일 드로우 경로와 화면·피킹·그림자가 일치하고,
드로우 수와 CPU/GPU 시간의 변화를 각각 기록한다. LOD 경계에서 물체가 사라지지 않는다. (`MeshInstancingCheck` 테스트 통과)

### S4. Compute 실행 기반과 Tiled/Clustered Lighting

2026-11-15 갱신. `LightManager`의 씬 광원 업로드 상한이 1024개(`MAX_LIGHTS`)로 확장되었으며, 타일당 256개 초과 계측(`s_TileLightCount` 보존)과 초과 타일 안전 전체 순회 폴백(`lightingPS.hlsl`, A06 본체/F10)이 반영되어 `x64-debug` 빌드 및 CTest 36/36 통과를 확인했다. 다수 광원 배치 씬에서의 실시간 렌더링 화면 비교 및 GPU 프로파일링 계측은 실측 검증으로 남긴다.

먼저 `LightManager::DispatchLightCulling()`에서 할당된 타일 버퍼의 용량과 이번에 실행할 타일 격자를 구분한다. 큰 버퍼를 재사용할 때도 현재 G-Buffer 위치 텍스처의 너비와 높이로 디스패치 그룹 수를 계산한다. 크기가 서로 다른 씬·게임 뷰와 해상도 축소·복원에서 타일이 중복 기록되지 않는지 확인한다. 현행 코드에서 찾은 문제이며 실행 검증이 남아 있다.

**목적:** 전체 광원 순회 비용을 줄이고 GPU 컬링·GI의 공통 기반을 마련한다.

- Compute PSO·Dispatch·UAV 버퍼·카운터·리소스 전환·메모리 가시성 처리를 연결한다.
  셰이더 자동 빌드와 런타임 컴파일·리플렉션 경로도 확장한다.
- **내장 시스템 셰이더 식별자 정리:**
  `TiledLightCullingCS`, `LightingPS` 등 엔진 내장 셰이더 경로의 하드코딩 매직 스트링을 심볼릭 논리 키 및 C++ `constexpr` 상수로 일원화하여 에셋 셰이더와의 참조 경계를 정돈한다.
- 기존 Deferred Lighting에 타일별 광원 목록을 먼저 연결한다.
  깊이 구분이 필요하거나 타일별 목록이 커지는 경우 Clustered 방식으로 확장한다.
- Directional·Sky Light와 범위가 있는 Point·Spot Light를 구분한다.
- 목록 용량 초과를 계측하고, 안전한 전체 순회 등 정확성을 유지하는 대체 경로를 제공한다.
  투명 Forward 경로에서 불투명 깊이만으로 광원을 제거하지 않는다.
- 초기에는 단일 큐로 검증한다. 비동기 Compute는 겹칠 작업과 이득이 측정될 때 추가한다.

**완료 기준:** 광원 수 0·1·다수, 목록 초과, 카메라 근접 경계에서 기본 경로와 결과가 일치한다.
적은 광원과 많은 광원 모두 측정해 새 방식의 손익 조건을 기록한다.
개념 참고: [Clustered Deferred and Forward Shading](https://www.cse.chalmers.se/~uffe/clustered_shading_preprint.pdf).

### S5. 환경맵 기반 IBL과 기존 그림자 안정화

**상태** — 2026-11-18 Karis 2013 중요도 샘플링 기반 256x256 `R16G16_FLOAT` Split-Sum BRDF LUT 절차적 자동 생성 및 캐싱 파이프라인(`IBLManager`) 구축. 사용자 LUT 미지정 시 엔진 기본 LUT 자동 주입 및 `PrefilteredMap` 단독 지정 시 폴백 지원. 큐브맵 부재 씬에서도 `SkyAtmosphereComponent`의 `ZenithColor`, `SkyIntensity` 기반 반구형 물리 IBL 연동. 직사광 완전 차폐 시 칠흑 현상(Pitch Black)을 방지하고 알베도를 보존하는 `ShadowAmbientFloor` 앰비언트 하한 밸런싱 도입 및 `IBLShadingCheck` 단위 검증 통과. [구현 기록](ImplementationLog.md)

**목적:** 동적 GI 전에 재질의 환경광 응답과 기본 그림자 품질을 확보하고, 다중 광원 환경에서의 그림자 농도·조도 밸런스를 개선한다.

- 기본 BRDF LUT는 지연 조명 패스 제출 시 준비하고, 패스에서는 GPU 텍스처만 바인딩한다. 사용자 LUT 없이 환경맵을 사용하는 씬에서 첫 바인딩과 반복 실행, 에디터 종료를 확인한다.
- Diffuse irradiance, roughness별 specular prefilter, BRDF LUT로 환경맵 IBL을 구성한다.
  먼저 고정 환경맵 하나로 시작하고, 동적 캡처·다수 Reflection Probe는 필요에 따라 확장한다.
- 색 공간, 선형 HDR 조명과 노출 조건을 고정해 금속도·거칠기별 구체를 비교한다.
- 기존 CSM·Spot·Point 그림자의 바이어스, 캐스케이드 경계, 필터 비용과 카메라 이동 안정성을 점검한다.
  기존 코드에 있는 CSM·PCF·PCSS 계열 처리를 신규 구현 성과로 중복 기록하지 않는다.
- **다중 광원 그림자 농도 균형 및 제어 기능 검토:**
  - Direct Light와 Point/Spot Light가 중첩될 때 발생하는 그림자 농도(대비) 불균일 현상을 분석하고 조도 밸런싱 가이드라인을 수립한다.
  - Directional Light에만 독점 적용된 접촉 그림자(`ContactShadow`)로 인한 그림자 간 이질감을 완화한다.
  - 광원별 그림자 강도(`ShadowStrength`, 0.0~1.0) 파라미터 또는 앰비언트 최솟값 보정 도입을 검토하여 과도한 칠흑 그림자(Pitch Black)를 방지한다.

**완료 기준:** 재질·환경맵 변경이 재현 가능하고, 직접광을 꺼도 환경광 반응을 확인할 수 있다.
그림자 품질과 비용은 고정 카메라 및 이동 카메라에서 각각 기록하며, 다중 광원 씬에서 그림자 농도 왜곡이나 과도한 간섭 없이 균형 잡힌 명암이 출력된다.

### S6. 래스터 반투명 재질과 수면

**상태** — 2026-11-18 1단계(정적 반투명 메시 카메라 정렬), 2단계(씬 컬러 복사 및 얇은 유리 굴절), 3단계(평평한 수면 셰이더, 잔물결 노멀 스크롤, Depth Fade 깊이 색상 그라데이션), 4단계(움직이는 파도 Gerstner Wave 정점 변위, 64x64 WaterGridMesh 격자 메시, 파도 머티리얼 에셋, 월드 공간 XZ 정렬 World-Aligned UV) 구현 완료. Editor Game View 및 독립 Windows 배포 Client(`Client.exe`) 환경에서 동일 카메라/해상도 렌더링 동등성 확인 완료. [구현 기록](ImplementationLog.md)

**출발점** — 공용 Deferred 프로필에서 `ForwardTransparent`는 `ForwardOpaque`의 HDR 색상과 깊이 타깃을 이어받는다. 반투명 VFX에는 알파 합성, G-Buffer 위치 기반 Depth Fade와 시선 각도에 따른 프레넬 림이 있다. 패스는 `BackToFront`로 설정되어 있지만, 현재 `Renderer::Render()`의 정적 메시 경로는 이 경우 머티리얼·메시 정렬을 건너뛰며 카메라 기준 거리 정렬은 확인되지 않았다. [패스 등록 코드](../Engine/Source/Render/Pipeline/Private/DeferredProfilePasses.cpp) · [정적 메시 제출 처리](../Engine/Source/Render/Private/Renderer.cpp) · [반투명 VFX 구현 기록](CompositeVisualEffectPlan.md#95-phase-5-step-1-구현-반영-내역-2026-11-16-커밋-기준)

작업 전 [Render Pipeline Profile 2·3단계](RenderPipelineProfilePlan.md#2단계-수동-검증)에서 같은 카메라·해상도의 Editor Game View와 저장소 밖 Windows Client 화면을 확보한다. 기존 투명 오브젝트, 그림자, HDR 톤매핑을 비교 기준으로 남긴다. 아래 네 단계를 차례로 검증하며 DXR(M3)과 패스 트레이싱(L4)은 독립적으로 진행할 수 있다.

1. **반투명 판 두 장으로 합성 확인.** 서로 다른 색의 판을 깊이 간격을 두고 겹친다. 카메라를 반대편으로 옮기거나 메시 제출 순서를 바꿔도 각 카메라에서 먼 판부터 합성되는지 확인한다. 불투명 물체 뒤의 판은 가려져야 한다. 깊이 검사는 사용하고 일반 알파 블렌드 판의 깊이 쓰기는 끈다. 정렬 수정이 필요하면 우선 정적 반투명 메시를 각 뷰포트 카메라 기준으로 처리하고, 기존 파티클·스프라이트 합성을 회귀 확인한다.
2. **얇은 유리 한 장에 굴절과 환경맵 반사를 적용.** 불투명 패스가 끝난 뒤 톤매핑 전 HDR 장면 색을 별도 읽기용 텍스처로 확보한다. 반투명 패스는 그 텍스처를 샘플링하고 기존 HDR 색상 타깃에 출력한다. 동일 타깃을 동시에 읽고 쓰는 바인딩을 피하고, 패스 입력·출력과 자원 상태 전환은 [바인딩 규약](Shader/BINDING_LAYOUT.md)에 맞춘다. 격자나 기둥을 배경으로 두고 굴절 강도 0에서는 왜곡이 사라지고, 비스듬히 볼수록 환경맵 반사가 강해지는지 확인한다. 왜곡된 샘플 좌표가 화면 밖이면 왜곡 전 배경을 사용한다. 첫 범위는 화면에 보이는 불투명 배경을 통과해 보는 단일 유리 표면이다.
3. **평평한 수면에 잔물결과 깊이에 따른 색을 추가.** 유리에서 검증한 장면 색·반사 입력을 재사용한다. 시간에 따라 표면 법선을 바꿔 잔물결을 만들고, 수면과 뒤쪽 불투명 표면의 거리를 근사해 얕은 곳과 깊은 곳의 색을 구분한다. 경사진 바닥으로 깊이 변화를 확인하고 물 앞에 놓은 불투명 물체의 모습과 가림이 유지되는지 확인한다.
4. **수면 메시를 움직여 파도를 만든다.** 작은 격자 메시에서 정점 높이와 셰이딩에 쓰는 법선을 함께 움직인다. 낮은 시점에서 수면 실루엣이 바뀌고 반사·굴절도 파도에 맞춰 이동하면 첫 예제를 통과한 것으로 본다. 넓은 바다, 쇄파, 부력, 다층 굴절은 콘텐츠가 요구할 때 별도 범위로 잡는다.

**공통 완료 기준** — Game View와 Windows 배포 Client에서 같은 카메라로 단계별 예제를 비교한다. 리사이즈 후 읽기용 색 텍스처와 깊이 타깃의 크기가 맞는지, 굴절 재질이 없는 씬의 출력이 유지되는지 확인한다. 굴절을 켜고 끈 경우의 장면 색 복사와 반투명 패스 GPU 시간을 동일 조건에서 기록한다.

### S7. 시간 누적 안티앨리어싱 (TAA)

**상태 (2026-11-23):** 코드에 반영했다. 첫 실행에서 접촉 그림자가 지터가 있는 G-Buffer를 지터 없는 카메라로 찾아 화면이 깜빡여 조명 카메라를 맞췄다. 씬 뷰 격자도 지터가 있는 깊이를 지터 없는 방향의 격자 깊이와 비교해 바닥과 겹친 곳이 깜빡여, 깊이만 깊이 타깃과 같은 방향으로 계산하게 했다. 사용자가 수정 후 씬 뷰 화면을 확인했다. 패스별 GPU 시간, 메모리, 움직이는 물체의 잔상은 기록하지 않았다.

- **지터.** 원근 카메라의 G-Buffer와 포워드 패스만 8프레임 주기로 픽셀 안에서 옮겨 그린다. 조명과 타일 광원 컬링은 G-Buffer를 화면 좌표로 다시 찾으므로 같은 카메라를 쓴다. 그림자·반사·기즈모·피킹은 원래 카메라를 쓴다. 직교 카메라와 독립 프리뷰·썸네일은 제외한다.
- **모션 벡터.** G-Buffer 구성은 바꾸지 않는다. 멈춘 면은 G-Buffer 위치와 이전 카메라로 구하고, 직전 프레임에서 움직인 정적·스킨드 메시만 별도 패스로 한 번 더 그린다. 깊이 대신 G-Buffer 위치를 비교하므로 정점을 옮기는 재질은 카메라 이동만 반영한다.
- **합성.** 반투명 뒤, 후처리 앞에서 장면 색과 다음 프레임의 이력에 함께 쓴다. 3×3 이웃의 범위로 이력을 자르고 밝기를 0~1로 눌러 섞는다. 이전 결과는 Catmull-Rom으로 읽는다.
- **사용 여부.** 기본 꺼짐이며 프로젝트 → 그래픽 → 뷰포트 순서로 덮어쓴다. Client는 프로젝트 설정만 쓴다. DirectX12만 지원한다.
- **남은 한계.** 동적·스플라인 메시, 지형, 파티클, 반투명은 자신의 모션 벡터가 없다. 씬 뷰 격자는 물체 윤곽에 가려지는 경계가 프레임마다 최대 반 픽셀 흔들릴 수 있다(디버그 선은 깊이 검사를 하지 않는다). 섞는 비율은 측정 전 시작값이다. 반사 누적은 아직 물체별 모션 벡터를 쓰지 않는다.

**완료 기준:** 멈춘 화면의 계단과 반짝임이 줄고, 카메라와 물체가 움직일 때 잔상이 남지 않는다. 켜고 끈 화면의 선명도와 패스별 GPU 시간, 메모리를 기록한다.

### S8. 앰비언트 오클루전 (화면 공간 GTAO·레이트레이싱)

**상태 (2026-11-23):** 코드에 반영했고 빌드와 화면 확인은 하지 않았다. 이전에는 재질 AO(`gPBR.a`)만 환경광에 곱했다. 사용자가 두 방식을 모두 요청해 한 설정에서 고르게 했다.

- **방식.** 설정 값은 상위 설정 따름·끄기·화면 공간·레이트레이싱이다. 레이트레이싱은 장치·셰이더가 지원하지 않거나 이번 프레임 TLAS가 없으면 화면 공간으로 계산한다. 기본 꺼짐이며 프로젝트 → 그래픽 → 뷰포트 순서로 덮어쓴다. Client는 프로젝트 설정만 쓴다. 쓰기 텍스처 Compute라 DirectX12만 지원하고, 독립 프리뷰·썸네일과 직교 카메라는 제외한다.
- **화면 공간(GTAO).** 전체 해상도에서 픽셀마다 화면 방향 2개, 방향마다 양쪽 6단계로 G-Buffer 월드 위치를 읽어 지평선을 찾고 법선 반구의 코사인 가중 가시성을 적분한다. 반경 0.5m(화면 높이의 10%까지), 대비 1.5제곱이다(측정 전 시작값). 화면 방향은 G-Buffer를 그린 카메라의 축과 투영 부호로 월드 방향으로 바꾼다. 화면 밖이나 앞 물체에 가려진 차폐는 찾지 못한다.
- **레이트레이싱.** 픽셀마다 법선 반구에 코사인 분포로 1m 광선 2개를 쏜다. TLAS의 그림자 캐스터(활성·보이는 정적 불투명 메시, `castShadow`)만 가린다. 스킨드·동적·스플라인 메시, 지형, Masked·반투명 재질은 가리지 못하고 받기만 한다.
- **누적.** 두 방식 모두 같은 면의 5×5 이웃으로 고른 값과 이전 결과를 섞는다(화면 공간 최대 16프레임, 레이트레이싱 32프레임). 이전 화면은 지터 없는 이전 카메라로 찾고 이전 G-Buffer의 TAA 지터만큼 옮겨 읽는다. 카메라 거리가 다르면 버리고, 이웃 분포 범위로 잘라 움직인 물체의 잔상을 줄인다. 물체별 모션 벡터는 아직 쓰지 않는다. 방식·씬·크기가 바뀌거나 카메라가 한 프레임에 20m 넘게 움직이면 이력을 버린다.
- **합성.** 결과를 재질 AO와 곱해 환경광(확산·정반사 IBL)에만 적용한다. 직접광과 레이트레이싱 반사에는 곱하지 않는다. G-Buffer 플래그 `FLAG_APPLY_SSAO`가 없는 재질은 받지 않는다(기본 G-Buffer·지형·셰이더 그래프는 켠다). 차폐하는 쪽은 플래그와 무관하다.
- **검사.** `AmbientOcclusionCheck`는 설정 덮어쓰기, 레이트레이싱 → 화면 공간 → 끄기 선택, 화면 축(LH·RH·y 뒤집은 투영), 반경 픽셀 환산, 지터 보정 좌표를 확인한다. 셰이더 적분과 누적은 화면으로 확인해야 한다.
- **남은 항목.** 켜고 끈 화면 비교, 패스별 GPU 시간(`_ScreenSpaceAOPass`, `_RaytracedAOPass`, `_AmbientOcclusionTemporalPass`)과 메모리(전체 해상도 R32F 1장 + RGBA16F 2장) 기록, 반경·표본 수 조정, 움직이는 물체의 잔상 확인, 레이트레이싱과 화면 공간의 결합 여부 판단, 반 해상도 계산 검토.

**완료 기준:** 물체가 바닥·벽과 맞닿은 곳에 접촉 음영이 생기고, 직접광이 닿는 면의 밝기는 바뀌지 않는다. 카메라가 멈추면 노이즈가 사라지고 움직여도 잔상이 남지 않는다. 두 방식의 화면과 GPU 시간을 같은 조건에서 기록한다.

### S9. 디퍼드 데칼 (상자 투영)

**상태 (2026-11-23):** 코드에 반영했다. 빌드·실행·GPU 시간 측정은 하지 않았다. 순수 계산은 `DecalProjectionCheck`로 검사한다.

- **구성.** `DecalComponent`(엔티티 변환 × `Size`의 단위 상자, 로컬 z가 투영 방향)와 VFX 데칼 트랙이 같은 `DecalDrawData`를 만든다. `DeferredSceneRenderer`가 G-Buffer와 같은 우선순위로 데칼 패스를 등록해 G-Buffer 뒤·조명 앞에 그린다. 프로필 JSON은 바꾸지 않는다.
- **투영.** 상자의 안쪽 면만 깊이 검사 없이 그리고, 픽셀마다 G-Buffer 위치를 상자 공간으로 옮겨 밖이면 버린다. 표면 법선과 투영 축의 각도(`MaxAngle`, 마지막 15도에서 부드럽게)와 상자 양 끝(`DepthFade`)에서 사라진다. 상자 양쪽 면을 모두 받는다.
- **채널.** 디퓨즈·법선·PBR의 RGB를 데칼별 불투명도로 섞는다. 기본 색 텍스처의 알파가 모양이다. 법선은 표면 법선 위에 데칼 축을 펼친 접선 공간으로 옮긴다. 블렌드가 타깃마다 같아 PBR은 거칠기·금속성·캐비티를 함께 바꾸며, 각 타깃의 a(하늘 판정·셰이딩 플래그·AO)는 쓰지 않는다.
- **수신 여부.** 패스 직전에 G-Buffer 법선을 복사해 `FLAG_RECEIVE_DECALS`와 표면 법선을 읽는다. 정적·스킨드 메시 렌더러의 `Receive Decals`를 끄면 G-Buffer 셰이더가 이 플래그를 빼고 기록한다. 지형은 항상 받고, 스프라이트(Unlit)는 받지 않는다.
- **순서와 카메라.** `SortOrder`가 작은 데칼부터 그린다(VFX 트랙은 0). 한 뷰에 512개까지 그린다. G-Buffer를 그린 카메라(TAA 지터 포함)를 쓴다. 메인 뷰포트는 활성 씬 전체, 독립 프리뷰는 자기 씬의 데칼을 모은다.
- **사용 여부.** DirectX12만 지원한다. 데칼이 없는 프레임은 패스를 꺼 법선 복사도 하지 않는다.
- **남은 한계.** 레이트레이싱 반사의 닿은 면과 포워드·반투명 표면에는 데칼이 없다. 데칼은 발광을 바꾸지 않는다. 깊이가 끊기는 픽셀의 밉 선택을 막으려 텍스처 좌표 기울기를 자른 값(0.05)과 각도 페이드 폭(15도)은 측정 전 시작값이다. 스킨드 메시처럼 움직이는 표면에서는 데칼이 미끄러진다(상자 고정 투영).

**완료 기준:** 경사·계단·원통 위에서 데칼이 굴곡을 따라가고 옆면에서 늘어나지 않는다. 카메라가 상자 안팎을 오가도 한 번씩만 섞인다. `Receive Decals`를 끈 메시와 하늘에는 그려지지 않는다. TAA를 켜도 흔들리지 않는다. 데칼 수에 따른 패스 GPU 시간을 기록한다.

### S10. 자동 노출 (Auto Exposure)

**상태 (2026-11-23):** 코드와 순수 계산 검사(`AutoExposureCheck`)를 작성했다. 빌드·검사·화면 확인은 아직 하지 않았다.

- **위치.** 후처리 효과 `Auto Exposure`(기본 꺼짐)로 효과 목록 맨 앞, 블룸 앞에 둔다. 톤매핑 전 HDR 값을 재고 장면 색에 `exp2(EV)`를 곱해 HDR 타깃에 쓴다. 블룸 임계값은 노출을 곱한 값에 적용된다. 톤매핑의 수동 `Exposure`는 그 뒤에 추가로 곱한다.
- **측정.** `autoExposureHistogramCS`가 log2 밝기 -10~10을 64구간 히스토그램으로 센다. `autoExposureAdaptCS`가 가장 어두운 10%와 가장 밝은 10%를 뺀 평균을 중간 회색 0.18에 맞추는 노출을 구한다. 태양·발광체처럼 작은 극단값은 평균에 들어가지 않는다.
- **적응.** 목표 노출을 최소·최대 EV(기본 -4, 4)로 자르고 노출 보정(기본 0)을 더한다. 이전 노출에서 `1 - exp(-dt·속도)`만큼 옮기며, 밝아질 때 3/초, 어두워질 때 1/초가 기본이다. 식은 `AutoExposure.h`와 셰이더가 같아야 한다.
- **상태와 초기화.** 히스토그램 버퍼와 이전 노출(1x1 `R32_FLOAT`)은 효과(=뷰)마다 GPU에 둔다. 처음 만들 때, 효과를 다시 켤 때, 뷰 크기 변경(`PostProcessPipeline::Resize`), 그리는 씬이 바뀔 때(`SetHistoryScene`) 이전 값을 버리고 목표 노출을 바로 쓴다.
- **파이프라인 변경.** HDR 효과가 이어질 수 있게 HDR 타깃을 두 장 번갈아 쓴다. 최종 출력은 그대로 8비트다. 저장된 설정에 없는 효과는 맨 뒤가 아니라 원래 순서상 자리에 끼운다(예전 씬에서도 자동 노출이 톤매핑 앞에 온다). 제출에 실패한 효과는 건너뛴다.
- **제외.** 썸네일·리소스 미리보기는 기본 설정(꺼짐) 파이프라인을 쓰므로 고정 노출이다. Compute UAV를 쓰므로 DirectX12에서만 동작하고 다른 백엔드는 경고 후 효과를 건너뛴다.
- **남은 한계.** 같은 주소에 다시 만들어진 씬은 바뀐 씬으로 알아채지 못한다. 측정 범위·제외 비율은 고정값이며 화면 가운데 가중치가 없다.

**완료 기준:** 어두운 실내에서 밝은 실외로 카메라를 돌리면 노출이 약 1초 안에 내려가고, 반대 방향은 더 천천히 올라간다. 작은 발광체가 화면에 들어와도 노출이 크게 흔들리지 않는다. 켜고 끈 화면과 측정 패스의 GPU 시간을 기록한다.

### S11. 피사계 심도 (후처리)

**상태 (2026-11-23):** 사용자 요청으로 코드에 반영했다. 빌드와 화면은 아직 확인하지 않았다. 순수 계산은 `DepthOfFieldCheck`로 검사한다.

- **결정 사항(사용자 확인).** 초점 값은 후처리 효과 파라미터에 두고, `CameraComponent`의 `OverrideDepthOfField`를 켠 메인 카메라로 그리는 Game View·Client만 카메라 값을 쓴다. 씬 뷰는 항상 후처리 값을 쓴다. 효과를 켜고 끄는 것은 후처리 설정이 정한다. CoC 식은 `Mode`로 고른다. `FocusRange`(초점 거리, 선명한 폭, 전환 거리)와 `PhysicalLens`(얇은 렌즈, f값, 센서 높이)가 있고, 렌즈 초점 거리는 세로 시야각과 센서 높이로 구한다. 앞쪽 흐림이 선명한 배경 위로 번지는 처리까지 포함한다.
- **입력.** 깊이는 G-Buffer 위치(월드 좌표)를 카메라 시선 방향에 투영한 거리다. 알베도의 a가 0.01보다 작으면 하늘로 보고 무한히 먼 곳으로 둔다(TAA와 같은 기준). D24S8 깊이 타깃은 SRV 형식 처리가 없어 읽지 않는다. 호출부가 매 프레임 `PostProcessPipeline::SetSceneInputs`로 G-Buffer 이름과 카메라를 넘기며, 넘기지 않은 프레임(썸네일·머티리얼 프리뷰)은 효과를 건너뛴다.
- **패스.** 절반 해상도 색·CoC → 8×8 타일의 앞쪽 CoC 최댓값 → 최대 흐림 반지름만큼 타일 확장 → 뒤쪽·앞쪽 48탭 원판 흐림 → 전체 해상도 CoC로 합성. 표본은 자기 CoC가 그 픽셀까지 닿을 때만 섞어 선명한 물체가 흐린 영역으로 번지지 않는다. 앞쪽 결과의 a는 흐린 앞 물체가 픽셀을 덮는 정도다. 최대 반지름은 전체 해상도 32픽셀이다.
- **순서.** 기본 위치는 자동 노출 뒤, 블룸 앞, 톤매핑 전이다. 흐린 결과를 HDR 타깃에 써서 밝은 점이 원판으로 번지고, 블룸이 그 결과를 다시 번지게 한다. TAA는 후처리 앞에서 끝난다.
- **후처리 파이프라인 변경.** (1) 보조 패스 순서: 슬롯마다 보조 패스 우선순위(130 + 2×슬롯)와 슬롯 패스 우선순위(+1)를 두고, `IPostProcessEffect::GetPrePasses`로 받은 보조 패스의 우선순위를 체인 위치에 맞춰 바꾼다. 전에는 블룸 보조 패스가 고정 우선순위(121~127)라 체인의 첫 효과일 때만 맞게 동작했다. (2) HDR 타깃을 두 개 번갈아 써서 HDR 효과를 연달아 쓸 수 있다. (3) `SubmitPass`가 실패한 효과는 슬롯을 쓰지 않고 건너뛴다. (4) 예전 프리셋·씬에 없는 효과는 맨 뒤가 아니라 현재 순서에서 뒤따르는 효과 앞에 둔다(`MergeEffectOrder`).
- **남은 한계.** 포워드로 그리는 불투명·반투명 물체(물, 파티클)는 G-Buffer에 위치가 없어 뒤에 있는 표면의 깊이로 흐려진다. TAA를 켜면 G-Buffer 위치는 지터가 있고 합성 대상 색은 지터가 없어 경계에서 반 픽셀 어긋날 수 있다. 절반 해상도 흐림을 쌍선형으로 올려 앞 물체 윤곽에 얇은 테두리가 남을 수 있다. 효과를 톤매핑 뒤로 옮기면 최종 출력이 HDR 형식이 된다(블룸과 같은 기존 한계). 에디터의 `Mode`는 정수 슬라이더로 표시한다. 직교 카메라는 `PhysicalLens` 식에서 흐리지 않는다.

**완료 기준:** 씬 뷰·Game View·Client에서 초점면이 선명하고 앞뒤가 흐려지며, 흐린 앞 물체가 선명한 배경 위로 번진다. 블룸과 함께 켜도 둘 다 적용되고, 효과 순서를 바꿔도 블룸·피사계 심도가 올바른 입력을 읽는다. 카메라 덮어쓰기를 켜고 끈 Game View 차이를 확인하고, 켜고 끈 패스별 GPU 시간과 메모리를 기록한다.

## 5. 중기 목표: GPU 중심 제출과 하이브리드 조명

### M1. GPU Driven Rendering과 Hi-Z 오클루전 컬링

**선행 조건:** S1~S3, S4의 Compute 실행 기반.

- GPU 장면 버퍼에 인스턴스·경계·메시·재질 참조를 구성하고 생성·수정·삭제를 갱신한다.
- GPU 프러스텀·LOD 선택 → 가시 명령 생성 → 간접 그리기 순서로 구현한다.
  DirectX12에서는 `ExecuteIndirect`를 우선 검토한다.
- 이후 Hi-Z 깊이 피라미드로 가려진 물체를 제거한다.
  이전 프레임 깊이 사용 시 카메라 컷·이동·새 물체·가림 해제에서 보수적인 재노출 정책을 둔다.
- 뷰포트와 그림자 뷰의 가시 목록을 구분한다. 카메라 밖의 그림자 캐스터를 잘못 제거하지 않는다.
- 프레임마다 가시 목록을 CPU로 읽어 드로우를 재구성하는 경로를 필수로 만들지 않는다.

**완료 기준:** CPU 기준 경로와 가시성·피킹·그림자가 일치하며, 갑작스러운 카메라 이동에서 누락이 없다.
가림이 많은 씬과 거의 없는 씬의 총비용을 비교한다.
참고: [Indirect Drawing and GPU Culling](https://learn.microsoft.com/en-us/windows/win32/direct3d12/indirect-drawing-and-gpu-culling-).

### M2. 선택적 Bindless 리소스 접근

**도입 조건:** 다수 재질의 바인딩 비용이나 GPU Driven 명령 구성 제약이 실제로 확인된 경우.

- GPU 재질 테이블에서 텍스처·샘플러를 인덱스로 참조한다.
- 직접 힙 인덱싱을 사용한다면 SM 6.6과 리소스 바인딩 지원 조건을 조회한다.
  셰이더 프로파일·루트 시그니처·컴파일 캐시·리플렉션과 기존 머티리얼 ABI를 함께 다룬다.
- 무효 인덱스의 기본 리소스, 슬롯 재사용과 GPU 완료 전 해제 방지 정책을 정의한다.
- 기존 바인딩 경로를 유지한다. Bindless를 모든 백엔드나 DXR의 필수 조건으로 삼지 않는다.

**완료 기준:** 많은 서로 다른 재질에서 슬롯 오염이 없고, 핫 리로드·삭제·씬 교체가 안전하다.
디스크립터 메모리와 CPU/GPU 비용까지 비교해 기본 사용 여부를 결정한다.
참고: [HLSL Dynamic Resources](https://microsoft.github.io/DirectX-Specs/d3d/HLSL_SM_6_6_DynamicResources.html).

### M3. DXR 그림자 → 반사

**선행 조건:** 기능 지원 조회, 자원 수명·배리어 관리와 패스 계측. M1·M2 완료는 필수가 아니다.

**그림자 2차 상태 (2026-11-22):** 방향광·스포트·점광원 최대 4개의 하드 섀도를 코드에 반영했다. 반사는 아래 반사 상태, 광원 크기에 따른 부드러운 그림자는 아래 부드러운 그림자 상태를 따른다. [구현 기록](ImplementationLog.md)

- **경로 선택.** 차폐 여부만 필요하므로 셰이더 테이블과 히트 그룹이 필요한 DXR 파이프라인 대신 Compute 인라인 RayQuery(Tier 1.1, SM 6.5)를 쓴다. 마스크를 별도 텍스처로 만들어 조명과 분리해 보고 잴 수 있게 했다.
- **가속 구조.** 메시별 BLAS를 캐시하고, 렌더되는 씬과 뷰의 조합마다 TLAS를 매 프레임 다시 빌드한다. LOD는 그 뷰의 GBuffer가 고른 LOD를 따른다. 새 BLAS는 프레임당 16개 또는 삼각형 100만 개까지 빌드한다(측정 전 시작값).
- **스킨드 메시 (2026-11-23, 미검증).** 프레임 시작에 Compute(`raytracedSkinningRTCS`)로 위치·법선·접선을 스키닝해 엔티티별 Storage 버퍼에 쓰고, 그 정점으로 만든 갱신 허용 BLAS를 매 프레임 refit한다. 처음 빌드와 기하 변경(장비 교체 등)은 빌드 예산을 쓰고, refit이 300프레임 이어지면 예산이 있을 때 다시 빌드한다. 같은 엔티티를 여러 뷰가 써도 한 번만 스키닝하며, 프레임당 32개까지 넣는다(측정 전 시작값). 한도를 넘거나 대기·실패한 스킨드 캐스터는 섀도맵에 남는다. 뼈는 그리기 경로처럼 메시당 256개다.
- **미지원 형상.** 동적·스플라인 메시, 정적 렌더러에 붙은 스킨드 메시, 지형, 불투명이 아닌 재질(Masked 포함, 섀도맵이 알파 기준값을 적용), 엔진 기본이 아닌 그림자 셰이더를 쓰는 재질은 기존 섀도맵이 담당한다. 최종 값은 `min(RT 마스크, 섀도맵)`이다.
- **다중 광원.** RGBA8 마스크의 채널마다 광원 하나를 추적한다. 섀도맵은 종류별 첫 광원 하나만 가지므로 캐스케이드 방향광, 섀도맵이 없는 광원, 나머지 순으로 채널을 배정하고 남는 광원은 섀도맵만 쓰거나 그림자가 없다. 섀도맵이 없는 광원에는 TLAS 미지원 형상의 그림자가 없다. 조명 셰이더는 광원 버퍼 인덱스로 섀도맵과 채널의 주인을 확인한다.
- **대기와 실패.** 이번 프레임 TLAS에 들어간 캐스터(정적·스킨드)만 레이트레이싱하는 광원의 섀도맵(캐스케이드·스포트 사분면·점광원 큐브맵)에서 제외한다. BLAS 대기·실패 캐스터와 TLAS 빌드에 실패한 씬은 섀도맵이 담당한다.
- **사용 여부.** 조명(기본 꺼짐) → 프로젝트 → 그래픽 → 뷰포트 순서로 뒤의 설정이 앞을 덮어쓴다. Client는 조명과 프로젝트 설정만 쓴다.
- **남은 항목.** 성능·메모리 통제 비교, Windows 패키지 실행, 다른 GPU와 미지원 장치 확인, BLAS 빌드 예산 실측과 강제 실패 화면 확인, 마스크 생성·Dispatch 실패 시 섀도맵 복귀, 알파 테스트 재질의 레이트레이싱, 스킨드 메시의 스키닝·refit 비용 측정과 한도·재빌드 주기 조정, 카메라 거리 기준의 스킨드 메시 선택.

**부드러운 그림자 상태 (2026-11-23, 사용자 확인 전):** 광원 크기에 따라 경계가 흐려지는 그림자를 코드에 반영했다.

- **광원 크기.** `LightComponent`에 방향광 `SourceAngle`(겉보기 지름, 도, 0~10)과 점·스포트 `SourceRadius`(m, 0~5)를 더했다. 기본은 0(선명)이며 `ALLOW_MISSING`이라 기존 장면은 그대로 읽힌다. GPU 광원 구조의 빈 칸(`Pad1` → `SourceSize`)에 방향광은 반각의 탄젠트, 점·스포트는 반지름을 넣어 버퍼 크기(80바이트)는 같다. 변환과 반그림자 식은 `LightSourceSize.h`에 있고 셰이더가 같은 식을 쓴다.
- **추적.** 크기가 있는 광원은 픽셀·광원마다 광원 원판 안의 한 점으로 광선 하나를 쏜다. 표본은 픽셀별 해시에서 R2 수열로 프레임마다 옮긴다. 가장 가까운 차폐물까지의 거리로 받는 면의 반그림자 반지름(m)을 함께 기록한다. 크기가 0인 광원은 이전처럼 첫 교차에서 끝낸다.
- **누적과 필터.** 크기가 있는 채널만 반사와 같은 방식(지터 없는 행렬과 픽셀 UV로 이전 화면을 찾고 거리·법선이 다르면 버림)으로 누적한다. 카메라가 멈추면 최대 32프레임, 움직이면 12프레임까지 이어 쓰고, 이번 프레임 5x5의 평균±1.5σ로 이력을 잘라 움직인 물체의 그림자가 남지 않게 한다. 이어서 같은 면 안에서 채널마다 반그림자 반지름(최대 24픽셀)만큼 12탭으로 흐린다. 채널과 광원의 연결이 바뀌면 이력을 버린다. 모든 채널의 크기가 0이거나 번호로 읽는 리소스(Tier 2)를 쓸 수 없으면 누적·필터 없이 한 표본 결과를 쓴다.
- **섀도맵 정합.** 섀도맵도 같은 광원 크기로 반그림자 폭을 정한다. 방향광 PCSS의 고정 상수(`lightSizeUV` 0.0175)를 없애고 캐스케이드 행렬에서 월드 1m당 깊이·UV를 구해 차폐 거리를 미터로 바꾼다. 스포트(고정 2.5텍셀 PCF)와 점광원(고정 반경 PCF)도 차폐물 탐색과 깊이 선형화로 PCSS를 쓴다. 필터 반지름은 1.5~16텍셀이며, 크기 0이면 1.5텍셀이라 기존 장면의 섀도맵 그림자는 이전보다 선명해진다(사용자 결정).
- **남은 항목.** 화면 확인, GPU 시간·메모리(누적 타깃 RGBA16F 6장+RGBA8 1장 추가), 누적·필터 값 조정, 큰 광원에서 16텍셀 상한에 걸리는 섀도맵 반그림자, 점광원 PCSS의 면 경계 근사.

**반사 상태 (2026-11-23):** 매끈한 면의 거울 반사와 거친 면의 반사, 시간 누적과 공간 필터를 코드에 반영했다.

- **추적.** 조명 패스 안에서 전체 해상도 Compute RayQuery로 픽셀마다 광선 하나를 쏜다. 거칠기 0.1 미만은 거울 방향, 그 이상은 GGX 분포에서 뽑은 방향이며 0.45부터 줄여 0.6에서 추적하지 않는다(측정 전 시작값). 닿은 면이 없으면 기존 환경광 반사를 쓴다.
- **누적과 필터.** 거칠기 0.1 이상만 누적하며, 카메라가 멈추면 최대 64프레임, 움직이면 약 25프레임까지 이어 쓴다. 밝기를 0~1로 눌러 평균을 낸다. 매끈할수록 닿은 물체의 가상 위치로, 거칠수록 면의 위치로 이전 화면을 찾고(TAA 지터만큼 어긋난 거리는 뺀다), 거리·법선이 다르면 버린다. 카메라가 움직이면 주변 픽셀의 범위로 자르고, 멈추면 조금씩만 당긴다. 이어서 같은 면 안에서만 8탭으로 섞으며 결과를 누적에 되먹이지 않는다. 물체별 모션 벡터가 없어 움직이는 면은 누적하지 못한다. 씬·크기가 바뀌거나 카메라가 한 프레임에 20m 넘게 움직이면 이력을 버린다.
- **닿은 면.** 번호로 읽는 정점·인덱스 버퍼와 텍스처로 재질을 구하고, 확산·정반사 직접광(광원 버퍼 앞 64개, `lightingPS`와 같은 GGX), 대표 방향광의 그림자 광선 하나, 환경광, 발광을 더한다. 2026-11-23부터 재질에 법선 맵이 있으면 정점 접선으로 `gbufferPS`와 같은 접선 공간을 만들어 적용하고(뒷면은 적용한 뒤 뒤집음), 환경광 정반사는 조도에 `EnvBRDFApprox`를 곱한다(미리 거른 환경 맵은 쓰지 않음). 미검증.
- **대상.** 활성·보이는 정적 메시와 스킨드 메시(위 그림자 항목의 한도 안)의 불투명·Masked 재질이다. 스킨드 메시는 스키닝한 정점·법선·접선과 일시 효과를 합친 재질 상수를 쓴다. Masked는 광선마다 알파를 확인한다. 동적·스플라인 메시, 지형, 반투명은 반사에 나타나지 않는다. 그림자용 캐스터와 광선 마스크로 구분해 그림자 결과는 바뀌지 않는다.
- **사용 여부.** 기본 꺼짐이며 프로젝트 → 그래픽 → 뷰포트 순서로 덮어쓴다. Client는 프로젝트 설정만 쓴다. Resource Binding Tier 2와 인라인 RayQuery가 필요하다.
- **스트리밍.** 화면 밖 물체는 스트리밍이 올려 둔 LOD와 밉으로 반사된다.

- 정적 삼각형 메시 BLAS와 인스턴스 TLAS를 생성하고 Transform·추가·삭제 변경을 반영한다.
- 첫 단계는 불투명 정적 메시의 단일 광원 그림자다.
  단순 차폐 조회에는 RayQuery를 검토하되, 전체 DXR 파이프라인과의 선택 이유를 기록한다.
- 다음 단계로 반사에 필요한 메시 속성·재질·텍스처 조회를 연결한다.
  기존 픽셀 셰이더를 이름만 바꾸어 재사용할 수 있다고 가정하지 않는다.
- Masked, 스키닝, 지형 변위, 투명 재질의 지원 정책을 따로 정의한다.
  초기 미지원 형상은 누락 사실을 표시하고 기존 그림자·반사 경로의 대체 정책을 명시한다.
- 정적 메시에 충분한 샘플을 사용하는 기준 영상을 먼저 만들고,
  이후 실시간 샘플 수를 위한 누적·디노이징과 카메라 컷 시 이력 초기화를 추가한다.

**완료 기준:** 화면 밖 물체의 차폐·반사가 확인되고, 인스턴스 이동·삭제·씬 교체 후 잔여 기하가 없다.
추적뿐 아니라 BLAS/TLAS 갱신, 누적·디노이징과 메모리까지 포함해 측정한다.
참고: [DirectX Raytracing 명세](https://microsoft.github.io/DirectX-Specs/d3d/Raytracing.html).

### M4. 프로브 기반 동적 GI

**선행 조건:** S5의 간접광 합성 기준과 M3의 광선 조회 기반. DDGI는 우선 검토할 구현 방식이다.

**상태 (2026-11-23, 3단계 코드 반영, 빌드·화면 확인 전):** 사용자와 다섯 단계로 합의했다. 1단계(볼륨·격자 계산·설정)와 2단계(프로브 갱신)는 main에 병합됐고, 사용자가 2단계 아틀라스가 채워지는 것을 확인했다. 3단계는 조명 패스가 볼륨 안의 확산 환경광을 프로브 조도로 바꾼다.

- **배치.** `ProbeGIVolumeComponent`가 엔티티의 월드 위치를 중심으로 `Size` 크기의 월드 축 정렬 상자에 프로브를 둔다. 회전·배율은 쓰지 않는다. 모서리에도 프로브가 있어 간격은 `Size / (개수 - 1)`이다. 축마다 2~32개(y는 16개), 기본 16×8×16 = 2,048개다. 한 뷰에서 계층 활성인 첫 볼륨 하나만 쓴다.
- **계산.** `ProbeGrid.h`에 번호·좌표, 셀 위치와 3선형 가중치, 상자 경계 혼합, 옥타헤드럴 인코딩, 아틀라스 배치(조도 8×8, 거리 16×16, 테두리 1텍셀)와 테두리 복사, 돌아가며 갱신하는 순서, 구면 피보나치 방향, 메모리 계산값을 두었다. `ProbeGridCheck`가 검사한다.
- **사용 여부.** 기본 꺼짐이며 프로젝트 → 그래픽 → 뷰포트 순서로 덮어쓴다(씬 뷰 렌더 패스 메뉴). Client는 프로젝트 설정만 쓴다. 반사와 같은 조건(인라인 RayQuery, Resource Binding Tier 2)과 활성 볼륨이 있어야 켜진다. 독립 프리뷰는 제외한다.
- **갱신(2단계).** 조명 패스 안에서 반사 다음에 Compute 세 번을 실행한다.
  - 추적(`probeGITraceRTCS`): 이번 프레임 차례의 프로브마다 구면 피보나치 방향을 프레임마다 무작위로 돌려 광선을 쏜다. 닿은 면은 반사와 같은 `LoadHitSurface`(`raytracingSurface.hlsli`, 반사 셰이더도 이 코드로 옮겼다)로 재질과 법선 맵을 읽고, 확산 직접광과 기존 환경광·발광을 더한다. 광원 버퍼 앞 16개 중 그림자를 드리우는 광원마다 그림자 광선을 쏜다. 뒷면에 닿으면 밝기 0과 음수 거리(-0.2 × 거리)를 쓴다. 닿지 않으면 환경 맵(밉 2)이나 하늘 반구 밝기를 쓴다. 해는 닿은 면의 직접광으로만 들어간다.
  - 섞기(`probeGIBlendIrradianceRTCS`, `probeGIBlendDistanceRTCS`): 프로브 칸 하나를 스레드 그룹 하나가 맡는다. 조도는 코사인 가중 평균(뒷면 광선 제외), 거리는 `pow(cos, 50)` 가중의 거리·거리 제곱 평균이며 대각선 간격의 1.5배로 자른다. 이전 값을 이력 비율(기본 0.97)로 남기고, 같은 그룹 안에서 테두리 텍셀을 채운다.
  - 일정(`ProbeUpdateSchedule`): 프레임마다 `ProbesPerFrame`개씩 돈다. 씬·격자 위치·간격·개수·갱신 수가 바뀌거나 아틀라스를 다시 만들면 아틀라스를 0으로 비우고, 처음 한 바퀴는 이전 값과 섞지 않는다. 기록에 실패한 프레임은 다음 프레임에 같은 프로브를 다시 갱신한다.
  - 확인 방법: 아틀라스는 렌더 타깃 목록에 `<위치 타깃>_ProbeGIIrradiance`, `_ProbeGIDistance`, 광선 결과는 `_ProbeGIRayData`로 보인다. 패스 시간은 같은 이름의 `_ProbeGI*Pass` 구간이다.
- **예산(계산값, 측정 아님).** 기본 격자에서 조도 1.6MB, 거리 5.3MB(이전 값을 UAV로 읽어야 해 `RGBA16F`), 광선 결과(프레임당 512개 × 128광선) 0.5MB로 뷰마다 약 7.1MB다. 프레임당 약 6.5만 광선과 닿은 면의 그림자 광선이다. 기본값에서 전체 프로브를 한 번 도는 데 4프레임, 이력 비율 0.97에서 대부분 수렴하는 데 약 100바퀴(400프레임)가 걸린다. 렌더러(뷰)마다 프로브를 따로 가지므로 씬 뷰와 게임 뷰를 함께 열면 비용이 두 배다.
- **2단계의 한계.** 닿은 면의 환경광은 반사와 같은 기존 환경광이라 실내에서도 하늘빛이 들어간다(4단계에서 이전 프레임 프로브 조도로 바꾼다). 볼륨을 옮기면 아틀라스를 처음부터 다시 채운다. 재질에 양면 정보가 없어 한쪽 면만 있는 판의 뒷면에 닿은 광선은 벽 속으로 기록된다. "GI만 보기" 화면은 같은 샘플링 코드가 필요해 3단계로 옮겼다.
- **조명 적용(3단계).** `lightingPS`가 `probeGISample.hlsli`로 둘러싼 8개 프로브의 조도를 읽는다(DDGI 방식).
  - 가중치: 3선형 × 법선이 프로브를 향하는 정도(`((cos + 1) / 2)² + 0.2`) × 체비쇼프 가시성(세제곱, 최소 0.05). 0.2보다 작은 가중치는 더 누른다. 한 번도 갱신하지 않은 프로브는 쓰지 않는다.
  - 표본 위치는 법선 방향으로 가장 좁은 간격의 0.1배, 카메라 쪽으로 0.3배 띄운다(측정 전 시작값).
  - 합성: 볼륨 안에서는 확산 환경광(`diffuseIBL`)을 `kd × 알베도 × 프로브 조도 × Intensity`로 바꾼다. 상자 밖 `BlendDistance`까지는 기존 환경광과 섞는다. 확산 IBL은 더하지 않고 `ShadowAmbientFloor`도 볼륨 안에서는 쓰지 않는다. 재질·화면 AO는 계속 곱한다. 정반사 IBL과 레이트레이싱 반사는 그대로다.
  - 이번 프레임에 갱신을 기록하지 못하면 그 프레임은 기존 환경광을 쓴다.
  - "GI만 보기": 씬 뷰 렌더 패스 메뉴의 프로브 GI 항목에서 켠다. 간접 확산광(볼륨 밖은 기존 환경광)에 AO를 곱한 값만 안개 없이 출력한다. 저장하지 않는다.
- **정반사 환경광 감쇠(3단계 보완, 2026-11-24, 빌드·화면 확인 전).** 볼륨 안에서 `specularIBL`에 `max(saturate(Y(프로브 조도 × Intensity) / Y(기존 하늘 확산 환경광)), 0.1)`을 `giWeight`로 섞어 곱한다(Y는 휘도). 상수 버퍼 변경이 없다. 하한 0.1과 식은 측정 전 시작값이다. 법선 반구의 평균 밝기비라 반사 방향별 가시성은 아니다. 1을 넘지 않아 밝히지 않으며, 하늘 밝기가 거의 0이면 적용하지 않는다. 프로브 GI 꺼짐·갱신 실패 프레임은 기존과 같다. RT 반사로 대체된 비율(`reflection.a`)은 이 값과 무관하게 추적 결과를 쓴다. AO는 이미 정반사를 포함한 환경광 전체에 곱해지므로 정반사 전용 오클루전은 넣지 않았다.
- **3단계의 한계.** 정반사 환경광은 조도비로만 줄이므로 열린 창 쪽을 보는 면의 하늘 반사는 과소 보정될 수 있고, 닫힌 실내의 거울면은 하한 0.1의 하늘빛이 남는다(방향별 정반사 가시성이나 프로브 반사 캡처는 후속 후보). 벽 속 프로브는 아직 그대로 써서 벽 가까이 어두운 얼룩이나 빛샘이 남을 수 있다(4단계). 바이어스는 측정 전 값이다.
- **다음 단계.**
  4. 빛샘과 안정성: 체비쇼프 가시성, 법선·시선 바이어스, 벽 속 프로브 이동·비활성, 다중 반사, 급격한 조명 변화에서 이력 비율 낮추기.
  5. 누출·지연·GPU 시간·메모리 기록.
- **공용 코드.** 닿은 면의 재질·법선 복원(`LoadHitSurface`), 광원 입사(`EvaluateLightIncidence`), 스카이 광원(`EvaluateSkyLight`)은 `raytracingSurface.hlsli`에 두고 반사와 프로브가 함께 쓴다. 반사는 이 정리로 결과가 바뀌지 않아야 한다.

- 제한된 실내 공간에 프로브를 배치하고 irradiance와 가시성 정보를 갱신한다.
- 프레임당 갱신량을 제한하고, 프로브의 벽 내부 배치·빛샘·보간·시간적 수렴을 처리한다.
- IBL·직접광·GI의 기여를 분리해 중복 조명을 방지한다.
- 먼저 확산 간접광을 지원한다. 거울 반사나 모든 재질의 간접 반사를 해결했다고 주장하지 않는다.

**완료 기준:** 직접광이 닿지 않는 면의 색 번짐과 조명 이동 반응을 확인한다.
벽 두께·프로브 간격·급격한 광원 변화에 따른 누출과 지연, 갱신 예산을 기록한다.
참고: [RTX Global Illumination / DDGI](https://developer.nvidia.com/blog/rtx-global-illumination-part-i/).

### M5. Mesh Shader와 Meshlet 처리 실험

**선행 조건:** 일반 메시의 GPU Driven 기준 경로와 재현 가능한 고밀도 메시 씬.

- 정적 메시를 Meshlet으로 전처리하고 저장·로딩 경로에 연결한다.
- Mesh Shader부터 비교한 뒤 필요할 때 Amplification Shader와 묶음 단위 컬링을 추가한다.
- 경계·노멀 콘 컬링의 전제를 확인한다. 양면 재질·음수 스케일·변형 메시를 별도로 처리한다.
- 기존 Vertex Shader 경로를 유지하고 GPU·장면별 손익을 기록한다.

**완료 기준:** 같은 모델에서 형상·재질·그림자가 일치하고, 전처리·메모리·GPU 비용을 함께 비교한다.
Mesh Shader 지원 자체를 Nanite 구현으로 표현하지 않는다.
참고: [Mesh Shader 명세](https://microsoft.github.io/DirectX-Specs/d3d/MeshShader.html).

## 6. 장기 목표: 요구가 확인된 기술부터 연구

### L1. 가상화 지오메트리

- **도입 이유:** 고밀도 정적 메시를 기존 LOD와 스트리밍만으로 다루기 어려울 때 검토한다.
- **범위:** 클러스터 계층·오차 기준·페이지 스트리밍·상주 예산·GPU 선택과 래스터 경로를 연결한다.
  먼저 제한된 정적 불투명 모델만 대상으로 한다.
- **비용과 제약:** 에셋 변환·파일 형식·런타임 메모리·그림자·피킹·RT 기하 표현까지 영향이 크다.
  소프트웨어 래스터라이징은 별도 손익 검토 대상이며 필수 출발점으로 두지 않는다.
- **완료 기준:** 카메라 이동과 페이지 미상주 상태에서 구멍이 없고, 원본 대비 오차·메모리·I/O 비용을 기록한다.

Nanite는 참고할 시스템이다. 첫 목표는 제한된 가상화 지오메트리 실험이며 동등한 기능을 약속하지 않는다.
참고: [Nanite 기술 발표](https://advances.realtimerendering.com/s2021/Karis_Nanite_SIGGRAPH_Advances_2021_final.pdf).

### L2. Virtual Shadow Maps

- **도입 이유:** 기존 CSM·아틀라스의 해상도 분배나 다수 그림자 광원의 비용이 실제 한계가 될 때 검토한다.
- **범위:** 가상 페이지·물리 페이지 풀·요청 수집·페이지별 캐스터 컬링·캐시 무효화를 구현한다.
- **비용과 제약:** 움직이는 광원·스키닝·지형·정점 변위가 많은 경우 캐시 재생성 비용이 커질 수 있다.
  가상화 지오메트리 전체를 필수 조건으로 만들지는 않는다.
- **완료 기준:** 페이지 예산 초과에서도 정의된 대체 동작을 유지하고, 정적/동적 씬에서 품질·메모리·시간을 비교한다.

참고: [Epic Virtual Shadow Maps](https://dev.epicgames.com/documentation/unreal-engine/virtual-shadow-maps-in-unreal-engine).

### L3. ReSTIR 기반 다수 광원·간접광 샘플링

- **도입 이유:** Clustered Lighting과 기존 RT 샘플링만으로 많은 광원을 처리하기 어려울 때 검토한다.
- **범위:** ReSTIR DI부터 시작해 후보 샘플, reservoir, 공간·시간 재사용과 가시성 검사를 구현한다.
  이후 필요할 때 GI·경로 재사용으로 확장한다.
- **비용과 제약:** 움직임·가림 해제에서 잘못된 샘플 재사용과 잔상, 분산·편향의 조건을 검토해야 한다.
  MegaLights는 참고 시스템이며 ReSTIR와 동일한 알고리즘이라고 가정하지 않는다.
- **완료 기준:** 충분한 샘플의 기준 영상과 비교하고, 급격한 광원·카메라 변화에서 오차와 총 실행 비용을 기록한다.

참고: [NVIDIA RTXDI](https://github.com/NVIDIA-RTX/RTXDI).

### L4. 패스 트레이싱 기준 렌더러

- **도입 이유:** 실시간 조명 결과를 비교할 기준 영상과 빛 전달 학습 도구가 필요할 때 추가한다.
- **범위:** 먼저 정적 씬의 누적 렌더링, 다중 반사, 직접광 중요도 샘플링과 MIS를 구현한다.
  충분히 수렴한 영상을 저장하고, 카메라·기하·재질·광원 변경 시 누적을 초기화한다.
- **비용과 제약:** 초기 목표는 실시간 게임 경로 전체의 교체가 아니다.
  실시간 전환은 샘플링·디노이징·지원 하드웨어 예산이 확보된 뒤 별도로 판단한다.
- **완료 기준:** 단순 분석 장면에서 조명·재질을 검증하고, 샘플 수에 따른 수렴과 기준 영상의 오차를 기록한다.

### L5. 추가 연구 후보

- **Work Graphs:** GPU 내부 작업 생성·분류가 기존 Dispatch·간접 실행으로 병목이 될 때 검토한다.
  기존 경로를 대체할 필요, 장치·SDK 지원과 메모리 비용을 먼저 확인한다.
- **Virtual Texturing:** 실제 텍스처 상주 메모리와 로딩이 한계일 때 검토한다.
  페이지 요청·미상주 대체 mip·비동기 업로드를 작은 예제로 검증한다.
- **Visibility Buffer:** G-buffer 대역폭 또는 다수 재질 처리 비용이 주요 병목일 때 검토한다.
  재질 복원·미분·Masked 처리 복잡성을 포함해 기존 Deferred와 비교한다.
- **Neural Rendering·3D Gaussian Splatting:** 학습·실사 캡처 콘텐츠라는 별도 요구가 생길 때 독립 실험으로 다룬다.
  일반 메시·재질·동적 조명의 기본 경로를 대체하는 필수 목표로 두지 않는다.

## 7. 공통 검증과 완료 기록

### 비교 장면과 측정 조건

- 작은 기본 씬: 신규 경로의 고정 비용과 기존 기능 회귀 확인.
- 반복 메시 씬: 예를 들어 1천·1만 개로 늘리며 인스턴싱·GPU 제출 비용 확인.
- 다양한 재질 씬: 바인딩 비용, 디스크립터 예산과 Bindless 비교.
- 가림이 많은 실내/거의 없는 야외: CPU 컬링과 GPU·Hi-Z 컬링 손익 비교.
- 다수 광원 씬: 광원 수와 겹침 정도를 나누어 목록 길이·오버플로·조명 비용 확인.
- 고밀도 모델·이동 물체 씬: LOD·Meshlet·스트리밍·가속 구조 갱신 확인.
- 단순 조명 기준 씬: 금속·거칠기 구체, 얇은 벽과 색상 벽으로 반사·GI 오차 확인.

위 물체 수는 검증용 예시이며 달성 성능이나 지원 한도를 뜻하지 않는다.
같은 GPU·드라이버·빌드 구성·내부 해상도·카메라·광원·품질로 비교한다.
성능 비교 시 VSync·프레임 제한 상태를 기록하고, 워밍업 뒤 여러 구간의 중앙값과 상위 지연을 남긴다.
평균 FPS 외에 CPU 제출·패스별 GPU ms·메모리·업로드량과 화질 차이를 함께 남긴다.

### 실행 흐름과 경계 조건

- 사용자가 Visual Studio에서 대상 구성을 빌드하고 F5로 실행하는 경로를 기본 검증 흐름으로 삼는다.
- Scene View·다중 뷰포트·머티리얼 미리보기·PIE 반복 시작/종료·Client에서 기능 범위와 회귀를 확인한다.
- 씬 교체, 창·뷰포트 리사이즈, 카메라 컷, 에셋 삭제와 셰이더 핫 리로드 실패를 확인한다.
- 2D Sprite·UI 정렬과 투명 재질, 지형·스키닝처럼 지원 경계가 다른 경로를 별도로 기록한다.
- 지원하지 않는 GPU, 빈 장면, 최대 목록 초과와 자원 할당 실패에서 정의된 동작을 확인한다.
- GPU 디버그 계층·검증 도구를 활용하되, 검증 모드의 성능을 일반 실행 수치와 섞지 않는다.

### 설정·도구·완료 판정

- 품질·디버그 옵션은 실제 구현된 기능만 노출한다. 미지원 옵션에는 이유와 대체 동작을 표시한다.
- 설정 UI는 `ImGuiDevelopmentPlan.md`의 GraphicsSettingPanel 방향과 연결한다.
  UI 구현과 엔진 실행 로직을 분리하고, 필요한 사용자 설정만 기존 저장 체계에 연결한다.
- 고정 표시 문구는 기존 로캘 키를 먼저 확인하고 Engine.csv·Editor.csv의 영어·한국어 번역을 함께 등록한다.
  시각화 토글·단축키·카메라 조작은 InputManager 경로를 따른다.
- 기능별 기록에는 변경 파일, 지원 백엔드·형상·재질, 정상/실패 동작, 검증 환경과 미검증 항목을 남긴다.
- 상태는 계획·구현 중·정적 확인·실행 검증 완료를 구분한다.
  코드나 API 선언의 존재, 문서의 체크 표시, 한 번의 FPS 관찰을 완료 근거로 삼지 않는다.

이 문서 작성에 대한 직접 수정 허가는 렌더러 구현이나 빌드·테스트 실행 허가로 확대하지 않는다.
후속 작업은 루트 AGENTS.md와 해당 요청에서 허용된 범위를 따른다.
