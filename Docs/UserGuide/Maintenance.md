# 사용자 문서 관리 규칙

[목차](README.md)

## 문서의 책임

- `Docs/UserGuide/`: 사용자가 실제로 기능을 사용하는 순서와 설정, 예시, 제한.
- `Docs/Technical/`: 내부 구조, 데이터 계약, 아키텍처.
- 기존 `*Plan.md`: 예정 기능과 구현 로드맵. 예정 내용을 사용법에 완료 기능으로 기록하지 않는다.
- `Sources.md`: 최초 조사에 사용한 고정 커밋 링크. 각 문서는 변경 시 자신이 검토한 커밋과 관련 소스를 갱신한다.

## 코드 변경 시 갱신 순서

1. 변경된 UI, API, 포맷, 기본값, 지원 범위를 확인한다.
2. 영향받는 사용 문서를 수정한다. 동일 절차를 여러 파일에 복사하지 않고 링크를 사용한다.
3. 실제 사용 절차, 기대 결과, 실패 시 조치, 한계 및 검증 수준을 기록한다.
4. C++ 예제는 선언과 사용 조건을 확인하고 컴파일 여부를 명시한다.
5. 문서 상단에 검토 커밋과 날짜를 갱신한다. 검증하지 않은 문서의 기준을 일괄 최신으로 바꾸지 않는다.
6. 관련 CTest 및 Editor/Client 확인 결과를 기록한다. 번역 문서가 있다면 함께 갱신하거나 차이를 명시한다.
7. README 목차, 상대 링크, 코드 펜스 및 파일명을 점검한다.

## 권장 문서 형식

```markdown
# 기능 이름
[목차](README.md)
> 검토 커밋 / 날짜 / 검증 수준

## 기능 개요 및 선행 조건
## 사용 절차
## 예시와 기대 결과
## 제약 및 문제 해결
## 관련 소스 및 문서
```

## AI 코딩 에이전트 작업 규칙 (적용 제안)

기능 구현 또는 사용자 동작을 변경하는 경우 관련 사용자 가이드를 같은 변경 단위에서 갱신한다. 계획서와 헤더 존재만으로 지원 완료라고 기록하지 않는다. 실제 테스트를 하지 않았다면 그대로 기록한다. 엔진 API 이름, 메뉴명, 파일 확장자와 예제 값은 소스에서 확인한다.

이 규칙을 저장소 `AGENTS.md`에 반영할지는 별도로 검토한다. 기존 개발 지침을 자동 변경하지 않는다.
