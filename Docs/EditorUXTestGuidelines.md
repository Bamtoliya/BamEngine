# 에디터 사용성(UX) 테스트 및 검증 기준

- 작성일: 2026-11-14
- 적용 범위: `Editor/` 전체 패널, 리소스 편집기, 모달·팝업, 공용 UI 위젯(`EditorUI`), 뷰포트 및 단축키/입력/다국어 경로
- 관련 구현 지침: [EngineEditorClientGuidelines.md](EngineEditorClientGuidelines.md) (10·14·16~19절), [ImGuiDevelopmentPlan.md](ImGuiDevelopmentPlan.md), [EditorWorkflowAndInteractionPlan.md](EditorWorkflowAndInteractionPlan.md)

## 1. 문서의 목적과 검증 원칙

`EngineEditorClientGuidelines.md`가 에디터 UI/UX의 **설계·구현 규칙**을 정의한다면, 이 문서는 해당 규칙이 실제 사용 흐름에서 깨지지 않았는지 판정하는 **테스트 계층, 테스트 환경 조건, Pass/Fail 기준 및 회귀 점검 절차**를 정의한다.

1. **구현 확인과 UX 검증의 구분**: 코드·스타일 스택·로캘 키 연결을 읽는 **정적 확인**만으로 UI/UX 검증 완료를 선언하지 않는다.
2. **자동 검사와 수동 확인의 분리**: 레이아웃 사각형 계산, 단축키 문맥 격리, 문서 보호 상태 머신처럼 GPU 없이 판정할 수 있는 불변 조건은 **헤드리스 CTest**로 고정하고, 실환경 수동 검증은 렌더링·OS 창 이벤트·복합 워크플로에 집중한다.
3. **경계 조건 우선 검증**: 기본 창 크기(`1920x1080`, `1.0x`, 단일 언어)만 확인하고 통과로 간주하지 않는다. 언어 전환, UI 배율 확대, 좁은 도킹 폭, 저장 실패·취소 경로를 기본 테스트 조건에 포함한다.

## 2. 검증 3계층 (Verification Tiers)

| 계층 | 검증 방식 | 주요 검증 대상 | 관련 타깃 / 도구 |
| :--- | :--- | :--- | :--- |
| **Tier 1. 정적·데이터 무결성 감사** | 빌드 파이프라인 / 스크립트 검사 | - `Editor.<Group>.csv` / `Engine.csv` 누락 키, 빈 번역, 중복 키<br>- 에디터 CSV의 열 개수, 명시적 Group, 파일명과 Group 일치, 중복 Group 접두사<br>- `ImGui::*` / `AddNotification` / `AddText` 내 하드코딩 UI 문자열<br>- `ImGui::IsKey*`, `IsMouse*`, `GetMousePos*`, `io.Key*`/`Mouse*` 등 원시 입력 직접 조회<br>- 리터럴 액션 ID 미등록 여부 및 `IImGui` 파생 패널의 `m_DisplayNameKey`/`GetDisplayName` 누락 여부 | `GenerateLocalization`, `AuditLocalization` (`Tools/Audit/LocalizationAuditor/audit_localization.py --strict`), `LocalizationAuditUtility` (CTest) |
| **Tier 2. 헤드리스 UI·상호작용 자동 검사** | 창·GPU 없이 `ImGui::CreateContext()`와 합성 입력(`io.AddMouse*`, `AddKeyEvent`, `InputManager`)으로 실행 (CTest) | - 배율별(`0.75x`~`2.0x`) 및 한·영 전환 후 메뉴바 첫 클릭·드래그 영역 분리<br>- 단축키 문맥 우선순위, 비활성 로컬 명령의 `Global` 폴백 차단, 텍스트 입력/키 캡처 억제, 동적 `GetShortcutHint()`<br>- 무입력 `Draw` 불변성, 언어 전환 후 카테고리 상태 유지, 드래그 앤 드롭 타입 안전성, 읽기 전용 차단<br>- 계층 트리 클릭·드래그 부모 변경·교차 씬 드롭 차단, `StateId` 기반 Undo 기준점·미저장 보호 | `MainMenuBarLayoutCheck`, `ShortcutManagerCheck`, `ReflectionInspectorCheck`, `HierarchyEditorCheck`, `EditorHistoryCheck`, `CanvasViewCheck`, `GraphMessageLocalizationCheck` |
| **Tier 3. 실환경 대화형·GPU·OS 통합 검증** | 실제 `Editor` 실행 후 시각·조작·OS 연동 수동 검증 | - SDL3 네이티브 창 드래그, 최소화/최대화/복원, 다중 모니터 DPI 이동, OS 파일 다이얼로그<br>- 3D 뷰포트/프리뷰어 렌더링(`ViewportDeferredPipeline`, G-Buffer 채널 뷰, `EditorCameraController`, `ImGuizmo`)<br>- 오버레이 클릭 관통 방지, 비동기 썸네일 업로드 예산 및 대량 폴더 프레임 시간<br>- PIE(`F5`/`Shift+F5`) 시점 분리 및 재실행 시 `Workspace.json` / `EditorPreferences.json` / `EditorStyle.json` 복원 | 5절 실환경 회귀 점검 시트 |

> `GenerateLocalization`은 [에디터 로캘 폴더](../Editor/Resources/Data/Localization)의 그룹별 CSV와 [Engine.csv](../Engine/Resources/Data/Localization/Engine.csv)를 읽어 번역본 JSON(`English.json`, `Korean.json`)을 동기화한다.

#### 원본 이동과 분할 검증

에디터 원본만 변경했다면 저장소 루트에서 아래 명령으로 에디터 JSON을 재생성하고 전체 로캘을 감사할 수 있다.

```powershell
python Tools/Codegen/CSVToJsonConverter/localizationcsvtojson.py --input Editor/Resources/Data/Localization --strict
python Tools/Audit/LocalizationAuditor/audit_localization.py --strict
```

- 변환과 엄격 감사의 종료 코드가 모두 `0`이고, 누락 키·빈 번역·중복 키·에디터 CSV 형식 오류가 없어야 한다.
- 파일 분리 전후의 두 JSON을 파싱해 최종 키 집합과 번역 값을 비교한다. 키의 출력 순서는 달라질 수 있다.
  번역 수정이 포함되면 값이 바뀐 키가 의도한 항목과 일치해야 한다.
- 감사기를 바꿨다면 `LocalizationAuditUtility`도 실행한다. 키나 표시 문구의 실제 사용을 확인하려면 대상 화면에서 영어·한국어 전환을 점검한다.

## 3. 표준 테스트 환경 매트릭스 (Standard Test Matrix)

모든 신규 패널, 공용 위젯 수정 및 레이아웃 개편은 아래 **표준 경계 조건 조합**을 기준으로 검증한다.

1. **언어 전환 (`Korean` ↔ `English`)**:
   - 단어 길이가 긴 영문(`English`)과 조사·복합어가 결합되는 국문(`Korean`)을 모두 확인한다.
   - 에디터 실행 도중 상단 메뉴 또는 설정에서 언어를 최소 2회 왕복 전환하여 캐시·ID·입력 상태 누수를 확인한다.
2. **UI 배율 및 글꼴/여백 (`Scale & Font`)**:
   - `1.0x` (100%, 기준), `1.5x` (150%, 고해상도 표준), `2.0x` (200%, 고배율 경계).
   - 글꼴 크기와 `FramePadding`을 변경한 상태 및 `EditorStyle.json` 저장 후 재실행 시 Unscaled Base Style SSOT가 유지되는지(배율 중복 곱셈 없음) 확인한다.
3. **패널 도킹 폭 경계 (`Docking Width`)**:
   - **표준 폭 (`400px ~ 800px`)**: 일반 도킹 상태에서 정렬, 열 비율, 툴바 구성을 확인한다.
   - **좁은 도킹 폭 (`240px ~ 300px`)**: 인스펙터, 계층 패널, 리소스 편집기 사이드바의 최소 실사용 폭에서 툴바 줄바꿈, 아이콘 축약, 오버플로 툴팁, 스플리터 클램핑을 확인한다.
   - **극한 축소 폭 (`< 180px`)**: 아이콘 하나보다 좁아진 극한 폭에서도 크래시, 음수 크기 Assert, 가로 무한 팽창이 발생하지 않는지 확인한다(일부 표시 생략은 허용 한계로 기록).

## 4. 6대 핵심 UX 영역별 Pass/Fail 기준

### 4.1 레이아웃 적응성 및 시각적 무결성 (지침 17·18절)

| 항목 ID | 테스트 조건 및 조작 | 통과(Pass) 기준 | 실패(Fail) 징후 |
| :--- | :--- | :--- | :--- |
| **UX-1.1 버튼·배지 글리프 수용** | 배율 `1.0x`/`1.5x`/`2.0x` 및 한·영 전환 상태에서 `IconButton`, `SmallIconButton`, 타입 배지, 읽기 전용 자물쇠 배지 확인 | 현재 글꼴 측정값(`CalcTextSize`) + 스타일 패딩이 배경 사각형 안에 완전히 포함되고, 시각적 사각형과 클릭 히트 영역이 일치함 | 글리프/텍스트가 캡슐·버튼 밖으로 삐져나오거나(`18x18` 등 고정 크기 잔류), 클릭 판정 위치가 어긋남 |
| **UX-1.2 반응형 툴바 줄바꿈** | `ToolbarLayout` 적용 편집기(12종+)와 뷰포트 상단 바의 패널 폭을 `800px` → `260px`로 축소 | 가용 폭 부족 시 우측 버튼이 잘리지 않고 다음 줄로 개행되거나 아이콘+툴팁으로 전환됨. 줄바꿈 시 하단 캔버스/프리뷰 시작 Y좌표가 늘어난 높이만큼 내려감 | 우측 버튼이 창 밖으로 잘려 클릭할 수 없거나, 툴바가 아래 프리뷰/캔버스 위를 덮음 |
| **UX-1.3 속성 테이블 및 오버플로 툴팁** | `BeginPropertyTable` 패널 폭을 `260px`로 줄이고 긴 라벨에 마우스 호버 | 라벨 열(`WidthFixed`)이 우측 예약 버튼(`↺`, 잠금 등)을 침범하지 않고, 실제 가용 폭 초과(`CalcTextSize().x > availWidth`) 시에만 호버 툴팁이 표시됨. 값 열은 `-FLT_MIN` 또는 예약 폭 차감으로 우측 끝까지 채움 | 라벨과 입력 위젯이 겹치거나, 고정 오프셋(`-65.0f` 등) 때문에 `2.0x` 배율에서 우측 버튼이 잘림 |
| **UX-1.4 스플리터 클램프 및 선호 폭 보존** | 스플리터가 있는 창(`ModelEditor`, `ModelImportModal`, `ConsolePanel`, `UnifiedSettingsPanel`)에서 ① 경계 끝까지 드래그, ② 창 축소 후 다시 확대 | ① 양쪽 영역이 모두 `minSize` 이상을 유지해 사라지지 않음.<br>② 창 축소 중 표시용 클램프가 저장용 선호 폭(`preferredWidth`/`Height`)을 덮어쓰지 않아 창을 다시 넓히면 원래 비율로 복원됨 | 한쪽 영역이 `0px`가 되어 복구할 수 없거나, 창을 잠깐 줄였다 키웠을 때 사이드바가 최소 크기로 고정됨 |

### 5.2 Tier 3 대화형 UI 점검 체크리스트

**리소스 문서 닫기와 편집 이력**

  - [ ] 누락한 레거시 머티리얼 참조와 같은 경로를 메모에도 기록한다. 자동 복구 뒤 참조 경로만 갱신되며 메모와 Null 참조는 보존된다. 대체 파일이 둘 이상 있거나 검사 뒤 참조가 바뀌면 이전 제안대로 기록하지 않는다.
  - [ ] 현재 씬과 편집기가 보관 중인 리소스 문서를 포함해 일괄 복구한다. 보관 중인 원본은 안내 후 건너뛴다. 대상 문서 하나의 기록 권한을 막으면 작성 묶음이 적용되지 않고 성공 건수를 표시하지 않는다. 정상 복구 후 `.bam/asset-reference-repair/`에서 수정 전후 백업을 확인한다.
  - [ ] 저장된 씬 → 머티리얼 → 텍스처 관계에서 씬의 의존성과 텍스처의 사용처를 두 단계 펼친다. 화살표 클릭은 현재 대상을 유지하며 행 클릭은 해당 파일을 새 조회 대상으로 바꾼다.
  - [ ] 가지를 접은 상태에서 간접 사용처와 의존성을 각각 검색한다. 한글·공백 파일명과 대소문자가 다른 URI, 슬래시와 역슬래시를 사용한 절대 경로로 찾는다. 순환 및 공유 관계에서도 방향별 결과가 중복되지 않고 다른 폴더의 동명 파일은 구분된다.
  - [ ] 검색 결과에서 대상을 클릭하거나 우클릭해 열기·위치 찾기를 실행한다. 이전·다음 조회 및 재검사 후 검색어는 유지되고 결과는 현재 조회 대상을 기준으로 갱신된다. 일치 항목이 없으면 안내를 표시하고 X 또는 Escape로 지우면 기존 트리와 펼침 상태로 복귀한다.
  - [ ] 씬 → 머티리얼 → 텍스처를 차례로 조회하고 툴바 버튼과 마우스 X1/X2로 순서를 되짚는다. 기록 끝의 버튼이 비활성화되고, 다른 패널이나 열린 팝업 위에서 X1/X2를 눌러도 참조 조회 대상은 바뀌지 않는다.
  - [ ] 뒤로 간 뒤 다른 대상을 조회하면 앞으로 기록이 비워진다. 같은 파일을 다시 조회하거나 수동 검사해도 방문 기록이 중복되지 않는다. 문제가 있는 경로도 방문할 수 있으며 누락 안내가 표시된다.
  - [ ] 현재 조회 대상이 아닌 이전·다음 기록의 파일 또는 상위 폴더를 이동·이름 변경한다. 뒤로·앞으로 이동 시 새 경로를 표시하고, 파일 작업 Undo/Redo 후 양쪽 기록이 현재 파일 위치를 따라간다.
  - [ ] 조회 대상 경로와 사용처·의존성의 중첩 행을 각각 우클릭한다. **콘텐츠 브라우저에서 찾기**를 선택하면 닫힌 브라우저가 열리고 해당 파일이 보인다. 검색·필터가 적용된 상태에서도 한글·공백 이름, 서로 다른 폴더의 동명 파일, Engine 매핑 에셋을 올바르게 찾는다.
  - [ ] **열기**로 씬·프리팹·머티리얼을 각각 연다. 미저장 씬의 교체 확인을 취소하면 기존 씬이 유지되고, 편집 중인 리소스의 교체는 기존 보호 경로를 사용한다. 내부 편집기가 없는 파일은 OS 기본 프로그램으로 열리며, 파일이 사라진 상태에서 메뉴 명령을 실행하면 알림이 표시된다.
  - [ ] 상호 참조하는 문서는 순환 참조 표시에서 펼치기가 끝난다. 같은 에셋을 공유하는 두 가지에는 각각 표시된다. 서로 다른 폴더의 동명 파일은 독립적으로 펼쳐지고, 한국어와 영어 전환 시 펼침 상태가 유지된다.
  - [ ] 조회 대상과 사용처를 각각 이동하거나 이름을 바꾸고 콘텐츠 브라우저에서 Undo/Redo를 실행한다. 검사 버튼을 누르지 않아도 조회 대상과 트리의 경로가 현재 위치를 가리킨다. 이동 취소나 실패 후에는 경로와 결과가 유지된다.
  - [ ] 조회 중인 에셋과 상위 폴더를 각각 삭제한다. 원래 조회 경로와 대상 누락 안내가 표시되며, 문제 탭에서 남아 있는 문서의 누락 참조를 확인할 수 있다. Undo로 같은 대상의 관계가 돌아오고 Redo로 다시 누락 안내가 표시된다.
  - [ ] 다른 에셋을 참조하는 씬을 복사한다. 참조 대상의 사용처에 새 복사본이 나타나고 Undo/Redo로 사라졌다 다시 나타난다. 여러 항목 중 일부 복사가 실패하면 성공한 복사본만 반영한다.
  - [ ] 삭제 확인을 취소하거나 복원할 경로를 막아 Undo를 실패시킨다. 파일 이력 커서와 패널 결과가 작업 전 상태를 유지한다.
  - [ ] 콘텐츠 브라우저를 닫은 상태에서 씬의 머티리얼 또는 머티리얼의 텍스처 참조를 바꿔 저장한다. 짧은 대기 후 참조와 문제 목록이 자동 갱신된다. 씬 편집을 저장하기 전에는 디스크에 저장된 기존 관계가 표시된다.
  - [ ] 외부 편집기의 직접 저장과 임시 파일을 사용한 원본 교체, 대문자 확장자 참조 문서를 각각 확인한다. 기존 문서 저장은 엔진 통계에 변경 문서 검사로 표시되고 한 파일만 저장하면 폴더 0개·문서 1개로 잡힌다. 프로젝트나 Engine·Editor 리소스에 대상 파일을 추가·삭제하면 자동 전체 검사로 바뀐다. 감시 범위 밖 파일은 수동 검사로 갱신한다.
  - [ ] 문서 하나의 참조를 누락 경로로 바꾸어 저장한다. 기존 링크는 사라지고 해당 문서의 문제만 추가된다. 원래 경로를 다시 저장해 복원한 뒤 수동 전체 검사로 링크와 문제 건수가 일치하는지 확인한다.
  - [ ] 씬 두 개가 같은 머티리얼을 참조하는 상태에서 머티리얼의 마지막 텍스처 참조를 제거하고 다시 추가한다. 자동 갱신마다 두 씬의 의존성에서 머티리얼의 펼치기와 텍스처의 역참조가 함께 바뀌는지 확인한다. 관계 검색을 유지한 상태에서도 제거·복원이 반영되고, 참조가 그대로인 저장에서는 검색 결과가 유지되어야 한다.
  - [ ] 여러 문서에 누락 참조가 있는 상태에서 유형과 검색어를 동시에 적용한다. 표시 중인 앞쪽 문제와 필터로 가려진 문제를 각각 해결하고, 다른 문서에 새 문제를 추가해 저장한다. 남은 행의 원본·대상·개별 복구 동작, 표시/전체 건수와 복구 가능 건수를 수동 전체 검사와 비교한다.
  - [ ] 패널을 닫거나 비활성 도킹 탭으로 가린 채 이동·이름 변경·삭제·복사·저장을 연속 실행한다. 패널을 다시 표시하면 마지막 변경 이후 최종 파일 상태를 기준으로 한 번만 스캔한다. 유휴 프레임에는 스캔이 반복되지 않는다.

- **G. 계층 패널의 묶음 드래그 이동과 순서 변경**
  - [ ] 박스·Ctrl·Shift로 여러 엔티티를 선택하고 선택된 행을 다른 부모로 드래그한다. 드래그 미리보기에 선택 개수가 나오며, 루트들을 원래 월드 위치에서 새 부모 아래로 옮긴다. 부모와 자식을 함께 선택한 경우 하위 관계가 유지된다.
  - [ ] 선택되지 않은 행에서 시작하면 해당 엔티티 하나가 선택되고 그 항목만 이동한다. 씬 루트 드롭으로 묶음을 분리하고, Ctrl+Z/Ctrl+Y 각 한 번으로 계층과 형제 순서가 함께 복원되는지 확인한다.
  - [ ] 선택에 포함된 엔티티를 자손 아래로 옮기거나 잠긴 엔티티와 함께 옮겨 거부되는지 확인한다. 대상의 스케일 때문에 월드 변환을 유지할 수 없는 경우에도 다른 엔티티의 부모·순서·이력이 유지된다.
  - [ ] 같은 부모 아래에서 1번과 3번 행을 선택한다. 2번 행 위쪽 또는 아래쪽 삽입선에 드롭하면 1번과 3번의 상대 순서와 각자의 자식·Transform이 유지된다. Ctrl+Z/Ctrl+Y 한 번씩으로 순서가 바뀌는지 확인한다.
  - [ ] 다른 부모의 항목을 섞어 선택한 뒤 드래그를 시작한 행과 같은 부모의 형제 행 가장자리에 드롭하면 트리와 이력이 그대로다. 순서가 같은 위치에 뒀을 때도 새 이력이 생기지 않는다. 펼쳐진 형제 뒤에는 다음 형제 위쪽에서 삽입하거나 행을 접은 뒤 삽입한다. 행 가운데 드롭과 씬 루트 드롭은 기존처럼 부모를 바꾼다.
  - [ ] 다른 씬으로 넘어간 드래그와 드래그 도중 사라진 엔티티는 묶음 전체를 거부한다. 인스펙터의 엔티티 참조 필드는 드래그를 시작한 엔티티를 사용한다.

- **H. 프리뷰 오버레이와 모델 임포트 푸터**
  - [ ] 모델·VFX 프리뷰에서 렌더 타깃 목록을 열어 중간 타깃과 최종 출력을 바꾼다. 조명 팝업은 현재 저장값으로 열리고 변경은 현재 프리뷰에 표시된다. 취소·바깥 클릭·툴바가 가려질 정도의 축소 뒤에는 저장값으로 돌아오며, 적용하면 다른 프리뷰에도 반영된다.
  - [ ] 한글·공백이 있는 긴 파일명의 대형 모델 임포트에서 푸터의 단계 표시와 취소 버튼을 확인한다. 좁은 폭에서 파일명이 잘려도 공간이 허용되는 동안 취소 버튼은 클릭할 수 있다. 취소 후 출력과 이후 작업을 [모델 임포트 1차 검증](OutOfProcessAssetPipelinePlan.md#모델-임포트-1차-검증)에 따라 확인한다.

## 6. Tier 2 헤드리스 자동 검사 확장 후보 (`EditorUICheck`)

현재 `Editor/examples/`의 검사는 메뉴바·단축키·인스펙터·계층·문서 이력을 다루며, 공용 위젯 집합(`EditorUI`) 자체의 불변 조건을 검증하는 전용 타깃은 아직 없다. 향후 `Editor/examples/EditorUICheck.cpp`를 신설할 때는 다음 4가지 계약을 CTest로 고정한다.

1. **`DialogButtonBar` 계약**: 우측 정렬 및 좁은 폭 세로 줄바꿈 시 `GetDialogButtonBarHeight()`와 실제 렌더링 높이 일치 여부, `CancelIndex = -1` 시 `Escape` 무반응, 비활성 확인 버튼 및 `InputText` 활성 중 `Enter` 무시.
2. **`DrawSearchBar` 계약**: `FocusOnDraw = true` 첫 프레임 입력 포커스 획득, 활성 상태에서 `Escape` 입력 시 `Cleared == true` 반환 및 버퍼 초기화, 빈 버퍼 시 `[X]` 비활성 상태 유지.
3. **`IconButton` / `SmallIconButton` 배율 계약**: 배율 `1.0x`/`1.5x`/`2.0x`에서 `GetItemRectSize()`가 글리프 측정 크기 + 최소 패딩 이상을 항상 만족하는지 검사.
4. **`ToolbarLayout` 폭 경계 계약**: 좁은 창 폭(`220px`)에서도 모든 자식 위젯의 `GetItemRectMax().x`가 창 오른쪽 경계(`WindowPos.x + WindowWidth`)를 초과하지 않고 다음 줄로 개행되는지 검사.
